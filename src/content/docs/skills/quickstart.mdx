完成[安装与配置](/skills/getting-started/)后，在要处理的业务仓库根目录启动 Claude Code 或 Codex。下面的提示词输入到客户端；终端命令只在标注的目录执行。

## 1. 先认识当前项目

向 Agent 提出一个范围明确的请求：

```text
先定位当前项目的启动入口、用户模块和已有检查命令。
引用真实文件路径，本次先不修改业务代码。
```

Agent 会结合项目记忆和源码定位入口，适用时使用 `project-navigator`；未知仓库需要建立概览时使用 `start`。项目记忆缺失时可能初始化唯一 `PROJECT-MEMORY.md`，它保存稳定事实，不保存对话副本。

核对返回的文件是否存在、命令是否来自项目配置。若 Agent 找错仓库，明确给出目标目录后再继续。

## 2. 选择你当前要做的事

不必背诵完整 Skill 名称。描述目标、现象和约束即可；需要指定能力时，也可以显式调用。

| 当前任务 | 可直接使用的提示词 | 主要入口 |
| --- | --- | --- |
| 已有任务续作 | 读取我的唯一 TODO，继续当前已批准的功能 | `next` 与适用实现 Skill |
| 新功能 | 添加订单管理，包含列表、详情和状态更新；先核对现有实现与需求 | 新需求规划，再进入专业实现 |
| 故障修复 | 登录后立即返回 401，请沿请求链定位并修复 | `bug-detective` |
| 页面整理 | 调整已有订单列表的布局和错误状态 | `frontend-polish` |
| 性能问题 | 订单列表加载需要 8 秒，请先定位耗时 | `performance-doctor` |
| 审查改动 | 审查当前 diff 的缺陷和验收证据 | `code-review` |
| 执行检查 | 运行项目已有检查，不新增测试代码 | 复用已有命令 |
| 编写测试 | 为订单状态转换补单元测试代码 | `test-development` |

例如，显式定位项目入口：

```text
Claude Code：/project-navigator 找到订单列表的页面与 API 入口
Codex：$project-navigator 找到订单列表的页面与 API 入口
```

自然语言选择由客户端提供的 Skill 清单、任务语义和仓库事实共同决定。上表是职责指引，不是固定调用序列；“加快开发进度”也不等于要诊断程序性能。

## 3. 接续另一段会话

新加入的两个 Skill 按**历史来源**选择，与当前使用哪个客户端无关。

```text
读取 Claude Code 的会话 <session-id>，继续其中未完成的问题。
目标仓库是 <项目路径>。
```

```text
读取 Codex 中关于订单分页的那段会话，先总结进度，不修改代码。
```

前者使用 `resume-claude`，后者使用 `resume-codex`。支持会话 ID、记录路径、描述或 `latest`；省略引用或使用 `latest` 时，只查当前目录的最近会话。描述匹配多项时会列出候选供选择。

读取历史不会恢复旧进程、工具连接或运行中命令。继续前仍会核对当前分支、改动与 TODO；只要求总结时，停在摘要。详见[历史会话接续](/skills/usage/session-resume/)。

## 4. 核对结果与下一步

一个可核对的答复应说明：处理了什么、依据哪些文件、执行了哪些验证、还有什么未完成。只有构建通过时，不应声称真实业务流程已经验收。

任务记录与稳定项目事实分开保存：

| 内容 | 位置 |
| --- | --- |
| 当前开发者的功能、依赖和状态 | `docs/<developer-id>/tasks/todo/<原文件名>.md` |
| 项目技术栈、复用入口和边界 | 唯一 `PROJECT-MEMORY.md`；已有 `docs/PROJECT-MEMORY.md` 时沿用 |

新功能先完成必要规划；已批准 TODO、明确 Bug 和普通维护按现有边界执行。只有本轮明确要求写测试时才新增或修改测试源码，运行已有检查不需要转成测试开发任务。

需要 Git 交付时明确说明提交范围、目标分支和是否推送。已有授权在原范围内继续有效；Runtime Hook 本身不执行 commit 或 push。持续开发的完整顺序见 [Git 工作流](/skills/usage/git-workflow/)。

每次真实代码、Skill、配置或文档变更都要在同一提交更新仓库根 `CHANGELOG.md`；分支合并时按 fast-forward 或 merge commit 的实际结果记录，具体格式见[变更日志](/skills/usage/changelog/)。
