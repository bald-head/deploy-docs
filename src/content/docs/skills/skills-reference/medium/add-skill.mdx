## 用途

`add-skill` 将已有 Skill 接入目标客户端，并核对索引、Runtime Hook、远端 Penpot MCP 和原生发现。创建内容使用 [`skill-creator`](/skills/skills-reference/medium/skill-creator/)，修改已有规则使用 [`skill-optimizer`](/skills/skills-reference/medium/skill-optimizer/)。

## 什么时候用

| 请求 | 处理范围 |
| --- | --- |
| 把已有 Skill 注册到 Codex | 接入指定客户端并核对其发现入口 |
| 同步刚拉取的新 Skill | 核对目录、索引和目标客户端可读性 |
| Skill 文件存在但客户端找不到 | 定位真实来源、发现路径和元数据问题 |

已有完整 Skill 目录，并且需要注册或同步时即可使用；不要求必须发生清单变化。普通正文或 reference 修改不触发注册检查。

## 操作示例

```text
把这个已有 Skill 目录接入 Codex，复用当前共享源，
确认本轮客户端可以发现，并说明尚未验证的调用方式。
```

下面的命令在 **Skill 源仓库根目录** 执行，按目标客户端选择一条：

```bash
AGENT_WORKFLOW_CLIENT=codex node add-skill/scripts/validate-skill-catalog.mjs --install-discovery --require-discovery=codex
```

```bash
AGENT_WORKFLOW_CLIENT=claude-code node add-skill/scripts/validate-skill-catalog.mjs --install-discovery --require-discovery=claude-code
```

frontmatter、description 或清单变化需要更新 `SKILLS.md` 时，按本次注册范围在同一次 validator 调用中添加 `--write`。只有本次需要纳入未跟踪的新 Skill 时才加 `--include-untracked`，不默认扫描所有临时目录。

## 注册器会做什么

1. 检查并按需安装 Runtime Hook、注册当前 CLI 的远端 Penpot MCP，然后复检。
2. 核对目录名、`name`、`description`、索引以及所需引用。
3. 按指定客户端建立或验证发现入口；替换已有发现目录前先备份。
4. 返回真实错误和已验证范围，不把文件落盘当成客户端调用成功。

无 `--write` 只表示不重写索引；validator 仍可能执行安装与修复，不是只读命令。成功要核对退出码 `0`、`errors: []`、`runtimeHooks.installed: true` 和 `penpotMcp.configured: true`，数量以实际输出为准。

Penpot 地址只能来自既有客户端配置、`PENPOT_MCP_URL` 或本机真实配置来源，缺失时报告注册缺口。Codex 若提示新 Hook 尚未信任，按 `/hooks` 提示处理。本文档维护本身不运行这些安装操作。

## 发现与调用

| 客户端 | 调用方式 |
| --- | --- |
| Claude Code | `/skill-name` 或自然语言 |
| Codex | `$skill-name` 或自然语言；`/skills` 用于浏览 |

共享目录只维护一个真实源，客户端可通过其支持的软链接或配置发现。候选目录必须结合当前客户端配置确认，不能把路径存在当作已发现；只验证本次指定且实际可用的客户端。

每个 Skill 的必需脚本、规则和资源应随自身目录分发，不能依赖兄弟 Skill 的相对路径。更多步骤见[安装与配置](/skills/getting-started/)和 [Frontmatter 规范](/skills/advanced/frontmatter-spec/)。
