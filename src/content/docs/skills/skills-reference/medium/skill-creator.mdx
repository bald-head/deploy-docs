## 用途

`skill-creator` 创建新 Skill 内容，或实施已经确认的目录结构与公共能力改动。已有 Skill 的普通修正使用 [`skill-optimizer`](/skills/skills-reference/medium/skill-optimizer/)，安装和同步使用 [`add-skill`](/skills/skills-reference/medium/add-skill/)。

明确的创建或修改请求已经授权内容编辑，不需要再次确认同一动作。提交、推送、发布或客户端接入按其对应的有效授权处理。

## 使用示例

```text
为这项重复操作创建 Skill。先检查本地是否已有能承接的能力，
明确触发场景、输入、输出和边界；有合适 Owner 时直接扩展它。
```

```text
按已确认方案整理这个 Skill：核心步骤留在 SKILL.md，
专项说明放到按需读取的 references，确定性操作使用随包脚本。
```

先判断新建、扩展还是复用。只有本地没有可承接职责、存在独立触发场景，并且有明确运行时消费者时才新增 Skill；外部仓库提供结构与规则参考，不按其目录名逐个复制平行能力。

## 内容组织

| 位置 | 内容 |
| --- | --- |
| `SKILL.md` frontmatter | 准确的 `name` 和能独立说明用途与边界的 `description` |
| `SKILL.md` 正文 | 高频核心流程、完成条件、失败与授权边界 |
| `references/` | 长示例、专项知识和平台差异，从正文直接链接 |
| `scripts/` | 确定性的重复操作，由正文说明调用时机 |
| `assets/`、`agents/` | 实际需要且有消费者的模板、资源或客户端元数据 |

每个 Skill 是可独立分发的单元。安装后必读的规则、脚本与资源随自身目录分发；跨 Skill 按能力名称协作，不依赖兄弟目录的相对路径。

## 实施步骤

1. 明确意图、目标目录、触发语义和非目标。
2. 检查相邻 Skill 的真实职责，确定新建、扩展或复用。
3. 只创建运行时需要的最少文件，同步必要引用。
4. 核对 frontmatter、直接引用、脚本语法或仓库现有检查，并做一次 Review。
5. 需要注册或清单同步时交给 `add-skill`，不把内容写完当作客户端已验证可用。

流程精简不能删除专业能力。规划类 Skill 仍覆盖产品、适用设计、架构与技术结论；实施类 Skill 仍消费唯一 TODO 当前项，并覆盖真实纵向交付、验证和一次 Review。

产出说明创建或修改的路径、用途、检查与未覆盖边界，不生成平行任务状态、无消费者的 Schema 或固定完成报告。字段格式见 [Frontmatter 规范](/skills/advanced/frontmatter-spec/)。
