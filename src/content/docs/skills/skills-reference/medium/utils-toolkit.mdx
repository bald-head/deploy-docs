## 用途

`utils-toolkit` 从目标仓库、标准库和已有依赖中查找可复用的工具类或 API，并核对真实调用方式。它不负责通用软件推荐，也不默认开发新的公共工具。

## 使用示例

```text
订单模块需要把 Entity 转成返回 DTO。
请先查项目记忆、当前依赖和相邻调用，找到已有转换入口，
核对 import、方法签名、空值、敏感字段与嵌套对象映射行为。
```

```text
这个日期格式化应该复用哪个现有 API？
请结合当前调用位置核对时区、locale、格式和异常语义。
```

请求要包含具体调用场景。“有什么工具”“怎么调用”只有指向仓库中的实际代码能力时才适用；泛泛询问常用软件不因此选择本 Skill。

## 查找与采用

1. 从 `PROJECT-MEMORY.md` 的复用地图、当前模块和直接调用链找已有 Owner。
2. 核对构建与锁文件，确认依赖和版本真实存在。
3. 读取定义、导入、签名和生产调用方，不凭工具名称推断契约。
4. 比较输入输出、空值、异常、上下文、精度、时间、线程安全与兼容语义。
5. 在当前允许范围采用已确认能力，运行适用的最小检查并交回结果。

默认只搜当前调用链和相邻实现，出现实际 import、调用或相同契约指向公共 Owner 时再扩大范围，不为每个功能扫描全仓。

## 常见核对点

| 候选能力 | 要核对什么 |
| --- | --- |
| 同名 `StringUtils` | 完整 import 与版本，以及空串、空白和 null 语义 |
| 对象转换器 | 实际生成或手写映射，字段忽略、嵌套对象与空值处理 |
| HTTP 封装 | 超时、状态码、错误、重试、幂等和认证上下文 |
| 时间与数字工具 | 时区、locale、单位、精度和边界输入 |
| 公共缓存或资源工具 | 生命周期、隔离、并发、清理和失败恢复 |

同名不等于同义，不能仅凭库名称声称深拷贝、线程安全或特定默认值。结论应引用真实定义与调用证据。

没有合适能力时，说明候选缺口与原因；新增工具或业务实现交给对口专业 Skill / [`dev`](/skills/skills-reference/high/dev/)，新增依赖由 [`tech-decision`](/skills/skills-reference/high/tech-decision/) 比较。不要为了“复用”再包一层同语义工具。

最终说明采用的准确 API、关键契约、改动或只读结论、验证与未覆盖边界，不创建 TODO 或另行维护状态。
