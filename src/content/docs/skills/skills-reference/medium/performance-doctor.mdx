## 用途

`performance-doctor` 按运行指标定位接口、SQL、页面加载、CPU 或内存瓶颈。它先建立可复现的基线，再做最小优化，并用同条件对照确认结果。

“能不能快点”只有指向程序响应或资源消耗时才属于性能诊断。催促 Agent 加快开发进度、减少重复验证，不触发本 Skill。

## 使用示例

```text
订单列表在约 10 万条数据时加载需要 8 秒。
请先定位请求、SQL 与页面渲染的耗时分布，核对现有索引和缓存，
建立可复现基线后再优化，并给出同条件下的对照结果。
```

提供具体接口、页面、查询或运行对象，以及已知环境、数据规模和目标。缺少基线时先测量或提出可验证假设，不能直接报告提升百分比。

## 诊断过程

1. 明确用户可感知指标、性能目标、环境与数据规模。
2. 分解客户端、网络、网关、应用、数据库、缓存和外部依赖耗时。
3. 用 trace、profiling、执行计划、日志或计数器验证主因。
4. 选择最小改动，说明影响、回滚和适用范围。
5. 在同数据、流量与环境下对比分位延迟、吞吐、错误率和资源指标。
6. 复用已有功能、权限、一致性和降级检查，完成适用真实主路径与一次 Review。

指标按实际问题选择，不为每个局部问题采集不相关的整套数据。没有前后对照时，只报告实际完成的诊断或静态检查，不声称性能已改善。

## 边界与协作

| 问题 | 入口 |
| --- | --- |
| 功能结果错误、请求失败 | [`bug-detective`](/skills/skills-reference/high/bug-detective/) |
| 页面布局、交互和视觉整理 | [`frontend-polish`](/skills/skills-reference/high/frontend-polish/) |
| 数据表设计与迁移 | [`database-design`](/skills/skills-reference/high/database-design/) 与 [`database-ops`](/skills/skills-reference/high/database-ops/) |
| 引入新缓存、中间件或依赖 | [`tech-decision`](/skills/skills-reference/high/tech-decision/) |
| 编写测试源码 | 本轮明确要求后使用 [`test-development`](/skills/skills-reference/medium/test-development/) |

不能关闭认证、租户隔离、数据权限、校验或 TLS 来换取指标改善。生产压测、索引和数据库全局配置调整按实际授权与环境边界执行。

## 交付结果

报告基线、根因证据、实际修改、对照结果、回退方式和未覆盖环境。性能结论只适用于已测量的数据与条件；本 Skill 不维护 TODO 状态或执行 Git，结果交给当前 Feature Owner 收口。
