## 用途

`archify` 把系统架构、技术流程、API 时序、数据流和生命周期转换为可探索的独立 HTML，内含 SVG、明暗主题与导出能力。输入可以是自然语言、已有架构事实，或粘贴的 Mermaid。

它负责图形表达，架构决策由 [`architecture-design`](/skills/skills-reference/high/architecture-design/) 完成。只需要 README 内的小型 Mermaid 图时使用 [`mermaid`](/skills/skills-reference/low/mermaid/)；统计图、海报和幻灯片使用对应专业能力。

## 选择图表类型

| 类型 | 适用内容 | 请求示例 |
| --- | --- | --- |
| `architecture` | 组件、基础设施、云与安全边界 | 根据当前仓库画服务部署与依赖图 |
| `workflow` | 技术步骤、审批门禁、CI/CD | 把发布流程画成可探索 HTML |
| `sequence` | API 调用、异步轨迹和返回 | 展示订单请求从入口到回调的时序 |
| `dataflow` | ETL/ELT、血缘、加工与消费者 | 画清数据来源、转换和落点 |
| `lifecycle` | 状态、重试、等待和终态 | 把订单状态转换画成生命周期图 |

## 使用示例

```text
根据当前仓库的订单调用链生成交互式时序图 HTML。
保留接口名、异步调用、失败与重试语义，节点和关系需要源码依据。
```

```text
把下面的 Mermaid stateDiagram 转成生命周期图 HTML，
保留状态和转换含义，使用中文说明，不需要动画。
```

Mermaid 的 `flowchart` / `graph` 通常映射到 `workflow`，组件地图使用 `architecture`；`sequenceDiagram` 映射到 `sequence`，`stateDiagram` 映射到 `lifecycle`。迁移的是拓扑和含义，不机械复制旧样式。

## 生成与验证

Agent 从实际发现的 `archify` Skill 目录读取一种匹配 Schema、公共 Schema 和一个结构示例，写出新的候选 JSON。示例不作为真实系统事实来源。

以下维护命令在 **archify Skill 根目录** 执行，文件名和类型替换成实际产物：

```bash
node bin/archify.mjs guide "订单支付回调的失败重试链路" --json
node bin/archify.mjs validate sequence candidate.json --quality showcase --json
node bin/archify.mjs deliver sequence candidate.json diagram.html --quality showcase --json
node bin/archify.mjs visual-check diagram.html --json
```

默认 `showcase` 要报告全部 9 项产物检查，composition error 和 warning 均为零。4 项基础检查不等于通过该档验收。最终 `deliver` 冻结规范字节、校验并原子写出 HTML，报告规范与产物各自的 SHA-256 和字节数；非零退出码不能宣称成功。

`visual-check` 检查多个桌面尺寸并生成截图证据，但 `visualReview` 仍为 `pending`，需要实际查看截图。不能通过删除有意义的标签、裁剪内容或缩小文字掩盖布局问题。

## 阅读与导出

HTML 支持平移缩放、搜索定位、聚焦、关系追踪和主题切换，可导出 PNG、JPEG、WebP、SVG、WebM。默认静态内容；只有明确要求演示或动画时启用轨迹动画。

交付包含 HTML 路径、图表类型、验证摘要和实际视觉检查状态。需要本地立即打开时再要求预览，普通生成不默认启动持续预览服务。
