## 概述

`progress` 是 **Medium 优先级** Skill，负责只读统计当前开发者唯一 TODO 的功能进度。

**适用场景**：
- 查看当前任务进度
- 统计功能完成情况
- 检查验收证据
- 了解任务状态

**不适用场景**：
- 产品定义 → 使用 `product-manager`
- 代码实现 → 使用 `dev` 或 `universal-development`
- TODO 创建 → 使用 `task-todo-workflow`
- 状态更新 → 使用 `update-status`

<Aside type="note">
这是只读操作，不会修改 TODO、代码或 Git。
</Aside>

## 快速开始

### 查看进度的方式

```bash
# 方式 1: 直接询问
"当前进度如何？"
"任务完成情况"
"查看进度"

# 方式 2: 使用 Skill
/progress

# 方式 3: 查看 TODO 文件
cat docs/<developer-id>/tasks/todo/*.md
```

## 关键规则

### 1. 只读操作

```markdown
<!-- 正确 -->
progress 只读取 TODO 和代码
→ 不修改任何文件

<!-- 错误 -->
progress 发现问题后自动修复 TODO
→ 不能修改 TODO
```

### 2. 功能完整性检查

```markdown
完整完成的标准:
- ✅ 数据库表已创建
- ✅ API 接口已实现
- ✅ 前端页面已实现
- ✅ 前后端联调通过
- ✅ 权限控制已实现
- ✅ 验收证据完整
- ✅ Review 已通过
- ✅ 代码已提交

不完整的情况:
- ❌ 只有静态页面（无 API 调用）
- ❌ 只有 mock 数据
- ❌ 只有孤立接口（无前端）
- ❌ 只有迁移文件（无代码）
```

### 3. 验收证据要求

```markdown
有效证据:
- ✅ 手工测试截图
- ✅ 自动测试通过
- ✅ 真实数据验证
- ✅ DevTools 验证

无效证据:
- ❌ unverified
- ❌ "已实现"（无证据）
- ❌ "测试通过"（无日志）
```

### 4. 并行写集互斥

```markdown
合法并行:
- Feature A: src/api/user/
- Feature B: src/api/order/
→ 写集互斥 ✓

非法并行:
- Feature A: src/api/user/
- Feature B: src/api/user/
→ 写集冲突 ✗
```

## 进度统计指标

### 基础指标

```markdown
- 总功能数: 所有 Feature checkbox 数量
- 已完成: [x] 的数量
- 进行中: [~] 的数量
- 未开始: [ ] 的数量
- 阻塞: [!] 的数量
- 完成率: 已完成 / 总功能数
```

### 质量指标

```markdown
- 验收完整率: 有证据的 AC / 全部 AC
- 依赖满足率: 满足依赖的 Feature / 全部 Feature
- 写集冲突数: 冲突的写集对数
- Epic 完成率: 完成的 Epic / 全部 Epic
```

### 健康检查

```markdown
- [ ] 无状态冲突（同一 Feature 只有一个实例）
- [ ] 无依赖冲突（所有 [~] 的依赖全部 [x]）
- [ ] 无写集冲突（所有活动写集两两互斥）
- [ ] 无验收缺失（所有 [x] 的 AC 有证据）
- [ ] 无 Epic 冲突（Epic 的 [x] 能由子 Feature 重算）
```

## Skill 协调

`progress` 与以下 Skill 配合：

| Skill | 关系 |
|-------|------|
| task-todo-workflow | 读取 TODO 结构 |
| update-status | 进度发现后更新状态 |
| code-review | 读取 Review 结果 |
| git-commit | 读取提交历史 |

<Aside type="note">
progress 只负责统计和报告，不负责创建、修改或更新任何内容。
</Aside>

## 与其他 Skill 的关系

### 选择决策

```text
查看进度 → progress
更新状态 → update-status
创建 TODO → task-todo-workflow
代码实现 → dev
```

## 最佳实践

### 1. 定期检查进度

```bash
# 每天检查
"查看今天的进度"

# 每周汇总
"本周完成了哪些功能？"

# 里程碑前
"距离 v1.0 还有多少功能？"
```

### 2. 关注验收证据

```bash
# 检查证据完整性
"哪些功能缺少验收证据？"

# 补充证据
"USER-EDIT 的 AC-002 需要验证"
```

### 3. 解决依赖阻塞

```bash
# 发现依赖问题
"哪些功能被依赖阻塞？"

# 调整优先级
"先完成 USER-PERMISSION，解除阻塞"
```

### 4. 避免并行冲突

```bash
# 检查冲突
"当前有并行写集冲突吗？"

# 调整并行策略
"等 USER-EDIT 完成后再开始 USER-DELETE"
```
