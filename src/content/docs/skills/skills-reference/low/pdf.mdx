## 概述

PDF 尴尬的地方在于它同时是交付格式和唯一数据源——合同、报表、体检单、证件扫描件都只有 PDF 这一份。所以处理它有两类风险：把原件弄坏，和把里面的东西弄漏。

`pdf` Skill 用一套固定的路径压住第一类风险：按任务类型选定工具（拆合并、抽文本表格、生成、命令行批处理各有各的），扫描件先转成图再识别，表单填写走"先探结构 → 再定坐标 → 填完渲染回看"三步。原件始终原地不动，所有写入都落到新的副本上。

第二类风险它管得更严。一份 PDF 里可能同时有证件号、金额、签名、内网地址；OCR 出来的图片、表单字段的中间 JSON、终端里滚过去的日志，都会把这些东西带出去。默认做法是能少读就少读、能少落盘就少落盘、日志和截图里不出现完整的敏感值，临时产物在交付时说清是留着还是清了。

这是这批 Skill 里对数据边界要求最高的一个，也是"看起来跑成功了其实没跑"最容易发生的一个——因为缺一个系统工具时脚本往往安静地失败。

## 什么时候用

| 你会这样说 | 场景 |
| --- | --- |
| "把这几个 PDF 合成一个" | 合并、拆分、旋转、改元数据 |
| "把这份 PDF 里的表格提出来" | 抽文本和表格，落成可处理的数据 |
| "这是扫描件，帮我认一下内容" | 先转图再 OCR |
| "生成一份 PDF 报告" | 从零创建，含中文字体与排版 |
| "帮我把这个表单填好" | 有字段的和纯图形的两种表单都能填 |
| "这个 PDF 有密码" | 加密文档，需要先确认授权 |
| "这份 200 页的能不能按章节拆开" | 批量拆分与命令行处理 |

## 什么时候不要用

- **Word 文档** → [docx](/skills/skills-reference/low/docx/)；**Excel 或 CSV** → [xlsx](/skills/skills-reference/low/xlsx/)；**演示文稿** → [pptx](/skills/skills-reference/low/pptx/)。
- **内容本身还没定稿** → 先用 [doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/) 或 [internal-comms](/skills/skills-reference/low/internal-comms/) 把话写对。先导出再改内容，等于每改一句话重做一遍排版。
- **要写代码、改代码** → [universal-development](/skills/skills-reference/low/universal-development/) 或对应专业 Skill。
- **文件要上传到对象存储、接文件服务** → [file-oss-management](/skills/skills-reference/medium/file-oss-management/)。这里只处理本地文件内容。
- **要把 PDF 当附件发出去** → [sms-mail](/skills/skills-reference/low/sms-mail/)。
- **要产品定义、验收标准** → [product-manager](/skills/skills-reference/critical/product-manager/)。

## 开始之前它会先确认的四件事

这四项都会影响结果，而且事后补救成本远高于事前问一句：

**工具链到底有没有。** qpdf、Poppler、Tesseract、ImageMagick 和 Python 侧的几个库不能假定装好了。缺哪个就降级，并且在交付里明说"这一项没做"——最怕的情况是缺 Poppler 导致转图失败，脚本照样退出码 0，你以为识别完了。

**输出往哪儿写。** 你指定了路径就用你的；没指定就先看仓库有没有文档目录的既有约定；两边都没有时，它会在第一次写文件前问你一个文档前缀，最终文件落到 `<doc-prefix>/pdf/`。这个前缀在当前任务里复用，不会被写成团队默认值。

**是不是加密的。** 加密 PDF 需要你确认有权解密。它不会自己反复试密码。

**有没有破坏性参数。** 覆盖同名文件、原地写入、批量删除这类操作，动手前先说清覆盖范围和怎么恢复。

<Aside type="danger">
填表单尤其要先确认。表单里通常就是身份信息和金额，位置填错、覆盖了原有文字，往往没有第二份原件可以对照。原件保持原位、写副本，是这套流程里最不该被"图省事"跳过的一条。
</Aside>

## 使用示例

### 场景 1：合并一批文件，再把里面的表格抽出来

**你的输入**：

```text
这个目录下 12 份月度报表，合成一份，再把每份里的"应收明细"表抽成 CSV。
```

**它会用到的东西**：

```text
合并、拆页、旋转、改元数据   pypdf
抽文本和表格                pdfplumber
纯命令行的批量拼接          qpdf
从零生成新文件              reportlab
```

**你会拿到的交付说明**：

```text
输入        12 个文件，共 148 页（每份 11-14 页）
输出        merged_2025h1.pdf（148 页）
            receivables/2025-01.csv … 2025-12.csv（12 个）
工具        pypdf 5.x / pdfplumber 0.11.x，均可用；未使用 qpdf
加密/OCR    无加密，未做 OCR（源文件是文字型 PDF，不需要）
原件        12 个源文件未被修改，输出全部写到新路径
中间文件    无（表格直接流式写出，未落中间 JSON）
敏感信息    CSV 里保留了客户名与金额，未在终端打印任何整行数据
验证        随机抽 3 个月份，把 CSV 行数与 PDF 页面上的小计行核对，一致
未验证      第 7 份第 9 页有一个跨页表格，被断成两段已手工接上；
            其余跨页表格未逐页人工核对
```

那份"未验证"是这个交付里最有价值的一行——它告诉你还剩什么风险，而不是给你一句"处理完成"。

### 场景 2：扫描件，而且环境里没装 OCR

**你的输入**：

```text
这份合同是扫描的，帮我把第 3 条的内容念给我。
```

**你会拿到的回应**：

```text
这份是图像型 PDF，抽不到文字层，需要先转图再识别。

当前环境探测结果：
  Poppler     可用
  Tesseract   未安装 —— 识别这一步跑不了

两个选择：
  1. 你装一下 Tesseract（含中文语言包），我继续跑
  2. 我只把第 3 条所在的那一页转成图片给你，你直接看

先说明一件事：识别出来的文字不能当作合同原文使用，
条款类内容我会同时给出对应页码和图片位置，让你能自己核。

如果继续，中间产物会放在任务临时目录，交付时告诉你是留还是清。
```

<Aside type="caution">
它宁可告诉你"这一步没跑"，也不会拿一个空结果假装识别过了。所以看到交付里出现"未运行 OCR""未做真实渲染确认"这类句子，那是它在正常工作，不是偷懒。
</Aside>

### 场景 3：填一份没有可填写字段的表单

**你的输入**：

```text
帮我把这份申请表填好，内容我发你了。
```

**它会先做的判断**：

```text
第一步永远是判断表单类型 —— 有可填写字段（Fillable）和纯图形两种，
处理路径完全不同，判断错了会白填一遍。

这份属于纯图形：整页是扫描图，没有任何表单域。
路径：提取版面结构 → 转图定位每个框 → 校验框坐标 → 填 → 再渲染回看
```

**你会拿到的交付说明**：

```text
输入        application.pdf（2 页，纯图形表单）
输出        application_filled.pdf（原件未动）
填写方式    坐标标注法（无表单域，无法走字段填写）
坐标来源    版面结构提取 + 页面渲染图比对
填写前校验  17 个框的边界做过静态检查，2 个偏出可写区域已调整
填写后确认  已把成品重新渲染成图片逐页看过：
            17 处全部落在框内，未压住原有文字与表格线
中间文件    坐标 JSON、渲染前后各 2 张图，位于任务临时目录，已清理
敏感信息    表单含身份证号与银行账号，未在日志或截图中出现完整值
未验证      第 2 页底部签名栏留空（按你要求手写），未做任何处理
```

<Aside type="caution">
填完必须重新渲染成图片看一眼。坐标偏移在 JSON 里完全看不出来——数字都在合理范围，但字可能就是压在了表格线上或跑到了下一格。填写前的边界校验是静态检查，替代不了这一步。
</Aside>

### 场景 4：它会停下来的请求

```text
你：这个 PDF 有密码，你破一下。

它：能不能处理取决于你有没有这份文件的权限，而不是技术上难不难。
    如果密码你有，直接给我，我用它打开并输出一份未加密副本；
    原件的加密状态不动。
    如果密码你没有，这件事我不做，也不会去逐个试。

    另外提醒：解密后的副本比原件危险得多 —— 它会落在磁盘上、
    可能被同步、可能进备份。要不要在处理完之后立刻删掉？
```

## 与其他 Skill 的关系

**上游**：内容先在 [doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/) 或 [internal-comms](/skills/skills-reference/low/internal-comms/) 定稿，源文件由 [docx](/skills/skills-reference/low/docx/) / [pptx](/skills/skills-reference/low/pptx/) 产出。

**同族**：[docx](/skills/skills-reference/low/docx/)、[pptx](/skills/skills-reference/low/pptx/)、[xlsx](/skills/skills-reference/low/xlsx/) 处理其他办公格式，取材和落盘的规矩一致。需要一份能继续编辑的版本时转 `docx`。

**下游**：产物要上传或接入文件服务转 [file-oss-management](/skills/skills-reference/medium/file-oss-management/)；要当附件发出去转 [sms-mail](/skills/skills-reference/low/sms-mail/)。

```text
doc-coauthoring / internal-comms（内容定稿）
        ↓
docx / pptx / xlsx（源文件）
        ↓
pdf  合并 · 拆分 · 抽表 · OCR · 生成 · 填表
        ↓                        ↓
file-oss-management（上传）   sms-mail（附件发送）
```

## 常见坑

**缺工具却当成跑成功了。** 这是这个 Skill 最常见的翻车方式。转图、识别、加密处理这几步依赖系统命令，缺了往往不报错只出空结果。判断有没有真跑，看交付里工具那一行有没有写可用性。

**在原件上直接改。** 一旦覆盖，就没有对照物了——填错位置、抽错页、旋转反了都无法回退。写副本这件事不是洁癖。

**表格抽出来行数对不上。** 跨页表格、合并单元格、无边框表格是三个高发区。抽完先核一次行数或小计，比之后在下游发现要便宜得多。

**填完不看图。** 坐标合法不等于位置正确。只有渲染出来才知道字是不是压住了原有文字。

**敏感值滚进了日志。** 调试时打印整行数据很自然，但那一行可能包含证件号和账号，而终端记录、CI 日志、截图都会留下来。

**中间文件没人管。** OCR 图片、坐标 JSON、渲染图往往就是最敏感的那几张。交付时说清留还是清了，别默认丢在临时目录里。

**先导出再改内容。** 内容还会变的时候导出 PDF，等于每改一句话重做一次排版。

## 最佳实践

- **动手前把四件事问清。** 工具链、输出路径、是否加密、有没有覆盖动作。这四项都是事后补救最贵的。
- **抽数据时先抽一页看看。** 用一页确认表格识别得对不对，再跑 200 页，能省掉一次全量重跑。
- **让交付说明替你记账。** 输入输出、工具可用性、原件与临时文件、敏感信息处理、验证方式、没验证的部分——按项写，别用"已完成"一句话代替。
- **"未验证边界"要写得具体。** "未做真实渲染确认"比"可能有小问题"有用一百倍。
- **中文生成要先解决字体。** 从零生成 PDF 时中文字体缺失会静默变成方块或空白，这一项值得在写内容之前先验一页。
