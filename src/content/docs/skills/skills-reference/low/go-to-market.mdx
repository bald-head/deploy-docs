## 概述

GTM 方案有两种常见死法。一种是客户画得太大——"中小企业都能用"，评审时没人反对，执行时没人说得清第一个客户从哪儿找。另一种是把上线那天的动作清单当成全部计划，上线三周后没人知道该看什么数、什么情况下该撤。

`go-to-market` 从开头就堵住这两条路。它先逼你收敛到一个滩头：一个具体细分，现有渠道找得到、有预算、痛得够急、你还交付得起。定位由这一个细分推导，再分头写给会用的人、掏钱的人、卡合规的人和拍板的人——四份说法可以长短不一，但不许互相打脸。发布被切成上线前、上线窗口、上线之后，每段都要有负责人、护栏和撤退线。增长部分要求画出一个真能自己转起来的机制，给漏斗换个名字不算。

它对数字很不客气：手里没有历史数据时，CAC、转化率、ROI、循环系数只能以"这是假设 + 打算怎么测"的形式进入方案。竞品为什么输、客户说了什么好话，同样要有出处。这条会让你的方案看起来不如同事那份漂亮，换来的是里面没有半年后会被打脸的东西。

不做的事也很清楚：不替你选商业模式、不写 PRD、不投广告、不承诺价格、不起草对内的发布邮件。

## 什么时候用

| 你会这样说 | 场景 |
| --- | --- |
| "帮我出一份 GTM 方案" | 直接触发，从滩头一路走到增长循环 |
| "这个版本怎么推出去" | 已有能卖的功能，缺渠道和发布节奏 |
| "我们的 ICP 到底是谁" | 客户收敛：谁算、谁不算、怎么把他们找出来 |
| "定位怎么写，和竞品差在哪" | 定位句、分角色消息、Battlecard |
| "该走 Inbound 还是 Outbound" | 渠道 Motion 的比较与取舍 |
| "增长循环怎么设计" | 画真循环，而不是给漏斗换个名字 |
| "上线要准备什么、上线后看什么" | 三段式发布节奏与指标护栏 |

## 什么时候不要用

- **还在纠结做不做、靠什么赚钱** → [product-strategy](/skills/skills-reference/high/product-strategy/)。要不要进这个市场是它的题；这里接的是"已经决定要卖，怎么卖出去"。
- **价值本身还是个猜测** → [product-discovery](/skills/skills-reference/high/product-discovery/)。没人验证过用户真的要，再精致的渠道计划也是在推一个空盒子。
- **要 PRD、OKR、路线图** → [product-execution](/skills/skills-reference/high/product-execution/)。它把上市动作接成排期，这里只负责动作本身长什么样。
- **要写对内的发布公告、周报、纪要** → [internal-comms](/skills/skills-reference/low/internal-comms/)。对内讲清楚和对外打得动，是两种文体。
- **要落地活动页、埋点、投放脚本** → [dev](/skills/skills-reference/high/dev/) 或对应专业 Skill。方案不产代码。
- **要算显著性、拉漏斗 SQL** → [product-analytics](/skills/skills-reference/medium/product-analytics/)。这里给指标定义和护栏，统计推断在那边做。

<Aside type="caution">
开场那几个问题不是客套：产品版本、已验证的价值、发布类型、目标地域、时间窗、预算、团队人手、手上的客户与渠道、价格区间、合规约束。少了预算和人手，它会推荐一个你交付不了的渠道；少了合规，它会写出你发不出去的动作。答不上来的项直接说"不知道"，比编一个更省事。
</Aside>

## 使用示例

### 场景 1：一句"这版怎么推"换一份能派活的计划

**你的输入**：

```text
设备巡检 SaaS，试点 3 家维保商跑了两个月，续约都签了。
下个月正式对外，帮我出 GTM 方案。团队 2 个销售 1 个市场，预算 8 万。
```

**你会拿到的产出**（节选，实际会更长）：

```text
## 滩头与客户
细分     长三角 200-800 人的第三方设备维保商
纳入     外派工程师 ≥ 30 人 / 已用企业微信 / 现在靠纸单 + Excel 汇总
排除     单一厂区自建团队 / 已上 SAP PM / 只做安装不做维保
购买触发 甲方续约时要求提供电子巡检记录
选它的理由 纸单方案每月约 2 天返工，且返工成本落在有预算的人头上
可触达性  行业协会名录 + 招投标公告可筛出约 340 家（已核对 20 家有效）

## 定位
对外派工程师 30 人以上的第三方维保商，在甲方开始要电子记录的时候，
这是一套巡检执单系统，让每次到场都留下能直接交给甲方的凭证。
相对纸单加 Excel，可证明的差异是：工单闭环时自动生成甲方可验收的记录。
（对照物选的是纸单，不是同类 SaaS——这是客户实际正在用的东西）

## 分角色说法（互不矛盾检查已过）
工程师   少填一次表，到场扫码即可，旧单不用补录
老板     每月省下的返工时间，折算 ≈ 1.5 个人日
IT/安全  数据存放位置、账号回收、导出权限
甲方对接人 记录格式与验收单一致

## Motion
主选   Outbound + Partner（协会名录 / 甲方推荐）
不选   Paid —— 名单只有 340 家，投放打不准，单客成本不可控
不选   PLG —— 签单人是老板，工程师不是决策者，自助试用带不动扩张

## 发布节奏
| 阶段 | 目标人群 | 动作 | 证据/假设 | 指标与护栏 | Owner 状态 |
| 上线前 3 周 | 5 家试点 | 收数据 + 销售话术演练 | 3 家已续约（事实） | 试点全留 | 张 · 进行中 |
| 上线窗口 | 名单前 80 家 | 名录外呼 + 甲方案例 | 回复率 8%（假设） | 投诉 ≥ 2 例即停 | 李 · 未开始 |
| 上线后 4 周 | 已激活账号 | 首月执单率跟踪 | — | 激活转周活 ≥ 40% | 张 · 未开始 |

## 标为假设的数字
回复率 8% / 激活转周活 40% / 单客获客成本
三项都没有历史数据，写法统一为「假设值 + 怎么测 + 首轮样本量」，不作为承诺。

## 未执行
未联系任何客户、未投放、未对外发布、未报价
```

计划里每一行都能指到人，每个数字都能指到来源或标着"假设"——这才是能拿去派活的状态。

### 场景 2：没有研究数据，它不会替你把 ICP 说成结论

**你的输入**：

```text
我们的 ICP 是什么？还没做过用户访谈，就手上几个熟客。
```

**你会拿到的产出**：

```text
## 这次只能给到"假设"这一层
已有证据   3 家熟客的成交记录与使用频次（样本太小，不构成分群依据）
缺什么     没有访谈、没有流失原因、没有拒买原因、没有竞品切换样本

## ICP 假设 A：第三方维保商
识别信号   工程师规模 / 是否外派 / 甲方是否要求电子记录
支持它的观察  3 家熟客里 2 家属于此类，且都在甲方要求后主动找来
反对它的观察  第 3 家是甲方自建团队，购买动因完全不同

## ICP 假设 B：甲方设备科
识别信号   自有设备资产量 / 是否有专职设备科 / 是否已上 EAM
待验证     它可能是更大的市场，但采购周期与合规门槛完全没摸过

## 怎么把假设变成结论（4 周）
第 1-2 周  两类各访 6 家，问最近一次到场怎么做记录（不问"你会不会买"）
第 3 周    从协会名录抽 40 家核对识别信号能不能从外部看出来
第 4 周    有一类的购买触发被 ≥ 6 家独立确认，才写进 ICP 定稿

## 明确没做的事
没有编造两类客户的规模、预算区间和转化率；
Persona 的年龄、职级、偏好一栏留空，不用想象补。
```

<Aside type="note">
这是它最有用也最容易被嫌弃的一种回应：你想要一份 ICP，它先告诉你现在只够写假设。想直接拿定稿，先补研究——那是 [product-discovery](/skills/skills-reference/high/product-discovery/) 的活。
</Aside>

### 场景 3：增长循环被打回

**你的输入**：

```text
增长循环我想好了：用户注册 → 用起来 → 觉得好 → 推荐给同行 → 新用户注册。
```

**你会拿到的回应**：

```text
## 这不是循环，是一条许愿链
断点  "觉得好 → 推荐给同行"之间没有任何机制。
      产品里现在没有邀请入口、没有可分享的产出物、没有推荐动力。
      少了这一环，下一轮输入不会自己产生，得靠销售继续外呼——
      也就是说增长成本不随规模下降。

## 两个可能真成立的机制
机制 1（可复用产出）  巡检记录导出时带上生成来源，甲方看到 →
                     甲方要求其他维保商也用 → 新输入来自甲方侧
                     每轮耗时：一个续约周期（长，但不花钱）
机制 2（协作拉入）    甲方对接人被邀请进来验收记录 → 他手上还有 4 家维保商
                     每轮耗时：单次工单闭环（短）

## 现在不能给的东西
循环系数：没有任何一轮的真实数据，给出的任何数字都是编的。
能给的是测量方式：一个甲方账号在 8 周内带来多少个新维保商账号。

## 顺带提醒
护栏要先写：导出记录里含甲方名称时的授权边界、邀请频次上限。
```

它拒绝给循环系数这件事，比给一个好看的数字有用——上线后你不用解释为什么实际差了 5 倍。

### 场景 4：它会直接拒的请求

```text
你：把这三家竞品的赢单原因写进 Battlecard，客户证言也帮我编两条。

它：竞品赢单原因需要来源——丢单复盘记录、客户原话或公开材料，
    三者都没有的话我只能列"待调研"，不能替你写。
    客户证言同理，编出来的话第一次被客户看到就是事故。
    可以先给你一份 Battlecard 骨架，把"何时不该跟这家竞"那一栏留出来，
    这一栏往往比对比表更能救销售。
```

## 与其他 Skill 的关系

**上游**：[product-discovery](/skills/skills-reference/high/product-discovery/) 先证明有人要，[product-strategy](/skills/skills-reference/high/product-strategy/) 先定清楚卖给哪个市场、靠什么赚钱。

**下游**：[product-execution](/skills/skills-reference/high/product-execution/) 把上市动作接成排期与责任，[internal-comms](/skills/skills-reference/low/internal-comms/) 把同一批信息翻译成对内版本。

**协作**：[product-analytics](/skills/skills-reference/medium/product-analytics/) 负责指标口径与数据分析，[doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/) 负责把方案写成对外能看的材料。

**改用它**：如果聊到一半发现真正卡住的是"这门生意怎么成立"，换 [product-strategy](/skills/skills-reference/high/product-strategy/)，别在渠道层继续绕。

```text
product-discovery（有人要吗）→ product-strategy（这生意怎么成立）
                                        ↓
       go-to-market  滩头 → 定位 → Motion → 发布三段 → 增长循环
                          ↓                        ↓
     product-execution（接成排期）        internal-comms（对内同步）
                          ↓
     product-analytics（口径与度量）  doc-coauthoring（对外材料）
```

## 常见坑

**把行业当客户。** "制造业""中小企业"这类写法过不了它的检查，因为无法据此列出一份名单。可行的检验很朴素：照着你写的 ICP，今天下午能不能筛出 50 个具体公司名。筛不出来就还不是 ICP。

**定位的对照物选错。** 很多人拿同类 SaaS 当参照，但客户此刻用的往往是 Excel、纸单或者一个实习生。对照物选错，"可证明的差异"就会落在客户根本不关心的地方。

**四份说法各说各话。** 给老板讲省人力、给工程师讲功能更多，两句话放到同一次采购会上就互相拆台。它会做一致性检查，这一步值得你自己也过一遍。

**推荐了交付不了的渠道。** Community 和 Partner 在方案里最好看，但需要长期投入和专人。预算与人手没说清时，你很容易拿到一份漂亮的、跑不动的计划。

**没写停止条件。** 渠道最贵的不是启动成本，是没人敢喊停。每个渠道都该有一条"到这个数就撤"。

**名字先用后查。** 产品名、活动名都只是候选，商标、域名、多语义、可读性都没查过之前，别印到物料上。

**用假倒计时和假稀缺撑转化。** 短期数字会好看，代价是复购和口碑，它不会给你这类方案。

## 最佳实践

- **先把边界题答完。** 预算、人手、合规、时间窗——这四项决定了哪些渠道从一开始就不该出现在选项里。
- **一次只推一个滩头。** 想同时打两类客户时，把第二类明确写成"扩张路径"，而不是并列的主战场。
- **上线后那一段先写完再上线。** 上线前的清单人人都会写，上线后看什么、谁看、多久看一次，才是决定这次发布有没有学到东西的部分。
- **让每个数字自带标签。** 有来源的写来源，没来源的写"假设 + 怎么测"。评审时你会感谢这个习惯。
- **把"何时不该竞争"写进 Battlecard。** 销售最需要的一句话往往是"这单别追了"。
