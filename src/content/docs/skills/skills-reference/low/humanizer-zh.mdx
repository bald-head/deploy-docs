"这段读起来太像 AI 了"是个真实但很难执行的反馈——不知道具体哪里像，就只能整体重写一遍，然后写出另一段同样像 AI 的文字。`humanizer-zh` 把它变成可执行的检查：它带着一份具体的模式清单逐条扫，命中就替换。清单的来源是维基百科整理的"AI 写作特征"，涵盖宣传式语言、三段式堆叠、回避简单系动词、公式化的"挑战与未来展望"、粗体滥用、知识截止日期免责声明、填充短语、通用积极结论等等。

它还替你划了一条容易被忽略的标准：**去掉模式只是工作的一半**。技术上干净但没有声音的写作，和机器生成的内容一样明显。所以它的第二项任务是注入个性——有观点、变化节奏、承认复杂性、必要时用第一人称。它不写代码、不定义产品、不做翻译，技术文档也不在它的适用范围。

## 什么时候用

| 你会这样说 | 场景 |
| --- | --- |
| "这段太有 AI 味了，改一下" | 已有成稿需要去痕 |
| "帮我改得像人写的" | 语气过于中立、没有声音 |
| "去掉 AI 痕迹" | 直接触发 |
| "这篇公众号读起来很假" | 宣传式语言和三段式过载 |
| "帮我把这段润一下，别加内容" | 保留含义、只改表达 |
| "为什么这段读起来不像人写的" | 需要点出具体命中了哪些模式 |

触发词概括起来是三组：去 AI 痕迹、人性化、文本优化。

## 什么时候不要用

- **翻译** → 不在范围。它只在同一语言内改写表达。
- **技术文档、API 文档、开发者指南** → [doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/)。
- **内部沟通、状态更新、发布说明** → [internal-comms](/skills/skills-reference/low/internal-comms/)。
- **产品定义、验收标准** → [product-manager](/skills/skills-reference/critical/product-manager/)。
- **代码实现** → [universal-development](/skills/skills-reference/low/universal-development/)。
- **补事实、查证、加数据** → 不在范围。它改的是表达方式，不核实内容真伪。

不适用范围概括为四条：代码实现、产品定义、翻译、技术文档。

## 前置条件

它没有声明 `gates`，也确实没有流程门槛——不需要仓库、不需要 TODO。真实的输入要求有两条：

1. **要有一段待改写的文本**，以及预期的语气（正式、随意、技术等）。维持语调是它的固定任务之一，没有目标语气就只能猜。
2. **文本里的事实必须已经正确**。它的任务是"保留含义"，所以不会补事实、不会查证、也不会替你把模糊主张换成真数据——只有原文已经有具体细节时，才能用具体替换模糊。

<Aside type="caution">
最容易被误解的一点：它不是"润色"。润色会让句子更漂亮，而这里的很多动作是**减法**——删掉过渡词、删掉三个并列形容词、删掉夸张的象征意义、把绕开的系动词还原成"是"和"有"。改完往往比原文短。
</Aside>

## 怎么用

### 1. 交文本，说语气

把要改的段落给它，并说清用在哪里、希望是什么口吻。不需要你先指出哪里像 AI——识别是它的工作。

### 2. 它逐条扫模式，而不是整体重写

它带着一份固定清单去比对，命中项包括：过度强调知名度与媒体报道、宣传广告式用语、公式化的"挑战与未来展望"段落、回避简单系动词、三段式并列过载、把不同尺度的东西凑成"从 X 到 Y"、粗体滥用、知识截止日期免责声明、填充短语、以及"前景光明"这类通用积极结论。

<Aside type="note">
清单里有两条来自英文语境，中文里表现不同：标题大小写在中文基本不适用；弯引号问题在中文里体现为英文引号的用法。它对这两条做过本地化处理，所以不会照搬英文规则误判中文文本。
</Aside>

### 3. 它把去痕和注入个性一起做

同一遍改写里并行五件事：识别模式、重写问题片段、保留含义、维持语调、注入个性。个性部分的动作是有取向的——允许表达观点而不是只做中立报道、让句子长短交替而不是全篇同一节奏、承认复杂性和不确定性、该用第一人称就用、把"这令人担忧"换成具体的场景和时刻。

<Aside type="tip">
判断改完没改完的最好办法是大声朗读。它的验收标准之一就是朗读时听起来自然、句子结构有真实变化、模糊主张被具体细节替换、简单结构在合适的地方被恢复。你验收时用同一招最省事。
</Aside>

### 4. 你拿到改写结果加一份可选说明

固定两部分：改写后的文本，以及所做更改的简要总结（有帮助时才给）。除非你指定路径，它不新建文件、不改 TODO、不留仓库痕迹。

## 与其他 Skill 的关系

它的相关列表是平铺的：[doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/)、[internal-comms](/skills/skills-reference/low/internal-comms/)，没有前置或后续分组，所以它是一个**可以随时插入的独立入口**——任何已经成稿的中文文本都能交给它。

- **上游（先成稿）**：[doc-coauthoring](/skills/skills-reference/medium/doc-coauthoring/)、[internal-comms](/skills/skills-reference/low/internal-comms/)。
- **下游**：事实核对和最终确认由人来做；它不核实内容真伪。

```text
doc-coauthoring / internal-comms（先把内容写出来）
        ↓
humanizer-zh（扫模式 → 重写 → 注入个性）
        ↓
人工确认事实与语气是否符合场景
```

## 产出与验收

判断真的完成了：

- 清单里命中的模式**逐条**被处理，而不是整体重写一遍换个说法；
- 句子长度和结构有真实变化，不是全篇同一节奏；
- 模糊主张被具体细节替换（具体功能、具体数字、具体时间），而不是换成另一个形容词；
- 系动词恢复了，多余的粗体和三段式并列被清掉；
- 没有残留的知识截止日期免责声明和通用积极结论；
- 语气与场景一致——去 AI 味不等于把正式文本改成随意口语；
- 核心信息完整，没有在改写过程中丢掉或新增事实。
