## 如何使用这本手册

**这本手册不是从头读的**，而是按需查询的工具书。三种查法：

1. **知道要干什么，不知道用哪个 Skill**：看下面的「Skill 分类索引」，按你的领域找
2. **知道 Skill 名字，想看详细规则**：用左侧导航或搜索框直接跳转
3. **想了解整体有哪些能力**：快速浏览「Skill 优先级分层」表格

<Aside type="tip">
**场景示例**：你要「设计一个登录 API」
1. 扫「开发实施」分类 → 看到 `api-development`
2. 点进去看触发词：✅ "API 开发" 命中
3. 看 gates：需要已有产品定义 ✅
4. 直接说「设计登录 API」或 `/api-development`
</Aside>

## 概述

Skills Framework 提供 95 个专业 Skill，覆盖产品管理、架构设计、前后端开发、质量保障、Git 工作流等全栈开发场景。每个 Skill 都是独立的能力单元，通过 frontmatter 元数据实现精确路由。

## Skill 优先级分层

Skills Framework 按优先级分为四档，确保关键场景优先匹配。**左侧导航按这四档分组**，和下面的分类索引是同一批页面的两种查法。

| 优先级 | 数量 | 适用场景 | 特征 |
|--------|------|----------|------|
| **Critical** | 2 个 | 需求变更、新功能定义 | 一旦命中就抢占其他路由，避免漏做影响分析或重复规划 |
| **High** | 25 个 | 核心开发流程 | 产品、架构、实现、验证、Git 等主路径 |
| **Medium** | 30 个 | 专业领域开发 | 缓存、推送、部署、测试、文档等细分领域 |
| **Low** | 38 个 | 扩展与兜底 | 文件处理、设计工具、第三方集成、提示词工程 |

<Aside type="note">
优先级只决定**话术模糊时谁先被选中**，不代表能力强弱。Low 优先级的 Skill 需要你说得更具体，例如"把这份 Excel 拆成三个 sheet"。
</Aside>


## 核心工作流

### 新项目启动

```
project-navigator → product-manager → architecture-design → 
tech-decision → project-manager → [专业 Skill]
```

**涉及 Skill**：
- `project-navigator`: 发现项目结构与参考实现
- `product-manager`: 完成产品定义与验收条件
- `architecture-design`: 设计系统边界与模块
- `tech-decision`: 选择可实施、可验证的技术方案
- `project-manager`: 生成功能+菜单形式的 TODO

### 需求变更

```
change-impact-analysis → [受影响的专业 Skill] → 
project-manager (更新 TODO)
```

**关键 Skill**：
- `change-impact-analysis`: 识别影响闭包并定向回流

### 功能开发

```
[专业 Skill 实现] → code-review → git-commit → 
update-status → next (领取下一项)
```

**涉及 Skill**：
- 实现类: `dev`, `crud-development`, `api-development`, `ui-pc`, `ui-app` 等
- `code-review`: 缺陷优先 Review
- `git-commit`: 精确提交与推送
- `update-status`: 更新 TODO 状态
- `next`: 选择下一个可执行功能

## Skill 路由机制

Skills Framework 通过三层机制实现精确路由：

### 1. Frontmatter 元数据

每个 Skill 的 `SKILL.md` 包含结构化元数据：

```yaml
triggers:
  zh: [中文触发词]
  en: [English triggers]

gates:
  - "前置条件1"
  - "前置条件2"

conflicts:
  other-skill: "职责边界说明"

related_skills:
  before: [前置依赖]
  after: [后续推荐]
  complement: [协作 Skill]
```

### 2. 决策树路由

`skill-router.yaml` 定义 78 个典型场景、655 个触发词，按优先级自动选择最佳 Skill。

### 3. Runtime Hook 动态提示

`UserPromptSubmit` 和 `SubagentStart` Hook 根据当前 TODO 状态和项目记忆提示适用 Skill。

详细路由机制见 [核心概念 - 路由机制](/skills/core-concepts/routing/)。

## 使用建议

### 明确调用 vs 自动路由

```bash
# 明确调用特定 Skill
/code-review

# 自然语言触发自动路由
"帮我设计用户登录的 API"  # → api-development
"需求改了，要加个字段"    # → change-impact-analysis
"Review 这段代码"         # → code-review
```

### 前置条件检查

部分 Skill 有明确的 gates（前置条件）：

- `change-impact-analysis`: 需要已有批准范围
- `frontend-design`: 需要已有产品定义
- `code-review`: 需要有 git diff
- `update-status`: 需要有代码变更或 Review 结果

### 冲突解决

当多个 Skill 触发词重叠时，conflicts 规则自动选择：

- **"优化页面"**: 
  - 新页面 → `frontend-design`
  - 已有页面 → `frontend-polish`
  
- **"需求改了"**: 
  - 新需求 → `product-manager`
  - 已有范围变更 → `change-impact-analysis`

### 链式调用

复杂任务通常需要多个 Skill 协作：

```
1. product-manager        # 产品定义
2. frontend-design        # UI/UX 设计
3. architecture-design    # 系统架构
4. tech-decision          # 技术选型
5. project-manager        # 生成 TODO
6. api-development        # 实现 API
7. ui-pc                  # 实现页面
8. code-review            # 代码审查
9. git-commit             # 提交代码
10. update-status         # 更新状态
```
