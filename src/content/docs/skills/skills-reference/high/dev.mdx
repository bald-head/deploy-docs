## 概述

`dev` 是 **High 优先级** Skill，负责实施已批准 TODO 中的通用纵向功能。统一协调数据、API、后端、前端、权限等专业 Skill，完成完整的功能交付。

**适用场景**：
- 唯一 TODO 中明确的通用纵向功能
- 非纯 CRUD、非专业领域（如认证/权限/缓存）的业务功能

**不适用场景**：
- 纯 CRUD 业务 → 使用 `crud-development`
- 专业领域（认证/权限/缓存）→ 使用对应专业 Skill
- 代码生成器开发 → 使用 `code-generator`

## 快速开始

### 开发新功能的完整流程

```bash
# 1. 确认已有规划
# 检查 docs/<developer-id>/tasks/todo/*.md 是否有待开发功能

# 2. 领取功能
# Runtime 会自动领取下一个 Ready 功能

# 3. 实施功能
"开始实现 USER-LOGIN 功能"

# 4. 验证功能
npm run dev
# 访问 http://localhost:3000/login 测试

# 5. Review 代码
/code-review

# 6. 提交代码（授权后）
/git-commit
```

### 三种运行模式

| 模式 | 适用场景 | 说明 |
|------|---------|------|
| **existing** | 已有仓库 | 保护现有改动、复用生产模式 |
| **bootstrap** | 新项目骨架 | 实施 SHARED-BOOTSTRAP 技术项 |
| **greenfield** | 首个业务功能 | 共享骨架完成后的首个纵向功能 |

## 使用示例

### 场景 1：实施用户登录功能

**TODO 中的功能**：
```markdown
- [ ] `USER-LOGIN` 用户登录；Owner: alice-chen
  - 来源: PRD#用户登录
  - 来源锚点: `docs/prd.md#用户登录`
  - 目标: 用户可以通过邮箱密码登录
  - 验收: AC-001, AC-002, AC-003
  - 依赖: 无
  - 交付面: data / api / backend / web
```

**执行步骤**：

1. **明确目标**（自动完成）：
   ```markdown
   来源复核: docs/prd.md#用户登录 -> 锚点一致
   来源复核: docs/architecture.md#认证模块 -> 锚点一致
   来源复核: docs/tech-decision.md#JWT认证 -> 锚点一致
   ```

2. **复用检查**（调用 project-navigator）：
   ```markdown
   Reuse map:
   - 数据库: MySQL 8.0 (复用)
   - ORM: MyBatis (复用)
   - 认证框架: Spring Security + JWT (复用)
   - 前端框架: Vue 3 (复用)
   ```

3. **协调专业 Skill**：
   ```text
   交付面: data / api / backend / web
   
   → database-design: 设计 users 表
   → database-ops: 创建表和迁移脚本
   → api-development: 设计 POST /api/v1/auth/login
   → backend: 实现 AuthController.login()
   → ui-pc: 实现登录页面 src/pages/login.vue
   → security-guard: 实现 JWT Token 生成
   ```

4. **实施代码**：
   ```java
   // backend/src/main/java/controller/AuthController.java
   @RestController
   @RequestMapping("/api/v1/auth")
   public class AuthController {
       @PostMapping("/login")
       public Result<LoginResponse> login(@RequestBody LoginRequest req) {
           // 实现登录逻辑
       }
   }
   ```

5. **验证功能**：
   ```bash
   # 启动后端
   cd backend && mvn spring-boot:run
   
   # 启动前端
   cd frontend && npm run dev
   
   # 访问 http://localhost:5173/login
   # 测试登录功能
   ```

6. **记录证据**：
   ```markdown
   验收证据:
   - AC-001: 用户可以输入邮箱密码 → 手工测试通过
   - AC-002: 登录成功返回 Token → DevTools 验证
   - AC-003: Token 存储在 localStorage → 验证通过
   ```

7. **Code Review**：
   ```bash
   /code-review
   # Review 结果: pass
   ```

8. **提交代码**：
   ```bash
   /git-commit
   # 提交消息: feat: implement user login
   ```

### 场景 3：Bootstrap 共享骨架

**TODO 中的技术项**：
```markdown
- [ ] `SHARED-BOOTSTRAP` 共享框架骨架；Owner: alice-chen
  - 架构: 单体分层架构
  - 技术: Spring Boot 2.7 + Vue 3
  - 环境: local, test, prod
  - 仓库: 单仓
  - 验收: 
    - 后端可启动
    - 前端可访问
    - 数据库连接成功
```

**实施步骤**：

1. **后端骨架**：
   ```bash
   # 创建 Spring Boot 项目
   spring init --dependencies=web,mysql,mybatis backend
   
   # 配置 application.yml
   # 配置数据库连接
   ```

2. **前端骨架**：
   ```bash
   # 创建 Vue 3 项目
   npm create vite@latest frontend -- --template vue
   
   # 安装依赖
   cd frontend && npm install
   ```

3. **数据库迁移基线**：
   ```sql
   -- migrations/V001__init.sql
   CREATE DATABASE IF NOT EXISTS user_system;
   ```

4. **环境配置**：
   ```yaml
   # application-local.yml
   spring:
     datasource:
       url: jdbc:mysql://localhost:3306/user_system
   ```

5. **验证**：
   ```bash
   # 启动后端
   cd backend && mvn spring-boot:run
   # → 成功启动
   
   # 启动前端
   cd frontend && npm run dev
   # → 访问 http://localhost:5173 成功
   
   # 数据库连接
   mysql -u root -p -e "SHOW DATABASES;"
   # → user_system 存在
   ```

## 关键规则

### 1. 只消费已领取的 `[~]` 功能

```markdown
<!-- 正确 -->
当前 runtime instance: abc123
当前 TODO:
- [~] `USER-LOGIN` (执行实例: abc123) ← 只实施这个

<!-- 错误 -->
- [~] `ORDER-QUERY` (执行实例: def456) ← 不能实施
```

### 2. 依赖必须完成才能开始

```markdown
<!-- 正确 -->
- [x] `USER-INFO-API` (依赖已完成)
- [ ] `USER-INFO-PAGE` (依赖: USER-INFO-API) ← 可以领取

<!-- 错误 -->
- [~] `USER-INFO-API` (正在进行)
- [ ] `USER-INFO-PAGE` (依赖: USER-INFO-API) ← 不能领取
```

### 3. 纵向完整交付

```markdown
<!-- 正确: 纵向完整 -->
交付面: data / api / backend / web
→ 数据库表 + API + Service + 页面

<!-- 错误: 只完成一层 -->
交付面: api
→ 只写 API，不写数据库和前端
```

### 4. 代码优先原则

- ✅ 95% 时间用于代码实现、验证、Review
- ❌ 5% 时间用于 TODO、报告等辅助文档
- 默认不生成过程报告或 Context JSON

### 5. 阶段门禁

```markdown
当前阶段: technical-plan
→ 不能写生产代码

当前阶段: business-development
→ 可以写生产代码

当前阶段: code-review
→ 只能 Review，不能新增功能
```

## Skill 协调

`dev` 统一协调以下专业 Skill：

| 交付面 | 调用 Skill |
|--------|-----------|
| data | database-design, database-ops |
| api | api-development |
| backend | 后端业务逻辑 |
| web | ui-pc |
| app | ui-app |
| permission | security-guard, data-permission |
| integration | 外部集成相关 Skill |

<Aside type="note">
一个功能只做一次验证和 Review，所有专业 Skill 在同一实现遍中统一应用。
</Aside>

## 与其他 Skill 的关系

### 选择决策

```text
优先级: 专业 Skill > dev > universal-development

例子:
- 纯 CRUD → crud-development
- API 开发 → api-development  
- 通用功能 → dev
- 无适用专业 Skill → universal-development
```

### Related Skills

**协作 Skill**:
- `crud-development` - CRUD 业务
- `api-development` - API 实现
- `code-review` - 代码审查
- `universal-development` - 兜底开发

## 最佳实践

### 1. 先复用，后新建

```markdown
<!-- 正确 -->
检查 Reuse map:
- 认证框架: Spring Security (复用)
→ 使用 Spring Security

<!-- 错误 -->
不检查 Reuse map
→ 新建自己的认证实现
```

### 2. 来源锚点必须复核

```bash
# 每次开始前
来源复核: docs/prd.md#用户登录 -> 锚点一致

# 如果不一致
来源复核: docs/prd.md#用户登录 -> 已发现变化
→ 调用 change-impact-analysis
```

### 3. 完整验证闭环

```bash
# 每个功能必须
1. 启动后端
2. 启动前端
3. 访问真实入口
4. 验证所有 AC
5. 记录证据
```

### 4. 一次 Review

```markdown
<!-- 正确 -->
完成全部交付面 → 一次 code-review

<!-- 错误 -->
完成数据库 → code-review
完成 API → code-review
完成前端 → code-review
```
