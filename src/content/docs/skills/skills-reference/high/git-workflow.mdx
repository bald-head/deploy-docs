## 概述

`git-workflow` 是 **High 优先级** Skill，负责处理 Git 分支、历史与冲突。

**适用场景**：
- 分支管理（创建、切换、删除）
- 合并分支
- rebase 操作
- 解决冲突
- stash 操作

**不适用场景**：
- 普通提交和推送 → 使用 `git-commit`
- 代码实现 → 使用 `dev` 或 `universal-development`
- 产品定义 → 使用 `product-manager`

## 快速开始

### 分支管理的完整流程

```bash
# 1. 创建新分支
git checkout -b feature/user-login

# 2. 开发功能
# ... 编写代码 ...

# 3. 提交代码
/git-commit

# 4. 合并到主分支
git checkout main
git merge feature/user-login

# 5. 删除分支（可选）
git branch -d feature/user-login
```

## 使用示例

### 场景 1：创建和切换分支

**创建功能分支**：
```bash
# 从 main 创建新分支
git checkout main
git checkout -b feature/user-login

# 或使用新版本命令
git switch -c feature/user-login

# 查看当前分支
git branch
# * feature/user-login
#   main
```

**切换分支**：
```bash
# 切换到 main
git checkout main

# 切换回 feature 分支
git checkout feature/user-login

# 或使用新版本命令
git switch feature/user-login
```

### 场景 2：合并分支

**快进合并（Fast-forward）**：
```bash
# 功能开发完成
git checkout feature/user-login
/git-commit

# 切换到 main
git checkout main

# 合并
git merge feature/user-login
# Updating a1b2c3d..e4f5g6h
# Fast-forward
#  src/main/java/controller/AuthController.java | 50 +++++++++++
#  src/pages/login.vue | 120 +++++++++++++++++++++++
#  2 files changed, 170 insertions(+)
```

**三方合并（Three-way merge）**：
```bash
# main 分支有新的提交
git checkout main
git log --oneline
# e4f5g6h (HEAD -> main) feat: 添加用户列表
# a1b2c3d feat: 初始化项目

# feature 分支也有提交
git checkout feature/user-login
git log --oneline
# h7i8j9k (HEAD -> feature/user-login) feat: 实现登录
# a1b2c3d feat: 初始化项目

# 合并
git checkout main
git merge feature/user-login
# Merge made by the 'ort' strategy.
#  src/main/java/controller/AuthController.java | 50 +++++++++++
#  src/pages/login.vue | 120 +++++++++++++++++++++++
#  2 files changed, 170 insertions(+)
```

### 场景 3：解决冲突

**冲突发生**：
```bash
git checkout main
git merge feature/user-login
# Auto-merging src/main/java/controller/UserController.java
# CONFLICT (content): Merge conflict in src/main/java/controller/UserController.java
# Automatic merge failed; fix conflicts and then commit the result.

# 查看冲突文件
git status
# On branch main
# You have unmerged paths.
#   (fix conflicts and run "git commit")
#
# Unmerged paths:
#   (use "git add <file>..." to mark resolution)
#       both modified:   src/main/java/controller/UserController.java
```

**查看冲突内容**：
```java
// src/main/java/controller/UserController.java
@RestController
@RequestMapping("/api/v1/users")
public class UserController {
    
<<<<<<< HEAD
    @GetMapping
    public Result<List<UserVO>> list() {
        return Result.ok(userService.list());
    }
=======
    @GetMapping
    public Result<PageResult<UserVO>> list(UserQuery query) {
        return Result.ok(userService.page(query));
    }
>>>>>>> feature/user-login
}
```

**解决冲突**：
```java
// 手工合并两个版本的改动
@RestController
@RequestMapping("/api/v1/users")
public class UserController {
    
    @GetMapping
    public Result<PageResult<UserVO>> list(UserQuery query) {
        return Result.ok(userService.page(query));
    }
}
```

**标记冲突已解决**：
```bash
# 暂存解决后的文件
git add src/main/java/controller/UserController.java

# 完成合并
git commit
# 自动生成合并提交信息:
# Merge branch 'feature/user-login'
# 
# Conflicts:
#       src/main/java/controller/UserController.java
```

### 场景 4：Rebase 操作

**基本 rebase**：
```bash
# 在 feature 分支
git checkout feature/user-login

# 将 feature 分支 rebase 到最新的 main
git rebase main
# Successfully rebased and updated refs/heads/feature/user-login.

# 如果有冲突
git rebase main
# CONFLICT (content): Merge conflict in src/main/java/controller/UserController.java
# error: could not apply h7i8j9k... feat: 实现登录

# 解决冲突
# 编辑冲突文件...

# 标记冲突已解决
git add src/main/java/controller/UserController.java

# 继续 rebase
git rebase --continue

# 如果放弃 rebase
git rebase --abort
```

**交互式 rebase**：
```bash
# 修改最近 3 个提交
git rebase -i HEAD~3

# 编辑器会打开:
# pick a1b2c3d feat: 实现登录接口
# pick d4e5f6g feat: 实现登录页面
# pick h7i8j9k fix: 修复登录bug
#
# 可以使用的命令:
# pick = 保留提交
# reword = 保留提交但修改提交信息
# edit = 保留提交但停下来修改
# squash = 合并到上一个提交
# fixup = 合并到上一个提交但丢弃提交信息
# drop = 删除提交
```

### 场景 5：Stash 操作

**保存当前工作**：
```bash
# 当前有未提交的改动
git status
# On branch feature/user-login
# Changes not staged for commit:
#   modified:   src/main/java/controller/UserController.java

# 暂存改动
git stash
# Saved working directory and index state WIP on feature/user-login: a1b2c3d feat: 初始化

# 或添加描述
git stash push -m "临时保存用户控制器改动"

# 查看工作区
git status
# On branch feature/user-login
# nothing to commit, working tree clean
```

**恢复 stash**：
```bash
# 查看 stash 列表
git stash list
# stash@{0}: On feature/user-login: 临时保存用户控制器改动
# stash@{1}: WIP on main: e4f5g6h feat: 添加用户列表

# 恢复最新的 stash
git stash pop
# On branch feature/user-login
# Changes not staged for commit:
#   modified:   src/main/java/controller/UserController.java
# Dropped refs/stash@{0}

# 或恢复指定的 stash（不删除）
git stash apply stash@{1}

# 删除 stash
git stash drop stash@{0}

# 清空所有 stash
git stash clear
```

### 场景 6：删除分支

**删除本地分支**：
```bash
# 删除已合并的分支
git branch -d feature/user-login
# Deleted branch feature/user-login (was h7i8j9k).

# 强制删除未合并的分支（谨慎）
git branch -D feature/abandoned
# Deleted branch feature/abandoned (was x9y8z7w).
```

**删除远程分支**：
```bash
# 删除远程分支（需要授权）
git push origin --delete feature/user-login
# To https://github.com/user/repo.git
#  - [deleted]         feature/user-login
```

<Aside type="caution">
删除远程分支是高风险操作，需要明确授权。
</Aside>

## 关键规则

### 1. 分支策略

```bash
# 推荐: Git Flow
main          # 生产分支
develop       # 开发分支
feature/*     # 功能分支
hotfix/*      # 热修复分支
release/*     # 发布分支

# 或简化: GitHub Flow
main          # 主分支
feature/*     # 功能分支
```

### 2. 合并策略

```bash
# 选择 1: Merge（保留完整历史）
git merge feature/user-login

# 选择 2: Rebase（线性历史）
git rebase main

# 选择 3: Squash（压缩提交）
git merge --squash feature/user-login
```

### 3. 冲突解决原则

```markdown
1. 理解冲突原因
2. 保留两边的有效改动
3. 测试合并后的代码
4. 不能随意丢弃改动
```

### 4. 高风险操作需授权

```bash
# 需要授权的操作:
- git push --force
- git push origin --delete <branch>
- git reset --hard
- git rebase -i (改历史)

# 必须明确:
- 仓库路径
- 远程名称
- 目标分支
- 当前 OID
- 影响范围
```

## 分支管理最佳实践

### 1. 分支命名规范

```bash
# 功能分支
feature/user-login
feature/order-manage

# Bug 修复
fix/login-error
fix/order-status

# 热修复
hotfix/security-patch
hotfix/critical-bug

# 发布分支
release/v1.0.0
release/v1.1.0
```

### 2. 及时同步主分支

```bash
# 开发前
git checkout main
git pull origin main
git checkout -b feature/new-feature

# 开发中（定期同步）
git checkout main
git pull origin main
git checkout feature/new-feature
git merge main
# 或
git rebase main
```

### 3. 小步提交，经常合并

```bash
# 好的实践
feature/user-login  # 只实现登录功能
feature/user-register  # 只实现注册功能

# 不好的实践
feature/user-module  # 包含太多功能
```

### 4. 合并前检查

```bash
# 合并前检查清单
- [ ] 功能已完成
- [ ] 代码已提交
- [ ] Review 已通过
- [ ] 测试已通过
- [ ] 无未解决的冲突
- [ ] 分支已同步最新主分支
```

## Skill 协调

`git-workflow` 处理以下操作：

| 操作 | 说明 |
|------|------|
| 分支管理 | 创建、切换、删除分支 |
| 合并 | merge、rebase、squash |
| 冲突 | 解决合并冲突 |
| 历史 | cherry-pick、revert |
| 暂存 | stash、unstash |

<Aside type="note">
普通 commit 和 push 由 `git-commit` 处理，不在本 Skill 范围内。
</Aside>

## 故障排查

### 问题 1: 合并冲突

**症状**: `CONFLICT (content): Merge conflict in file.java`

**解决**:
```bash
# 1. 查看冲突文件
git status

# 2. 编辑文件解决冲突
# 删除 <<<<<<<, =======, >>>>>>> 标记

# 3. 标记已解决
git add file.java

# 4. 完成合并
git commit
```

### 问题 2: Rebase 出错

**症状**: `error: could not apply commit...`

**解决**:
```bash
# 1. 解决冲突
# 编辑冲突文件...

# 2. 标记已解决
git add file.java

# 3. 继续 rebase
git rebase --continue

# 或放弃 rebase
git rebase --abort
```

### 问题 3: 误删分支

**症状**: 分支被误删除

**解决**:
```bash
# 1. 查找删除的分支 commit
git reflog
# a1b2c3d HEAD@{0}: checkout: moving from feature/user-login to main
# h7i8j9k HEAD@{1}: commit: feat: 实现登录

# 2. 恢复分支
git checkout -b feature/user-login h7i8j9k
```
