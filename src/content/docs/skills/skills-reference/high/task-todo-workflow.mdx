## 概述

`task-todo-workflow` 是 **High 优先级** Skill，是新项目或新功能的**强制第一入口**。负责建立阶段状态机，并维护当前开发者覆盖完整纵向交付面的唯一 TODO 文件。

**核心职责**：
- 新项目/新功能的第一入口（--plan-start）
- 12 阶段状态机管理（intake → complete）
- 开发者身份解析与 TODO 路径规则
- Feature 来源锚点与上下文恢复
- 轻量上下文与项目记忆集成
- 阻止生产代码过早编辑（PreToolUse 门禁）

<Aside type="caution">
新项目/新功能必须先命中本 Skill 建立状态机，再进入任何产品、设计或实现 Owner。不能等全部方案完成后才建立状态。
</Aside>

### Gates（前置条件）

1. **新项目或尚未规划的新功能**（首次入口）
2. **或需要维护当前开发者唯一 TODO**
3. **已明确开发者身份**（Git user.name 或系统用户）

### Not For（不适用场景）

- 产品定义
- 架构设计
- 代码实现
- 需求分析
- 普通问答、只读诊断、单条命令或无需持久状态的低风险维护

## 使用场景

### 场景 1：新项目启动

**用户输入**：
```
我要做一个用户管理系统
```

**Skill 行为**：

1. **解析开发者身份**：
   ```bash
   # 优先级 1: Git user.name
   git config --get user.name  # → alice-chen
   
   # 规范化为目录安全 ID
   developer-id: alice-chen
   ```

2. **确定唯一 TODO 路径**：
   ```
   docs/alice-chen/tasks/todo/user-system.md
   ```

3. **执行 --plan-start**：
   ```bash
   node runtime-hooks/scripts/todo-continuation.cjs \
     --plan-start \
     --title "用户管理系统"
   ```

4. **创建 TODO 文件并初始化阶段状态机**：
   ```markdown
   # 用户管理系统 TODO
   
   Owner: alice-chen
   项目: 用户管理系统
   仓库: /path/to/user-system
   
   ## 阶段状态机
   
   **当前阶段**: intake
   **阶段状态**: in-progress
   **阶段 Owner**: task-todo-workflow
   **阶段门禁**: 记录项目入口信息
   **阶段产物**: 待生成
   **已完成阶段**: (无)
   **阶段结果**: 待生成
   **下一步**: 需求分析
   **阻塞/恢复**: (无)
   
   ---
   
   ## 持久阶段记录
   
   ### intake (进行中)
   - 开始时间: 2026-09-03 10:00
   - Owner: task-todo-workflow
   - 产物: 待生成
   - 结果: 待生成
   ```

5. **推进到 requirements-analysis**：
   ```bash
   node runtime-hooks/scripts/todo-continuation.cjs \
     --plan-advance \
     --stage intake \
     --next-stage requirements-analysis \
     --artifact "项目入口已记录" \
     --result "开发者: alice-chen, 项目: 用户管理系统"
   ```

6. **路由到 product-manager**：
   ```
   现在进入需求分析阶段，请完成产品定义
   ```

### 场景 2：阶段推进（需求确认）

**当前阶段**: requirements-analysis

**product-manager 完成产品定义后**：

```bash
# 等待用户确认
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-await \
  --stage requirements-analysis \
  --result "等待用户确认产品定义"
```

**用户确认后**：

```bash
# 推进到技术方案阶段
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-advance \
  --stage requirements-analysis \
  --next-stage technical-plan \
  --confirmed \
  --artifact "docs/prd.md" \
  --result "产品定义已确认：3个角色、5个核心能力、用户确认通过"
```

### 场景 3：PreToolUse 门禁阻止过早编码

**当前阶段**: technical-plan

**用户错误输入**：
```
开始写代码
```

**PreToolUse Hook 拦截**：

```
❌ 阻止操作

当前阶段: technical-plan
当前阶段状态: in-progress

不允许在 business-development 之前编辑生产代码。

当前阶段必须完成:
- technical-plan: 技术方案设计
- technical-confirmation: 技术方案确认
- task-breakdown: 任务拆分生成 TODO

请先完成上述阶段，再进入代码实施。
```

### 场景 4：阻塞与恢复

**阻塞场景**：

```bash
# 等待外部依赖
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-block \
  --stage technical-plan \
  --result "等待数据库账号开通，预计 2 天"
```

**TODO 更新**：
```markdown
**当前阶段**: technical-plan
**阶段状态**: blocked
**阻塞/恢复**: 等待数据库账号开通，预计 2 天；恢复条件：收到 DBA 开通邮件
```

**恢复操作**：

```bash
# 数据库账号已开通
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-resume \
  --stage technical-plan \
  --result "数据库账号已开通，连接测试通过"
```

### 场景 5：跳过不适用阶段

**场景**: 项目不使用代码生成器

```bash
# 标记 code-generation 不适用
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-advance \
  --stage task-breakdown \
  --next-stage code-generation \
  --artifact "不适用：项目采用手写代码，无代码生成器" \
  --result "任务拆分完成，直接进入业务开发"

# 立即推进到 business-development
node runtime-hooks/scripts/todo-continuation.cjs \
  --plan-advance \
  --stage code-generation \
  --next-stage business-development \
  --artifact "不适用" \
  --result "跳过代码生成，进入业务开发"
```

<Aside type="note">
`code-generation`、`test-generation` 和 `user-acceptance` 不适用时必须写事实原因，不能静默跳过。
</Aside>

## 工作原理

### 开发者身份与唯一路径

#### 身份解析优先级

```text
优先级 1: Git user.name
  git config --get user.name
  → alice-chen

优先级 2: 系统登录用户名
  whoami / $USER
  → alice

优先级 3: 环境变量
  $AGENT_DEVELOPER_NAME
  → alice-chen
```

#### TODO 路径规则

```text
当前开发者: alice-chen
唯一 TODO 路径: docs/alice-chen/tasks/todo/<原文件名>.md

其他开发者: bob-zhang
其他 TODO 路径: docs/bob-zhang/tasks/todo/<原文件名>.md (只读)
```

**路径规则**：
- 当前开发者目录内只能有一个活动 `.md` TODO
- 发现第二份时立即阻断并合并
- 其他 `<developer-id>` 目录只读
- 迁移时保留原文件名的日期或业务前缀
- 同一 Git identity 下的主 Agent 与 subagent 共用该 TODO

<Aside type="caution">
`docs/tasks/todo/`、`tasks/todo/`、`docs/<developer-id>/task/todo/` 和 Workflow/Context 目录只读兼容。发现后迁入当前开发者的 `docs/<developer-id>/tasks/todo/` 主目录。
</Aside>

### 12 阶段状态机

固定阶段顺序：

```text
intake
  ↓
requirements-analysis
  ↓
requirements-confirmation
  ↓
technical-plan
  ↓
technical-confirmation
  ↓
task-breakdown
  ↓
code-generation
  ↓
business-development
  ↓
code-review
  ↓
test-generation
  ↓
test-run
  ↓
user-acceptance
  ↓
git-delivery
  ↓
complete
```

#### 阶段 Owner 与职责

| 阶段 | Owner | 职责 |
|------|-------|------|
| intake | task-todo-workflow | 记录项目入口信息 |
| requirements-analysis | product-manager | 需求分析与完整产品定义 |
| requirements-confirmation | product-manager | 等待用户确认产品定义 |
| technical-plan | architecture-design, frontend-design, tech-decision | 技术方案设计 |
| technical-confirmation | 技术 Owner | 等待技术方案确认 |
| task-breakdown | project-manager | 任务拆分与唯一 TODO 生成 |
| code-generation | code-generator | 仅在确有生成器时执行 |
| business-development | dev | 纵向开发和验证 |
| code-review | code-review | 一次完整 Review |
| test-generation | test-development | 仅在本轮授权或仓库强制要求时进入 |
| test-run | test-development | 运行测试并验证 |
| user-acceptance | real-browser-automation | 适用的真实用户验收 |
| git-delivery | git-commit | 授权后的交付 |
| complete | - | 项目完成 |

#### 阶段字段

每个阶段必须记录：

```markdown
**当前阶段**: <stage-name>
**阶段状态**: in-progress / blocked / completed
**阶段 Owner**: <skill-name>
**阶段门禁**: <门禁条件>
**阶段产物**: <产物路径或"待生成">
**已完成阶段**: <逗号分隔的已完成阶段>
**阶段结果**: <门禁证据或"待生成">
**下一步**: <下一阶段名称>
**阻塞/恢复**: <阻塞原因与恢复条件>
```

#### 阶段推进命令

```bash
# 1. 启动新项目/功能
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-start \
  --title "功能名称"

# 2. 推进到下一阶段
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-advance \
  --stage <current> \
  --next-stage <next> \
  --artifact "路径或不适用原因" \
  --result "门禁证据"

# 3. 等待确认（requirements-confirmation 或 technical-confirmation）
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-await \
  --stage <current> \
  --result "等待用户/Owner确认"

# 4. 确认后推进（必须添加 --confirmed）
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-advance \
  --stage requirements-confirmation \
  --next-stage technical-plan \
  --confirmed \
  --artifact "docs/prd.md" \
  --result "用户确认通过"

# 5. 阻塞
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-block \
  --stage <current> \
  --result "阻塞原因与恢复条件"

# 6. 恢复
node <skills-root>/runtime-hooks/scripts/todo-continuation.cjs \
  --plan-resume \
  --stage <current> \
  --result "恢复依据"
```

<Aside type="caution">
`requirements-confirmation` 与 `technical-confirmation` 必须在明确确认后追加 `--confirmed` 才能推进。
</Aside>

### Feature 来源锚点与上下文恢复

每个可执行 Feature 都必须在唯一 TODO 中保存**来源锚点**：

```markdown
来源锚点：
- 来源文档: `docs/prd.md#用户注册`, `docs/ui-design.md#注册页面`
- 用户结果: 用户可以通过邮箱注册账号
- 范围边界: 必须实现邮箱+密码注册；不支持第三方登录；禁止替代为手机号注册
- 数据/权限边界: 用户表；默认分配"普通用户"角色；无特殊权限要求
- 关键状态/验收: AC-001: 用户可以注册；AC-002: 邮箱唯一性验证
- 设计约束: Element Plus Form + 响应式布局
- 技术结论: Spring Boot + BCrypt 密码加密 + Vue 3
```

**锚点作用**：
- **导航记忆**: 首次领取或恢复 Feature 时回读原始章节
- **冲突检测**: 原文与锚点冲突时触发 change-impact-analysis
- **上下文恢复**: 压缩、换 runtime、换设备、交接时的恢复点

**使用时机**：
- 首次领取 Feature
- 继续一个 `[~]` Feature
- 新 runtime/换设备恢复
- 上下文压缩后
- 任何可能改变范围的编码前

**复核输出**：
```markdown
来源复核: docs/prd.md#用户注册 -> 锚点一致
来源复核: docs/ui-design.md#注册页面 -> 已发现变化（增加了手机号字段）
```

<Aside type="caution">
若原文与锚点、TODO 或代码事实冲突，先停止生产编辑，调用 `change-impact-analysis` 定向复核并更新 TODO，再继续。
</Aside>

### 轻量上下文与项目记忆

**项目记忆文件**：
- 统一使用根目录 `PROJECT-MEMORY.md`
- 已有 `docs/PROJECT-MEMORY.md` 或 `docs/project-memory.md` 时沿用
- 是稳定事实与复用地图的唯一入口，不是任务状态源

**禁止生成**：
- 日常流程不生成或持续追加大型 `context.json`、`context.jsonb`
- 不生成 Context/Evidence/Execution 日志
- WorkflowContext 只在当前执行上下文中按需组装

**使用规则**：
- 启动、首次领取、续作、换 runtime 或上下文压缩恢复时，先读取记忆文件的 `Quick facts`、`Reuse map`、`Boundaries`
- 再按当前 Feature 定向读取相关章节
- 不得将全文注入提示词
- 收口时仅把已验证、会被后续 Feature 复用的公共 Owner、组件、工具、契约和禁止重复实现边界原位写入 `Reuse map`

### PreToolUse 门禁

Runtime `PreToolUse` 在状态机推进到 `business-development` 且当前实例原子领取 Feature 前，只允许：
- ✅ 读取仓库
- ✅ 原子推进状态
- ✅ 写入规划文档

**拒绝操作**：
- ❌ 对生产文件的 `Write`
- ❌ 对生产文件的 `Edit`
- ❌ `apply_patch`
- ❌ 等价 Shell 写入（`echo >`, `cat >`, `sed -i`, `awk` 等）

**拒绝消息示例**：
```
❌ 阻止写入生产代码

当前阶段: technical-plan
当前阶段状态: in-progress

不允许在 business-development 之前编辑生产代码。

请先完成:
1. technical-plan: 技术方案设计
2. technical-confirmation: 技术方案确认
3. task-breakdown: 任务拆分生成 TODO

然后推进到 business-development 阶段。
```

## 最佳实践

### 1. 必须先建立状态机

```markdown
<!-- 错误: 直接开始产品定义 -->
用户: 做一个用户管理系统
→ 直接调用 product-manager

<!-- 正确: 先建立状态机 -->
用户: 做一个用户管理系统
→ task-todo-workflow: --plan-start
→ 推进到 requirements-analysis
→ 调用 product-manager
```

### 2. 确认阶段必须等待用户

```bash
# 错误: 直接推进
--plan-advance --stage requirements-confirmation --next-stage technical-plan

# 正确: 先等待
--plan-await --stage requirements-confirmation --result "等待用户确认"

# 用户确认后再推进
--plan-advance --stage requirements-confirmation --next-stage technical-plan --confirmed
```

### 3. 不适用阶段必须说明原因

```bash
# 错误: 静默跳过
--plan-advance --stage code-generation --next-stage business-development

# 正确: 说明原因
--plan-advance \
  --stage code-generation \
  --next-stage business-development \
  --artifact "不适用：项目采用手写代码，无代码生成器" \
  --result "跳过代码生成"
```

### 4. 来源锚点必须完整

```markdown
<!-- 错误: 只有文件名 -->
来源锚点: prd.md

<!-- 正确: 完整锚点 -->
来源锚点:
- 来源文档: `docs/prd.md#用户注册`
- 用户结果: 用户可以通过邮箱注册
- 范围边界: 邮箱+密码注册，不支持第三方
- 技术结论: Spring Boot + BCrypt
```

### 5. 每个开发者只维护一份 TODO

```markdown
<!-- 错误: 多份 TODO -->
docs/alice-chen/tasks/todo/user-system.md
docs/alice-chen/tasks/todo/order-system.md

<!-- 正确: 唯一 TODO -->
docs/alice-chen/tasks/todo/all-features.md
  - Epic: 用户管理
  - Epic: 订单管理
```

## 故障排查

### 问题 1: PreToolUse 拦截了合法操作

**症状**: 规划文档也被拦截

**原因**: 文档路径在生产代码目录内

**解决方案**:
- 规划文档放在 `docs/` 目录
- 或使用 `--artifact` 参数记录路径

### 问题 2: 阶段推进失败

**症状**: --plan-advance 报错

**原因**: 阶段名称错误或顺序不对

**解决方案**:
- 检查当前阶段名称
- 确保 next-stage 是固定顺序中的下一阶段
- 查看 todo-continuation.cjs 日志

### 问题 3: 找不到 TODO 文件

**症状**: 系统提示找不到 TODO

**原因**: 开发者身份未解析

**解决方案**:
```bash
# 检查 Git 身份
git config --get user.name

# 或设置环境变量
export AGENT_DEVELOPER_NAME=alice-chen
```
