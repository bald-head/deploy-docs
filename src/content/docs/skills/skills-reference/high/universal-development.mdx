## 概述

`universal-development` 是 **Low 优先级** Skill，作为最低优先级兜底，仅在没有适用专业 Skill 时使用。

**适用场景**：
- 完整 Skill 清单扫描后无适用专业 Skill
- 最小代码路径修复
- 工具类、辅助函数等边缘场景

**不适用场景**：
- API 开发 → 使用 `api-development`
- 数据库设计 → 使用 `database-design`
- 前端页面 → 使用 `ui-pc` 或 `ui-app`
- 安全认证 → 使用 `security-guard`
- 任何有专业 Skill 的场景

<Aside type="caution">
这是最低优先级 fallback，只要有任何适用的专业 Skill 或 `dev`，都不应选择本 Skill。
</Aside>

## 快速开始

### 使用 universal-development 的决策树

```bash
# 1. 检查是否有专业 Skill
是否是 API 开发？ → 使用 api-development
是否是数据库？ → 使用 database-design/database-ops
是否是前端页面？ → 使用 ui-pc/ui-app
是否是 CRUD？ → 使用 crud-development
是否是认证/权限？ → 使用 security-guard

# 2. 检查是否有通用 Skill
是否是通用业务功能？ → 使用 dev

# 3. 都没有？
→ 使用 universal-development
```

## 使用示例

### 场景 1：修复工具类 Bug

**问题**：
```java
// StringUtils.java 存在 NPE
public static boolean isEmpty(String str) {
    return str.length() == 0;  // 当 str 为 null 时抛出 NPE
}
```

**修复**：
```java
// src/main/java/utils/StringUtils.java
public static boolean isEmpty(String str) {
    return str == null || str.length() == 0;
}

// 或使用标准库
public static boolean isEmpty(String str) {
    return str == null || str.isEmpty();
}
```

**验证**：
```bash
# 运行单元测试
mvn test -Dtest=StringUtilsTest

# 或手工测试
StringUtils.isEmpty(null);     // → true
StringUtils.isEmpty("");       // → true
StringUtils.isEmpty("test");   // → false
```

### 场景 2：添加工具方法

**需求**：
```
添加一个格式化金额的工具方法
```

**实现**：
```java
// src/main/java/utils/MoneyUtils.java
public class MoneyUtils {
    
    /**
     * 格式化金额为千分位显示
     * @param amount 金额（分）
     * @return 格式化后的字符串，例如: "1,234.56"
     */
    public static String formatAmount(Long amount) {
        if (amount == null) {
            return "0.00";
        }
        BigDecimal yuan = new BigDecimal(amount).divide(new BigDecimal(100), 2, RoundingMode.HALF_UP);
        DecimalFormat formatter = new DecimalFormat("#,##0.00");
        return formatter.format(yuan);
    }
}
```

**验证**：
```java
MoneyUtils.formatAmount(123456L);  // → "1,234.56"
MoneyUtils.formatAmount(100L);     // → "1.00"
MoneyUtils.formatAmount(null);     // → "0.00"
```

### 场景 4：简单 Bug 修复

**问题**：
```java
// 订单号生成重复
public String generateOrderNo() {
    return "ORD" + System.currentTimeMillis();  // 并发时可能重复
}
```

**修复**：
```java
// src/main/java/service/OrderService.java
private final AtomicLong sequence = new AtomicLong(0);

public String generateOrderNo() {
    long timestamp = System.currentTimeMillis();
    long seq = sequence.incrementAndGet() % 10000;
    return String.format("ORD%d%04d", timestamp, seq);
}
```

**验证**：
```java
// 并发测试
Set<String> orderNos = ConcurrentHashMap.newKeySet();
IntStream.range(0, 10000).parallel().forEach(i -> {
    String orderNo = orderService.generateOrderNo();
    orderNos.add(orderNo);
});

// 验证无重复
assertEquals(10000, orderNos.size());
```

## 关键规则

### 1. 最低优先级

```text
优先级顺序:
专业 Skill (api-development, database-design, ui-pc...)
  ↓
通用 Skill (dev, crud-development)
  ↓
universal-development (最后的兜底)
```

### 2. 最小改动原则

```java
// 正确: 最小改动
public static boolean isEmpty(String str) {
    return str == null || str.length() == 0;  // 只修复 NPE
}

// 错误: 过度重构
public static boolean isEmpty(String str) {
    // 重构整个工具类
    // 修改其他方法
    // 添加新功能
}
```

### 3. 不替代专业能力

```markdown
<!-- 错误: 越界 -->
发现需要修改 API 契约
→ 不能在 universal-development 中继续
→ 必须重新路由到 api-development

<!-- 错误: 越界 -->
发现需要修改数据库表
→ 不能在 universal-development 中继续
→ 必须重新路由到 database-design
```

### 4. 保护现有改动

```bash
# 编辑前检查
git status

# 发现文件已有改动
M src/main/java/utils/StringUtils.java

# 必须保护已有改动
1. 记录初始状态
2. 只修改当前任务相关的部分
3. 不覆盖、不夹带其他改动
```

## 执行顺序

### 完整执行流程

```bash
# 1. 确认无专业 Skill
扫描完整 Skill 清单
→ 确认没有更适用的专业 Skill

# 2. 发现项目结构
查看包清单、构建配置
→ 确认语言、框架、模块边界

# 3. 建立任务基线
记录 git status
记录目标文件初始状态
→ 保护已有改动

# 4. 搜索相邻实现
查找相同功能、相邻代码
→ 避免重复开发

# 5. 最小实现
遵循相邻代码风格
保持最小变更
→ 不做无关重构

# 6. 验证
运行已有检查
→ formatter、编译、构建

# 7. Review
/code-review
```

## 与其他 Skill 的关系

### 选择决策

```text
有专业 Skill → 使用专业 Skill
有通用 Skill → 使用 dev 或 crud-development
都没有 → 使用 universal-development
```

### 路由规则

```text
实施中发现专业路径 → 立即重新路由

例子:
- 发现 API 路径 → 路由 api-development
- 发现数据库路径 → 路由 database-design
- 发现前端路径 → 路由 ui-pc
- 发现安全路径 → 路由 security-guard
```

### Related Skills

**专业替代**:
- `api-development` - API 开发
- `database-design` - 数据库设计
- `ui-pc` - PC 端界面
- `security-guard` - 安全防护

**通用替代**:
- `dev` - 通用功能开发
- `crud-development` - CRUD 开发
