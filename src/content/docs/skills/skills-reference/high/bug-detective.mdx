## 概述

`bug-detective` 是 **High 优先级** Skill，负责用证据排查调用链故障。

**适用场景**：
- 页面/接口无响应
- 出现错误或异常
- 数据不一致
- 功能不正常工作
- 定位根因

**不适用场景**：
- 代码实现 → 使用 `universal-development`
- 产品定义 → 使用 `product-manager`
- 架构设计 → 使用 `architecture-design`
- 性能优化 → 使用 `performance-doctor`

## 快速开始

### Bug 诊断的完整流程

```bash
# 1. 描述故障现象
"登录接口返回 500 错误"
"用户列表页面空白"

"点击登录按钮"

# 3. 开始诊断
/bug-detective

# 4. 查看日志
tail -f logs/application.log

# 5. 定位根因
# 分析调用链、堆栈、数据

# 6. 修复 Bug
# 修改代码后验证
```

## 使用示例

### 场景 1：登录接口 500 错误

**故障现象**：
```bash
# 请求
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "123456"
  }'

# 响应
HTTP/1.1 500 Internal Server Error
{
  "code": 500,
  "message": "Internal Server Error"
}
```

**诊断步骤**：

1. **查看后端日志**：
```bash
tail -f logs/application.log

# 发现异常堆栈
2026-09-03 10:30:15 ERROR [http-nio-8080-exec-1] c.e.controller.AuthController - 登录失败
java.lang.NullPointerException: Cannot invoke "String.equals(Object)" because "user.getPassword()" is null
    at com.example.service.AuthService.login(AuthService.java:45)
    at com.example.controller.AuthController.login(AuthController.java:23)
    ...
```

2. **定位代码位置**：
```java
// AuthService.java:45
public LoginResponse login(LoginRequest request) {
    UserEntity user = userMapper.selectByEmail(request.getEmail());
    
    // 问题: user 或 user.getPassword() 为 null
    if (user.getPassword().equals(request.getPassword())) {  // ← NPE
        // ...
    }
}
```

3. **分析根因**：
```markdown
根因: 空指针异常

可能原因:
1. user 为 null（用户不存在）
2. user.getPassword() 为 null（密码字段为空）

验证:
- 检查数据库: SELECT * FROM users WHERE email = 'test@example.com'
- 发现: 用户存在，但 password 字段为 NULL
```

4. **定位根因**：
```sql
-- 查询数据
SELECT id, email, password FROM users WHERE email = 'test@example.com';
-- 结果: password 字段为 NULL

-- 检查数据插入
-- 发现注册时未加密密码，导致 password 字段为 NULL
```

5. **修复方案**：
```java
// 修复前
if (user.getPassword().equals(request.getPassword())) {

// 修复后
if (user == null) {
    throw new BusinessException(ErrorCode.USER_NOT_FOUND, "用户不存在");
}
if (user.getPassword() == null) {
    throw new BusinessException(ErrorCode.PASSWORD_INVALID, "密码未设置");
}
if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
    throw new BusinessException(ErrorCode.PASSWORD_INVALID, "密码错误");
}
```

### 场景 2：用户列表页面空白

**故障现象**：
```bash
# 访问用户列表页面
http://localhost:5173/user/list

# 页面显示空白
# 浏览器控制台报错
Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'map')
    at UserList.vue:45
```

**诊断步骤**：

1. **查看浏览器控制台**：
```javascript
// UserList.vue:45
const userList = computed(() => {
    return users.value.map(user => ({  // ← users.value 为 undefined
        id: user.id,
        name: user.name
    }));
});
```

2. **检查 API 调用**：
```javascript
// 查看 Network 面板
GET /api/v1/users
Status: 200 OK

Response:
{
  "code": 200,
  "message": "success",
  "data": null  // ← data 为 null
}
```

3. **定位根因**：
```java
// 后端代码
@GetMapping
public Result<List<UserVO>> list() {
    List<UserVO> users = userService.list();
    return Result.ok(users);  // users 为 null
}

// UserService.java
public List<UserVO> list() {
    List<UserEntity> entities = userMapper.selectList(null);
    // 问题: 当列表为空时返回 null 而不是空列表
    if (entities == null || entities.isEmpty()) {
        return null;  // ← 返回 null
    }
    return entities.stream()
        .map(this::convertToVO)
        .collect(Collectors.toList());
}
```

4. **修复方案**：
```java
// 修复后端
public List<UserVO> list() {
    List<UserEntity> entities = userMapper.selectList(null);
    if (entities == null || entities.isEmpty()) {
        return Collections.emptyList();  // ← 返回空列表
    }
    return entities.stream()
        .map(this::convertToVO)
        .collect(Collectors.toList());
}

// 修复前端
const users = ref([]);  // 初始化为空数组

const loadUsers = async () => {
    const res = await userApi.list();
    users.value = res.data || [];  // 处理 null 情况
};
```

### 场景 3：订单状态更新失败

**故障现象**：
```bash
# 更新订单状态
curl -X PUT http://localhost:8080/api/v1/orders/123/status \
  -d '{"status": "PAID"}'

# 响应成功
{
  "code": 200,
  "message": "success"
}

# 但查询订单状态仍是旧值
curl http://localhost:8080/api/v1/orders/123
{
  "id": 123,
  "status": "PENDING"  # ← 状态未更新
}
```

**诊断步骤**：

1. **检查更新代码**：
```java
@PutMapping("/{id}/status")
public Result<Void> updateStatus(@PathVariable Long id, @RequestBody UpdateStatusRequest request) {
    orderService.updateStatus(id, request.getStatus());
    return Result.ok();
}

public void updateStatus(Long id, String status) {
    OrderEntity order = orderMapper.selectById(id);
    order.setStatus(status);
    // 问题: 只修改了对象，没有保存到数据库
    // 缺少: orderMapper.updateById(order);
}
```

2. **验证数据库**：
```sql
-- 查询数据库
SELECT id, status FROM orders WHERE id = 123;
-- 结果: status 仍是 PENDING

-- 验证更新语句未执行
-- 检查数据库日志，没有 UPDATE 语句
```

3. **定位根因**：
```markdown
根因: 只修改了内存对象，未持久化到数据库

原因: 缺少 updateById() 调用
```

4. **修复方案**：
```java
// 修复后
public void updateStatus(Long id, String status) {
    OrderEntity order = orderMapper.selectById(id);
    order.setStatus(status);
    orderMapper.updateById(order);  // ← 添加保存操作
}
```

### 场景 4：数据查询不一致

**故障现象**：
```bash
# 管理员查询所有订单
curl http://localhost:8080/api/v1/orders?userId=admin
# 返回: 10 条订单

# 用户 A 查询自己的订单
curl http://localhost:8080/api/v1/orders?userId=1
# 返回: 10 条订单（包含其他用户的订单）← 问题
```

**诊断步骤**：

1. **检查查询代码**：
```java
@GetMapping
public Result<List<OrderVO>> list(OrderQuery query) {
    List<OrderVO> orders = orderService.list(query);
    return Result.ok(orders);
}

public List<OrderVO> list(OrderQuery query) {
    QueryWrapper<OrderEntity> wrapper = new QueryWrapper<>();
    // 问题: 没有根据当前用户过滤
    // 缺少: wrapper.eq("user_id", getCurrentUserId());
    return orderMapper.selectList(wrapper);
}
```

2. **验证 SQL**：
```sql
-- 实际执行的 SQL
SELECT * FROM orders;  # ← 没有 WHERE 条件

-- 应该执行的 SQL
SELECT * FROM orders WHERE user_id = 1;
```

3. **定位根因**：
```markdown
根因: 查询缺少用户权限过滤

原因: 未添加当前用户 ID 作为查询条件
安全风险: 数据泄露
```

4. **修复方案**：
```java
// 修复后
public List<OrderVO> list(OrderQuery query) {
    QueryWrapper<OrderEntity> wrapper = new QueryWrapper<>();
    
    // 添加权限过滤
    Long currentUserId = getCurrentUserId();
    if (!isAdmin(currentUserId)) {
        wrapper.eq("user_id", currentUserId);  // ← 添加过滤
    }
    
    return orderMapper.selectList(wrapper)
        .stream()
        .map(this::convertToVO)
        .collect(Collectors.toList());
}
```

## 关键规则

### 1. 先证明再解释

```markdown
<!-- 正确: 先证据后结论 -->
证据: NPE at AuthService.java:45
证据: user.getPassword() 为 null
证据: 数据库 password 字段为 NULL
结论: 注册时未加密密码导致字段为空

<!-- 错误: 只有猜测 -->
可能是密码加密的问题
```

### 2. 复现优先

```bash
# 正确: 最小复现
1. 访问 /api/v1/auth/login
2. 输入 test@example.com / 123456
3. 点击登录
4. 出现 500 错误 ✓

# 错误: 无法复现就猜测
"可能是网络问题"
"可能是缓存问题"
```

### 3. 只读诊断

```markdown
诊断阶段只能:
- ✅ 查看日志
- ✅ 查询数据库（只读）
- ✅ 查看代码
- ✅ 分析堆栈

诊断阶段不能:
- ❌ 修改代码
- ❌ 修改数据库
- ❌ 重启服务
- ❌ 安装依赖
```

### 4. 保护敏感信息

```bash
# 正确: 脱敏
Token: eyJhbG******（已脱敏）
Password: ******（已脱敏）
Connection: jdbc:mysql://localhost:3306/db（已脱敏密码）

# 错误: 泄露敏感信息
Token: eyJhbGciOiJIUzI1NiIs...（完整 Token）
Password: 123456（明文密码）
```
