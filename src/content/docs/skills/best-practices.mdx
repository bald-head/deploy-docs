## 把任务说到可以核对

提供目标仓库、要达成的结果、已知现象和约束。技术选型已有结论时直接引用；没有结论时让 Agent 从项目事实比较方案，不把教程中的技术栈当默认值。

```text
在当前项目修复订单导出：选择本月后，导出内容仍包含上月数据。
入口是订单列表的导出按钮。请复现并沿筛选参数到查询的链路定位，
保持现有导出格式和权限规则，说明修复及验证结果。
```

新功能需要必要规划，已批准 TODO、明确 Bug 和普通维护按现有边界推进。只有仍有会改变用户结果的未决决定时才澄清，避免反复询问仓库中能查到的事实。

## 区分容易混淆的任务

| 请求 | 合适入口 |
| --- | --- |
| 继续当前已批准 TODO | `next` 与适用实现 Skill |
| 读取 Claude Code 或 Codex 历史后继续 | `resume-claude` 或 `resume-codex`，按历史来源 |
| 调整已有页面布局、交互或状态 | `frontend-polish` |
| 定位接口或页面加载耗时 | `performance-doctor` |
| 催促加快开发 | 调整实施与验证节奏，不触发性能诊断 |
| 查项目已有工具 API | `utils-toolkit` |
| 设计测试方案或用例 | 本轮明确要求后使用 `test-strategy` |
| 写或修改测试源码 | 本轮明确要求后使用 `test-development` |
| 创建 Skill 内容 | `skill-creator` |
| 把已有 Skill 接入客户端 | `add-skill` |

## 一个功能覆盖完整交付面

数据、契约、后端、实际页面或调用方、权限和异常恢复属于同一个功能。存在页面入口的功能应接通真实接口，并呈现加载、空、错和成功状态。

新增表同时使用 `database-design` 与 `database-ops`。需要扩展公共组件或契约时，先核对现有 Owner 和直接消费者；职责一致时复用，不能只凭名称相似抽出公共层。

轻量化减少重复文书与检查次数，不减少真实交付面。技术结论已经具名且适用时直接复用，不为每次续作重新选型。

## 让验证对应结果

默认复用现有检查和适用的真实主路径；本轮没有测试源码授权时，不因覆盖率、Review finding 或 CI 门禁新增测试文件。

| 已有证据 | 可以报告 |
| --- | --- |
| 构建通过 | 当前构建根通过，不能据此声称业务验收完成 |
| 接口返回正确 | 已覆盖的请求与响应正确，不能据此声称页面已接通 |
| 页面实际完成操作并核对响应 | 对应入口和流程已经验证 |
| 设备、外部服务或发布未执行 | 明确未验证内容和继续条件 |

完整 diff 做一次缺陷优先 Review。修复 findings 后只复核相关问题与受影响路径，不让多个 Skill 反复做同一份完整审查。

## 保持任务和项目记忆各自清楚

当前开发者唯一 TODO 保存功能、依赖、验收、写集和状态。身份优先来自该仓库 Git `user.name`，然后是系统用户名，最后才读取显式 `AGENT_DEVELOPER_NAME`；不把示例用户名设成团队默认值。

稳定项目事实与复用入口写入唯一 `PROJECT-MEMORY.md`。不要保存整段会话、每个 Feature 的记忆副本或第二份进度文件。

历史会话的旧验证和助手结论只作核对线索。读取成功后仍以当前源码、Git 状态、记忆和 TODO 判断是否需要继续；只读总结不转为实现。

## 并行前核对依赖与资源

同一 Feature 只能由一个 runtime 实例领取，一个实例同时只能有一个进行中项。并行需要全部依赖已经进入核验过的远端功能提交，写集互斥，且没有共享迁移、配置、契约、端口或账号资源。

共享 checkout 中由主 Agent 串行处理 TODO 状态和 Git index/ref。子 Agent 负责自己的互斥实现范围并交回结果，不能同时暂存或提交。发生冲突时先收拢所有权，再继续编辑。

## 明确持续开发与 Git 范围

需要逐功能交付并继续时，可以这样说明：

```text
按已批准 TODO 持续开发。每个完整 Feature 验证与 Review 通过后，
把业务改动、必要文档和 TODO 完成状态同次 commit & push 到已配置 upstream。
远端核验成功后继续下一 Ready 项；真实阻塞或需要我决定时说明恢复条件。
```

普通开发请求不自动增加提交、推送或部署授权；同一范围内已有授权继续有效。Hook 提供状态检查和续作提示，实际 Git 操作由 Agent 执行。

TODO 的完成状态必须随功能提交，不能先交付业务代码、再补一份状态提交。本地 `[x]` 尚未推送时，不提前解锁下游依赖。

更多操作见[使用指南](/skills/usage/)、[TODO 管理](/skills/usage/todo-management/)和[故障排查](/skills/troubleshooting/)。
