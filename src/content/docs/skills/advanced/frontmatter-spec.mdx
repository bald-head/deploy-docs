每个 Skill 的 `SKILL.md` 以 YAML frontmatter 开始。当前 Harness 使用 `name`、`description` 和可读路径发现 Skill，正文与引用资源在命中后按需读取。

`triggers`、`gates`、`conflicts` 等字段是本仓库的语义约定，帮助维护者和 Agent 理解职责；它们不是所有客户端都会执行的路由协议。运行机制见 [Skill 发现与选择](/skills/core-concepts/routing/)。

## 最小发现字段

```yaml
---
name: resume-claude
description: >
  读取并接续 Claude Code 历史会话，支持会话 ID、日志路径、描述或当前目录最近会话。
  只读总结不改代码，单纯继续当前 TODO 不触发。
---
```

这是 `resume-claude` 发现信息的节选，完整内容以源仓库对应 `SKILL.md` 为准。

| 字段 | 要求 |
| --- | --- |
| `name` | 与目录名一致，使用小写字母、数字和连字符组成的 kebab-case；同一源目录内不得重复 |
| `description` | 非空，独立说明做什么、何时用和最关键的排除边界；当前目录 validator 限制为 1024 字符以内 |

客户端可能有其他格式限制，注册时同时核对实际客户端规则。不要把“必须 2 至 3 个单词”或固定中文字数当作本仓库的验证条件。

## 本仓库的扩展字段

下面的例子继续使用同一个 Skill，展示可按真实职责补充的字段：

```yaml
category: special
tags: [session, claude, handoff]
priority: medium
triggers:
  zh:
    - 读取 Claude Code 会话
    - 继续 Claude 会话
  en: [resume my Claude session, read a Claude Code session]
gates:
  - "本轮明确指定 Claude Code 为历史来源，或显式调用 resume-claude"
conflicts:
  resume-codex: "按历史来源选择；当前使用的客户端不决定历史来源"
  next: "只继续当前 TODO 时使用 next，不自动读取另一段历史"
not_for:
  - "恢复旧进程、登录会话或运行中命令"
related_skills:
  after: [next, dev]
  complement: [project-details]
  alternative: [resume-codex]
```

| 字段 | 用途 | 维护要点 |
| --- | --- | --- |
| `category`、`tags` | 组织能力与检索主题 | 沿用已有类别，按实际职责填写 |
| `priority` | 本仓库的优先级声明与文档分组 | 当前目录使用 `critical`、`high`、`medium`、`low`；不等于客户端固定评分或抢占保证 |
| `triggers` | 常见请求表达 | 带上任务对象和动作，不靠堆同义词补救模糊职责 |
| `gates` | 适用前提 | 使用能从请求、仓库或现有产物核对的条件 |
| `conflicts` | 相邻 Skill 的职责边界 | 写明选择依据，不能只列“相关 Skill” |
| `not_for` | 排除场景与替代入口 | 指向实际存在且职责适用的能力 |
| `related_skills` | 前置、后续、协作与替代关系 | 引用存在的 Skill；关系声明本身不自动执行后续任务 |

YAML 的多行列表与行内数组都可以表示 `triggers.zh`、`triggers.en` 等列表。它们只是序列的两种写法，没有固定条目数或不同的路由增益。

`related_skills.before` 表示通常的前置协作，`after` 表示可能的后续工作，`complement` 表示配合能力，`alternative` 表示替代入口。实际执行仍取决于当前任务、已批准范围和授权。

## 描述与边界怎么写

关键限制要出现在 `description` 中，不能只藏在很后面的正文里。

| 容易引起歧义的描述 | 更准确的写法 |
| --- | --- |
| 优化性能，让开发更快 | 按运行指标排查接口、SQL、页面加载、CPU 和内存性能；催促开发进度不触发 |
| 测试覆盖与测试用例 | 仅在本轮明确要求写、补或修改测试源码时实施测试；运行已有检查不触发 |
| 继续上次任务 | 读取并接续明确来源的历史会话；当前 TODO 续作不读取其他会话 |
| 提供常用工具 | 从目标仓库、标准库和已有依赖查找可复用 API；不负责通用软件推荐 |

`gates` 需要描述事实，例如“目标是客户端共享状态，并已定位现有 Store”，而不是“用户需要帮助”。`conflicts` 则回答在相邻能力之间如何选择，例如 `store-pc` 处理客户端状态，后端持久化交给 `database-ops`。

## 客户端专有字段与调用

| 客户端 | 显式调用 | 专有控制 |
| --- | --- | --- |
| Claude Code | `/skill-name` | `disable-model-invocation: true` 可让显式工作流不进入模型常驻清单 |
| Codex | `$skill-name`；`/skills` 用于浏览 | `agents/openai.yaml` 中的 `policy.allow_implicit_invocation: false` 控制隐式调用 |

这些配置不能互相套用。Codex 的 `agents/openai.yaml` 不替代 `SKILL.md`，也不是 Claude Code 的配置文件。各自发现目录和注册方式见[安装与配置](/skills/getting-started/)。

## 维护与验证

创建或更新 Skill 内容时，先按 [`skill-creator`](/skills/skills-reference/medium/skill-creator/) 或 [`skill-optimizer`](/skills/skills-reference/medium/skill-optimizer/) 处理。每个 Skill 是独立分发单元，安装后必读的脚本、规则和资源必须随本目录分发，不能依赖兄弟 Skill 的相对路径。

1. 核对 YAML、目录名、描述和直接引用资源。
2. 与真实重叠的相邻 Skill 做一次语义 Review，检查正向请求、排除场景和授权边界。
3. frontmatter、description 或清单变化时，按 `add-skill` 流程在 Skill 源仓库执行一次索引同步：

```bash
node add-skill/scripts/validate-skill-catalog.mjs --write
```

目录 validator 会先确保 Runtime Hook 和当前 CLI 的远端 Penpot MCP 接入，因此它不是纯只读校验。只修改文档站或普通 Skill 正文时，不因此运行注册流程。需要把 Skill 接入指定客户端时，使用[安装与配置](/skills/getting-started/)中的完整命令。

高碰撞职责变化可以更新已有行为场景；目录和静态语义检查不能证明真实效果。评测输入、命令和结论边界见[评估与验证边界](/skills/advanced/performance-metrics/)。
