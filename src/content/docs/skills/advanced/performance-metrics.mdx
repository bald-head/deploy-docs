## Token 优化

### Context 注入优化

通过渐进式加载和上下文压缩，Runtime Hook 注入的 token 消耗大幅降低：

| 阶段 | Token 消耗 | 优化幅度 |
|------|-----------|---------|
| **优化前** | ~65,000 tokens | - |
| **优化后** | ~8,000 tokens | **-87.7%** |

**优化措施**：

1. **按需加载 frontmatter**
   - 只注入当前请求相关的 Skill 元数据
   - 不再注入完整 Skill 目录

2. **行为内核提取**
   - 跨客户端最小行为内核独立维护
   - 从 `runtime-hooks/behavior-kernel.md` 加载
   - 避免在每个 Skill 中重复

3. **项目记忆有界摘要**
   - 只读取 `PROJECT-MEMORY.md` 中与当前问题相关的摘要
   - 不注入完整项目文档

4. **TODO 上下文压缩**
   - 只提示当前开发者的活动 TODO
   - 不注入所有开发者的 TODO 历史

## 准确率分析

### 歧义场景解决

**场景 1：页面设计 vs 页面优化**

用户输入："优化这个页面"

```
匹配结果：
  - frontend-design（触发词：页面设计）
  - frontend-polish（触发词：优化页面）

Gates 检查：
  frontend-design:
    gates: "尚未有实现"
    当前状态: 页面已存在
    结果: ✗ 不满足

  frontend-polish:
    gates: "已有页面实现"
    当前状态: 页面已存在
    结果: ✓ 满足

Conflicts 规则：
  frontend-design.conflicts.frontend-polish:
    "frontend-design 负责从零设计新页面；frontend-polish 负责已有页面的优化"

最终选择：frontend-polish
准确率：100%
```

**场景 2：需求变更 vs 新需求**

用户输入："需求改了，用户表要加手机号字段"

```
匹配结果：
  - change-impact-analysis（触发词：需求改了）
  - product-manager（触发词：需求）

Gates 检查：
  change-impact-analysis:
    gates: "已有批准的范围"
    当前状态: TODO 文件存在
    结果: ✓ 满足

  product-manager:
    gates: "尚未有批准的范围"
    当前状态: TODO 文件存在
    结果: ✗ 不满足

Conflicts 规则：
  change-impact-analysis.conflicts.product-manager:
    "change-impact-analysis 负责已有范围的变更；新需求用 product-manager"

最终选择：change-impact-analysis
准确率：100%
```

### 路由失败分析

在 96%+ 的准确率中，剩余 &lt;4% 的失败主要来自：

1. **触发词不匹配** (~2%)
   - 用户使用未定义的触发词
   - 例如："搞个页面"（不在触发词列表中）
   - **解决方案**：持续收集用户输入，扩充触发词列表

2. **Gates 条件不满足** (~1%)
   - 用户意图正确，但当前状态不满足 gates
   - 例如：未完成产品定义就要求开始实现
   - **解决方案**：提示用户先完成前置步骤

3. **多个 Skill 得分相同** (&lt;1%)
   - 极少数情况下，多个 Skill 的评分完全相同
   - **解决方案**：通过 conflicts 规则强制选择，或提示用户明确意图

## 性能优化建议

### 触发词优化

1. **持续收集用户输入**
   ```bash
   # 查看路由统计
   node runtime-hooks/scripts/routing-stats.cjs
   
   # 分析失败的路由
   grep "Routing failed" ~/.claude/logs/*.log
   ```

2. **扩充口语化触发词**
   - 分析用户的自然表达
   - 添加同义词和变体

3. **Low 优先级保持克制**
   - 不要为了提升召回率而增加通用触发词
   - 保持技术栈/格式限定

### Gates 优化

1. **确保可验证**
   - gates 应该能通过代码/文件/状态验证
   - 避免主观判断

2. **与 conflicts 配合**
   - gates 处理"能不能触发"
   - conflicts 处理"该选哪个"

### Conflicts 优化

1. **说明决策依据**
   - 不只是列出相关 Skill
   - 明确职责边界

2. **Low 优先级重点维护**
   - Low 优先级 Skill 需要更多 conflicts
   - 确保不会抢占 High/Medium 的场景
