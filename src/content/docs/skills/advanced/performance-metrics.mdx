Skill 数量、触发词数量和元数据覆盖率只能描述目录。它们不能证明 Agent 选择正确，也不能证明任务完成得更好。旧文档中的准确率、固定路由耗时和 Token 降幅没有对应的真实运行证据，不作为当前效果结论。

## 每种检查能证明什么

| 检查 | 可得结论 | 不能据此推断 |
| --- | --- | --- |
| 目录与 frontmatter 校验 | 名称、描述、索引和引用满足当前检查规则 | 客户端实际调用成功、任务完成率 |
| Hook 安装状态 | 本地托管配置是否安装、是否需要更新 | 客户端已信任 Hook、事件已经执行 |
| 上下文预算检查 | 本次上下文生成与字节预算结果 | 所有模型的 Token 用量和实际请求延迟 |
| 场景契约检查 | 评测场景及其 Skill 引用有效 | 真实路由准确率、行为稳定性 |
| 静态配对 Review | 相同请求下的职责和边界更清楚 | 在目标 Harness 中实际产生了增益 |
| 目标 Harness 的真实 observation | 指定场景中的选择、交接、停止与任务结果 | 未覆盖客户端、任务或环境的效果 |

验证一次 Skill 修改时，先根据变更选择所需证据，不把所有检查重复跑一遍。普通文案修改以差异、直接引用和一次 Review 为主。

## 检查场景契约

在 Skill 源仓库根目录执行：

```bash
node evals/route-eval.mjs
```

没有提供 observation 时，成功结果中的 `behaviorEvaluated` 仍是 `false`：

```text
ok: true
contracts: 以本次输出为准
behaviorEvaluated: false
```

它表示 `evals/route-scenarios.json` 的结构和引用有效。该文件是评测契约，不是客户端的运行时路由表。

## 采集真实行为

要比较修改前后或启用与未启用 Skill 的效果，先用目标 Harness 独立执行场景，再把观察值写到工作区外或临时目录中的 JSON。不能根据期望答案填充“实际结果”。

观察文件的顶层使用 `schemaVersion: 1` 和 `runs`。每条 run 按源仓库 `evals/README.md` 的契约记录：

| 字段 | 含义 |
| --- | --- |
| `scenarioId`、`runId` | 场景和独立运行标识 |
| `variant` | `with-skill`、`without-skill` 或 `previous` |
| `primaryRoute`、`forbiddenHits` | 最终主路由与禁止命中 |
| `signals`、`handoff` | 实际出现的必需信号和交接 |
| `stopCondition`、`goalCompleted` | 停止条件与目标结果 |
| `contextCharacters` | 非负整数的上下文字符数，不是 Token 数 |
| `initialPrimaryRoute` | 可选；只有能观察首次选择时才记录 |

当前评测器要求每个场景至少有 3 次独立 `with-skill` 运行，并且整份输入至少包含一个 `without-skill` 或 `previous` 基线。比较某个场景的增益时，该场景本身也必须有基线；没有基线的场景只能报告当前表现。

把路径替换成真实观察文件后运行：

```bash
node evals/route-eval.mjs --observations=/absolute/path/to/route-observations.json
```

评测器会检查主路由、禁止命中、必需信号、交接、停止条件和目标结果。独立运行不足、缺失必要基线或结果未满足场景条件时会返回非零退出码；`behaviorEvaluated: true` 本身不代表通过，还要核对 `ok`、`errors` 和各场景结果。

## 解读结果

| 输出 | 如何使用 |
| --- | --- |
| `routeStability` | 选择是否一致；一致地选错也可能稳定，需要同时看期望路由与目标结果 |
| `expectedRouteRate` | 主路由符合场景预期的比例 |
| `goalCompletionRate` | 满足场景要求、交接和目标完成条件的比例 |
| `forbiddenRouteRate` | 命中禁止路由的比例 |
| `routeCorrectionRate` | 有首次路由记录时计算纠偏比例；缺失时为不可计算 |
| `averageContextCharacters` | 该组运行的平均上下文字符数 |
| `delta` | 当前组与该场景基线的差值；没有基线时不提供比较 |

报告结论时带上客户端与版本、Skill 版本、场景范围、重复次数和基线来源。准确率、耗时或成本只能用于实际覆盖的样本，不能推广成框架的固定保证。

## 辅助路由与遥测

源仓库还包含 `skill-router.yaml` 和 `runtime-hooks/scripts/skill-router.cjs`，用于辅助场景候选匹配。它们不自动读取并同步全部 Skill frontmatter；当前辅助路由器的 `checkGates()` 也不执行实际门槛核验。

因此，候选出现次数不是 Skill 实际调用次数，命中率不是正确率，候选匹配耗时也不是完整 Agent 请求耗时。原生发现、辅助提示和真实执行需要分别核对，详见[发现与选择机制](/skills/core-concepts/routing/)。
