这一组共 27 个 Skill，覆盖产品定义、项目事实、设计与技术、纵向实现、质量和 Git。以下顺序便于查阅，不代表每个请求都要依次调用。

## Critical：产品与范围

| Skill | 用途与边界 |
| --- | --- |
| [product-manager](/skills/skills-reference/critical/product-manager/) | 对新项目或新功能完成研究、brainstorm、产品定义与验收 |
| [change-impact-analysis](/skills/skills-reference/critical/change-impact-analysis/) | 当已批准范围真实变化时，完整识别受影响功能、契约、数据、权限和交付面并原位更新 TODO。 |

## High：项目事实与规划

| Skill | 用途与边界 |
| --- | --- |
| [start](/skills/skills-reference/high/start/) | 建立未知仓库的可验证概览，并复用或补齐稳定项目记忆。 |
| [project-details](/skills/skills-reference/high/project-details/) | 维护并自动回读单一项目记忆中的稳定事实、复用地图和边界；不保存任务状态或替代 PRD/架构。 |
| [product-discovery](/skills/skills-reference/high/product-discovery/) | 用用户与市场证据验证产品机会和假设。 |
| [product-strategy](/skills/skills-reference/high/product-strategy/) | 制定产品市场、竞争、商业模式和定价取舍。 |
| [product-execution](/skills/skills-reference/high/product-execution/) | 把已确认的产品方向整理为 PRD、OKR、路线图或发布计划；不负责前置机会验证和完整业务定义。 |
| [frontend-design](/skills/skills-reference/high/frontend-design/) | 为新增或重构界面建立 UI/UX 设计基线，定义页面结构、交互、状态与约束；不编写生产页面代码。 |
| [architecture-design](/skills/skills-reference/high/architecture-design/) | 设计系统、模块、数据所有权、部署和仓库边界。 |
| [tech-decision](/skills/skills-reference/high/tech-decision/) | 在每个业务 Feature 实现前比较可行技术并选出可实施、可验证、可回退的方案。 |
| [project-manager](/skills/skills-reference/high/project-manager/) | 基于完整产品、设计、架构和技术结论，按功能点与菜单/入口建立当前开发者覆盖全部交付面的唯一 TODO。 |
| [task-todo-workflow](/skills/skills-reference/high/task-todo-workflow/) | 直接维护功能+菜单、覆盖全部交付面的当前开发者唯一 TODO |

## High：专业实现与优化

| Skill | 用途与边界 |
| --- | --- |
| [database-design](/skills/skills-reference/high/database-design/) | 设计数据库结构、迁移、索引、幂等、兼容和回滚。 |
| [database-ops](/skills/skills-reference/high/database-ops/) | 实施数据库表、ORM 映射、索引和数据迁移。 |
| [api-development](/skills/skills-reference/high/api-development/) | 设计实现 API 契约、校验、错误语义和文档。 |
| [dev](/skills/skills-reference/high/dev/) | 实施已批准 TODO 的通用纵向功能并统一验证与 Review；明确 CRUD 或专业领域任务优先使用对应 Skill。 |
| [crud-development](/skills/skills-reference/high/crud-development/) | 按已批准需求完成 CRUD 纵向业务交付，覆盖数据模型、API、Service 与页面联动；不开发代码生成器。 |
| [crud](/skills/skills-reference/high/crud/) | 仅在明确调用仓库现有 CRUD 生成器时生成并审查模块；一般 CRUD 业务交付使用 crud-development。 |
| [ui-pc](/skills/skills-reference/high/ui-pc/) | 按已发现的组件库、路由、状态与设计令牌实现 PC/管理端界面 |
| [ui-app](/skills/skills-reference/high/ui-app/) | 按已发现的平台、框架、导航与视觉令牌实现跨端应用界面 |
| [frontend-polish](/skills/skills-reference/high/frontend-polish/) | 审查并优化已有前端实现的布局、交互、视觉与可用性；不从零设计新业务页面。 |
| [security-guard](/skills/skills-reference/high/security-guard/) | 实现授权、输入与数据安全。 |
| [data-permission](/skills/skills-reference/high/data-permission/) | 设计或排查行级、字段级数据权限和租户边界。 |

## High：排查、审查与 Git

| Skill | 用途与边界 |
| --- | --- |
| [bug-detective](/skills/skills-reference/high/bug-detective/) | 用证据排查调用链故障。 |
| [code-review](/skills/skills-reference/high/code-review/) | 对指定 diff 做缺陷优先的完整 Review，并核对验收与交付证据；不代替仓库专项规范检查。 |
| [git-workflow](/skills/skills-reference/high/git-workflow/) | 处理 Git 分支、历史与冲突。 |
| [git-commit](/skills/skills-reference/high/git-commit/) | 经授权精确提交并推送 Git。 |

## 如何选择

新功能先核对事实并完成必要规划，已批准 TODO 直接复用既有结论。明确 CRUD 使用 `crud-development`；只有调用仓库已有 CRUD 生成器时才使用 `crud`。有适用专业 Skill 时优先使用，通用纵向交付由 `dev` 组织。

需要导航源码、查看 TODO、接续历史或管理 Skill 时，查 [Medium 目录](/skills/catalog/medium/)；完整任务步骤见[使用指南](/skills/usage/)。Git 操作按当前有效授权执行。
