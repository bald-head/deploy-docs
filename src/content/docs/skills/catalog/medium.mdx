## 这一层是什么

Medium 优先级的 30 个 Skill 覆盖**具体技术领域**：任务状态维护、基础设施、测试、文档、Skill 自身管理。

和 Critical / High 的区别在于调用方式：

- Critical / High 通常由流程自动串起来（产品定义 → 架构 → 技术选型 → 实施）。
- Medium 更多是**你在流程中途点名调用**的能力，例如"设计一下 Redis 缓存""把这个任务加到 TODO""检查一下后端规范"。

<Aside type="tip">
每个 Skill 的完整说明、触发词、门槛和协作关系在 [Skill 参考手册](/skills/skills-reference/) 里；本页只做速查和选型。
</Aside>

## TODO 与任务状态（4 个）

TODO 是整个框架的唯一状态源。这四个 Skill 分别负责写入、挑选、回写和统计。

| Skill | 什么时候用 | 说明 |
|---|---|---|
| [add-todo](/skills/skills-reference/medium/add-todo/) | "把这个也加进去" | 向唯一 TODO 追加去重、可验收且纵向完整的功能或步骤 |
| [next](/skills/skills-reference/medium/next/) | "接下来做什么" | 按依赖和代码事实挑出下一项可执行的完整功能 |
| [update-status](/skills/skills-reference/medium/update-status/) | 功能做完后 | 按代码、Review 和 Git 事实回写 TODO 状态 |
| [progress](/skills/skills-reference/medium/progress/) | "现在进度多少" | 只读统计功能进度，不改任何状态 |

<Aside type="caution">
这四个 Skill 都只操作**当前开发者唯一的那份 TODO**。不要用它们去改别人目录下的 TODO。
</Aside>

## 常见组合

新增一个带缓存的接口：

```
tech-decision → api-development → redis-cache → error-handler → check → code-review
```

功能做完收口：

```
update-status → git-commit → next
```

线上变慢了：

```
bug-detective → performance-doctor → redis-cache（如涉及缓存）→ code-review
```
