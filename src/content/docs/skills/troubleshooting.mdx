## 快速诊断

| 症状 | 先检查 |
|---|---|
| 没有上下文或 Hook 提示 | [Runtime Hook 问题](#runtime-hook-问题) |
| 找不到某个 Skill | [Skill 发现问题](#skill-发现问题) |
| TODO 路径或状态不符 | [TODO 问题](#todo-问题) |
| 候选 Skill 与任务不符 | [路由问题](#路由问题) |
| 无法领取、完成或续作 | [任务管理问题](#任务管理问题) |
| 项目事实没有加载 | [项目记忆问题](#项目记忆问题) |

文中的 `<skills-root>`、`<repo-root>` 和 `<developer-id>` 均为占位符。脚本从 Skills 仓库读取，TODO 与项目记忆则属于当前目标 Git 仓库，先确认两者没有混用。

## Runtime Hook 问题

### Hook 没生效

先检查本地托管配置：

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs" --check --json
```

通过条件是 `installed: true` 且 `needsInstall: false`。需要更新时，按返回的 `installCommand` 或 [安装与配置](/skills/getting-started/) 处理。Claude Code 要重新启动会话；Codex 通过 `/hooks` 检查并信任新的定义。

检查通过不表示客户端已重新加载，也不代表远端 MCP 已连通。不要在真实工作区执行破坏性命令来验证安装。

### 每次启动都提示更新

核对客户端实际配置目录与安装器检查结果，尤其是 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 和固定的 Node 解释器路径。切换 Node 版本后重新运行安装器；重复发生时可用 `AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0` 暂停自动对齐，保留差异提示用于排查。

### Stop 没有发生

强制退出或客户端崩溃不保证发出 Stop 事件。恢复会话后读取原 TODO、当前实例和 Git 事实，按 [会话接续](/skills/usage/session-resume/) 恢复。不要仅用一句“已完成”或额外状态提交代替完成检查。

<Aside type="note">
`AGENT_RUNTIME_HOOKS_DISABLED=1` 不是总开关：它停用 SessionStart、PreToolUse 和提示音，但上下文与 TODO 脚本仍可能运行。完整事件与配置排查见 [Hook 故障排查](/skills/hooks/troubleshooting/)。
</Aside>

## Skill 发现问题

### 找不到 Skill

先看当前客户端原生提供的 Skill 发现结果，确认 Skill 的 `SKILL.md` 可读、frontmatter 中的 `name` 与 `description` 有值，以及注册目录没有多嵌套一层。

```bash
rg --files "<skills-root>" -g SKILL.md
sed -n '1,35p' "<skills-root>/product-manager/SKILL.md"
```

Skill 数量会随版本和项目级覆盖变化，不能把固定数量作为通过条件。同名 Skill 还要核对实际命中的路径；原生发现根和同步步骤见 [安装与配置](/skills/getting-started/)。

`AGENT_SKILL_DISCOVERY_FALLBACK=1` 是旧客户端兜底，不应在原生发现已经正常时默认开启。目录 validator 的安装与 Penpot 注册核验是同步流程的一部分，普通业务回合无需重复运行。

## TODO 问题

### 路径不符

TODO 规范路径为：

```text
docs/<developer-id>/tasks/todo/<原文件名>.md
```

开发者身份依次来自当前仓库 Git `user.name`、系统登录用户名、最后才是 `AGENT_DEVELOPER_NAME`。身份还会规范化，不能直接把未经处理的显示名拼成目录。

```bash
git rev-parse --show-toplevel
git config --get user.name
whoami
rg --files docs -g '*.md'
```

将实际文件与 Hook 注入的 `<developer_scope>` 对照。身份确实错误时先修正仓库配置；历史落点由 `task-todo-workflow` 核对归属后处理，不直接移动或删除其他开发者的 TODO。

### 多份活动 TODO

每位开发者只保留一份活动 TODO。先核对各文件中的未完成 Feature、执行实例和依赖，再合并或处理历史文件。不要靠删除文件、写 `.active-todo` 或切换环境变量掩盖仍在运行的实例冲突。

### 状态和 Git 不同步

先只读核对：

```bash
git status --short
git log --oneline -5
git diff --name-only
```

本地 `[x]` 可能只是首次 commit 前准备好的完成 hunk。它必须与真实功能改动同次 commit & push，远端核验通过前显示 `delivery-pending`，不能解锁依赖项。

如果功能已经单独提交、TODO 仍为 `[~]`，先查明交付包为什么不完整，再由主 Agent 在已有授权和当前 Git 状态下修复；不要追加“仅更新 TODO 状态”的提交，也不要自动重写已发布历史。

## 路由问题

### 候选 Skill 不准确

先分清当前看到的是 Harness 原生发现结果，还是 `<skill_routing>` 中的本地辅助提示。本地路由读取 `skill-router.yaml`，不自动读取各 `SKILL.md` 的 frontmatter；`gates`、`conflicts` 和 `related_skills.after` 不能被理解成自动门禁或调用链。

给 Agent 补充具体操作、已有实现和期望结果，或直接点名 Skill。新页面设计与已有页面优化、性能诊断与视觉调整、已批准范围变更与新需求定义应按实际目标区分。

### 查看路由记录

实际的观测脚本是：

```bash
node "<skills-root>/runtime-hooks/scripts/routing-telemetry.cjs" --status
node "<skills-root>/runtime-hooks/scripts/analyze-routing.cjs" report --days 7 --json
```

遥测默认关闭，启用 `AGENT_ROUTER_TELEMETRY=1` 后才有记录；关键词记录还需要单独启用。记录的是辅助匹配结果，不证明 Harness 实际调用正确率。测量边界见 [评估与验证边界](/skills/advanced/performance-metrics/)。

## 任务管理问题

### 无法领取

依次核对当前 Feature 的状态、依赖、runtime instance 和并行写集：

- 一个实例只能拥有一个 `[~]`，一个 Feature 只能由一个实例领取。
- 依赖必须指向同一 TODO 中存在的 Feature 或 Epic，不能自依赖或成环。
- 依赖的 `[x]` 必须已进入核验过的远端功能提交。
- 不同实例并行时，写集须互斥，也不能共享迁移、配置、契约、端口或账号资源。

共享文件确实需要两项修改时应串行，或重新确认唯一 Owner 与交付边界。不要仅把该文件从写集声明里删掉。

### 无法完成

核对所有 AC 是否有新鲜证据、适用交付面是否完整、Review 是否通过，以及写集内是否存在真实改动。完成摘要中的 `Review: pass` 只是结果字段，不能代替实际 Review。

默认复用已有检查或一次真实主路径；高风险、覆盖率、CI 或 finding 不会自动授权新增测试源码。只有用户本轮明确要求时才新增或修改测试。

### 实例不匹配

先确认原实例是否仍在运行。原 Owner 未释放时，不启动第二个实例续作同一 Feature；确认原实例停止后，由主 Agent 通过状态机完成释放与重新分配。

## 项目记忆问题

### 文件没加载

先确认当前工作目录在目标 Git 仓库中。查找顺序是根目录 `PROJECT-MEMORY.md`、`docs/PROJECT-MEMORY.md`、`docs/project-memory.md`；已有文件直接复用。

主要章节为空时，使用 `init-docs` 采集仓库事实，再由 `project-details` 原位归并。示例技术栈、占位文字或旧对话不应当作真实事实。

### 摘要缺少某条事实

注入按问题选择有界摘要，不保证包含全文。让 Agent 读取对应源章节，再核对当前源码。稳定事实保存在项目记忆，任务进度只在唯一 TODO 中维护。

## 命令防护问题

保留 Hook 返回的完整拒绝原因，区分危险命令检查、提交署名检查和流程写入门禁。PreToolUse 不是完整 Shell 或 SQL 解析器，未拦截不等于操作安全或已授权。

阶段与已获授权不一致时，先核对 TODO 和已有产物，再用状态机推进。命令误报应保留目标与规则证据，定向修正；不通过换写法、关闭 Hook 或真实执行危险操作来“验证”。详细边界见 [PreToolUse Hook](/skills/hooks/pre-tool-use/)。
