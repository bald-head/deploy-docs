## Runtime Hook 概述

Runtime Hook 是 Skills Framework 的核心组件，在每次用户请求、工具调用、会话启动和结束时自动运行，提供：

- ✅ **行为内核注入**：跨客户端一致的行为原则
- ✅ **项目记忆加载**：自动读取相关上下文
- ✅ **TODO 自动管理**：任务领取、完成检查、续作
- ✅ **命令防护**：拦截高风险 Bash 命令
- ✅ **流程门禁**：状态机推进控制
- ✅ **语音提醒**：任务完成、需要确认时提醒

## Hook 生命周期

### SessionStart Hook

**触发时机**：客户端启动新会话时

**主要功能**：

1. **检查配置一致性**

比对客户端里已装的 Hook 配置和仓库当前版本。一致就静默通过；不一致会自动合并、去重，并在改写前备份原配置。

<Aside type="tip">
设置 `AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0` 可关闭自动修复。
</Aside>

2. **检查 Penpot MCP 注册状态**

只看本地有没有注册，不连远端，所以不会因为网络问题拖慢会话启动。

```bash
claude mcp get penpot
```

未注册时会提示你运行安装器。

3. **初始化环境变量**

确定这个会话的 developer-id（来自 Git `user.name` 或系统登录用户名）和运行实例 ID——TODO 的落点和"这一项归谁领取"都依赖它们。

**安装器行为**：

```bash
node runtime-hooks/scripts/install.mjs
```

它会先备份现有客户端配置，再把各个 Hook 合并进去（重复项去重），已有的其他 Hook 不会被覆盖。

### UserPromptSubmit Hook

**触发时机**：用户每次提交输入时（在 AI 处理之前）

**主要功能**：

1. **注入行为内核**

每轮请求会自动注入一份跨客户端统一的行为准则，约束事实来源、改动范围和完成判据。你不需要手工维护、复述或在提示词里重复它，Claude Code 与 Codex 得到的是同一份。

2. **自动定位项目根目录**

从当前工作目录向上找 Git 根目录，作为项目根。多仓库场景可以用 `AGENT_REPO_ROOTS` 显式指定映射。

<Aside type="caution">
不在 Git 仓库里时找不到项目根，项目记忆和 TODO 上下文都不会注入。
</Aside>

3. **确保项目记忆文件存在**

按 `docs/PROJECT-MEMORY.md` → `docs/project-memory.md` → 仓库根 `PROJECT-MEMORY.md` 的顺序查找。都没有就创建一份空模板；主要章节还是空的，会提示先用 `init-docs` 采集事实。

4. **加载相关项目记忆**

只取与当前问题相关的稳定事实（技术栈、复用地图、边界），不是整份 `PROJECT-MEMORY.md`。

<Aside type="caution">
注入的是摘要。需要完整背景时直接说"读取 PROJECT-MEMORY.md 的完整内容"。
</Aside>

5. **提示当前 TODO 状态**

如果当前会话已经领取了某个 Feature，这一轮会带上它的 ID、依赖、写集和验收条件，你不需要每轮重述"我在做哪个功能"。

如果还处在规划阶段，带上的是当前阶段、已完成阶段、下一阶段和阶段 Owner——以及当前阶段是否允许修改生产文件。

6. **提示适用 Skill**

```markdown
根据当前状态，推荐以下 Skill：
- 继续实现: universal-development, crud-development
- 完成验证: code-review
- 提交代码: git-commit
- 查看进度: progress
```

**上下文预算控制**：注入内容有总量上限，行为内核、项目记忆和 TODO 提醒都只放当前问题真正需要的部分。超过预算时自动截断并提示直接读取文件。

### PreToolUse Hook

**触发时机**：AI 尝试调用工具之前（Read、Write、Edit、Bash 等）

**主要功能**：

1. **命令防护**

检测高置信度破坏性 Bash 命令：

```bash
# 级别 1: 高危系统命令
rm -rf /
rm -rf /*
dd if=/dev/zero of=/dev/sda
mkfs.*
:(){ :|:& };:  # fork bomb

# 级别 2: 强制推送
git push --force
git push -f
git push --force-with-lease

# 级别 3: 权限提升
sudo rm -rf
chmod -R 777 /
```

命中后直接拒绝并给出中文原因，不是"提示确认"——同一条命令重试仍会被拒绝。确需执行时由使用者在自己的终端里操作。

<Aside type="danger">
`AGENT_COMMAND_GUARD=0` 可关闭命令防护（不推荐），但必须在**启动 CLI 之前** `export`：行内前缀（`AGENT_COMMAND_GUARD=0 git push --force`）只影响被执行的子进程，防护所在的 Hook 进程读不到它，命令照样被拒绝。
</Aside>

2. **流程门禁检查**

规划阶段还没结束时，试图编辑生产代码会被拒绝，并告知当前阶段和需要先推进到哪个阶段。规划阶段仍然可以只读调查、写 `docs/` 下的规划文档，以及推进阶段本身。

**阶段权限表**：

| 阶段类型 | Read | Write 规划文档 | Write 生产代码 | Bash |
|------|------|--------------|--------------|------|
| 规划阶段 | ✓ | ✓ | ✗ | 只读 |
| 实施阶段 | ✓ | ✓ | ✓ | ✓ |
| 交付阶段 | ✓ | ✓ | ✓ | ✓ |

3. **写集边界检查**

写入当前 Feature 写集之外的文件时会收到警告，并提示这个文件可能属于另一个 Feature。处理方式只有两种：先把该文件补进当前 Feature 的写集，或者切到真正拥有它的那个 Feature。

<Aside type="tip">
并行开发时，写集互斥检查防止两个任务同时改同一个文件。
</Aside>

### SubagentStart Hook

**触发时机**：启动子智能体时

**主要功能**：

与 UserPromptSubmit 类似，但额外让子智能体知道：

1. **父任务上下文**：主任务是什么、当前在做哪个 Feature。
2. **职责边界**：它只负责这个 Feature 的哪一部分、能改哪些文件；不允许改写集外的文件，也不允许自己变更 TODO 状态。
3. **交接契约**：结束时必须交回哪些东西——改了哪些文件、覆盖了哪些 AC、证据是什么。

<Aside type="tip">
并行派子智能体时，写集互斥同样生效：两个子智能体不会被允许同时改同一个文件。
</Aside>

### SubagentStop Hook

**触发时机**：子智能体完成任务时

**主要功能**：

子智能体返回时校验交接契约是否完整——改动文件、覆盖的 AC 及其证据、执行过的命令、做过的决策、以及尚未解决的风险。缺项会被指出；带未解决风险时仍然允许交接，但风险会显式带回给主 Agent，不会被悄悄吞掉。

<Aside type="caution">
SubagentStop 只校验 handoff，不代替主 Agent 的 Review、完成切换或 Git 收口。
</Aside>

### Stop Hook

**触发时机**：会话结束或任务完成时

**主要功能**：

1. **完成检查**

回合结束时核对当前 Feature 是否真的可以标完成。任何一项不满足，Feature 就留在 `[~]`，并告诉你缺的是哪一项。

**完成门禁要求**：

- ✅ 所有 AC 都有证据（每条 AC 后面必须挂上真实的验证结果，不是"应该没问题"）
- ✅ Review: pass
- ✅ 写集内存在待提交的业务或必要文档改动
- ✅ 验证档位要求满足（Lite / Standard / High-risk）

2. **状态原子切换**

门禁全过之后，TODO 里的 `[~]` 自动变成 `[x]`，执行实例字段清空，完成证据保留。同一个 Feature 不会被两个会话同时改写，所以并行开发时不需要手工加锁或排队。

3. **Git 收口提醒**

状态更新后会提示下一步是提交，并给出建议的 `git add` / `git commit` / `git push` 命令——TODO 文件本身也在建议的暂存列表里，避免代码提交了、状态没跟上。

4. **自动续作检查**

提交完成后自动在 TODO 里找下一项可执行的 Feature，找到就原子领取并继续；找不到就停下并说明原因（依赖未完成 / 写集冲突 / 队列已空）。

**续作条件**：

- ✅ 所有依赖都是 `[x]` 完成状态
- ✅ 写集与其他进行中任务不冲突
- ✅ 当前开发者是 Owner
- ✅ 没有阻塞（`[!]`）

5. **语音提醒**

回合结束时播放一个短音，用来区分三种情况：需要你做决定或补信息、任务真正完成、普通答复。你不用盯着终端也能知道该不该回来看。

<Aside type="tip">
设置 `AGENT_COMPLETION_SOUND=0` 可关闭语音提醒；也可以用下面的环境变量换成自己的音频文件。
</Aside>

## TODO 管理详解

### 当前开发者唯一 TODO

每个开发者只能有一个活动 TODO 文件：

```
docs/<developer-id>/tasks/todo/<项目名>.md
```

**developer-id 获取顺序**：

1. Git `user.name`（`git config user.name`）
2. 系统登录用户名（`whoami`）
3. 环境变量 `AGENT_DEVELOPER_NAME`（最后兜底）

**唯一性检查**：

`docs/<developer-id>/tasks/todo/` 下出现第二个文件时会直接阻断，要求你先合并或把不做的那份移出去，而不是自己猜该用哪一份。

### Feature 状态机

每个 Feature 有五种状态：

```markdown
[ ] - 未开始（依赖未满足或未领取）
[~] - 进行中（已领取，有执行实例）
[x] - 完成（已提交并推送）
[!] - 阻塞（遇到问题，需要人工介入）
Epic - 汇总（不可领取，自动计算）
```

### Feature 结构

```markdown
- [ ] `USER-LOGIN` 用户登录
  - 依赖: `USER-REG`
  - Owner: alice-chen
  - 执行实例: session-abc123
  - 并行写集: `src/api/user/login.ts`, `src/pages/login.vue`, `src/router/index.ts`
  - AC-001: 用户可以通过表单登录
  - AC-002: JWT token 存储
  - Review: pending
```

**字段说明**：

- **ID**：大写字母、数字、连字符，如 `USER-LOGIN`
- **依赖**：`无` 或反引号 ID 列表，如 `` `USER-REG` ``
- **Owner**：当前开发者 ID
- **执行实例**：Runtime Instance ID（仅 `[~]` 时存在）
- **并行写集**：该 Feature 修改的文件列表（用于并行冲突检测）
- **AC**：验收条件（每个 AC 必须有证据）
- **Review**：code-review 状态（pending / pass / fail）

### Epic 汇总

Epic 是同一 TODO 内的完成汇总：

```markdown
## Epic: USER-MGMT - 用户管理系统
- [x] `USER-REG` 用户注册
- [x] `USER-LOGIN` 用户登录
- [~] `USER-PROFILE` 个人信息
- [ ] `USER-SETTINGS` 用户设置
```

**特性**：

- ❌ 不可领取（只有 Feature 可以领取）
- ❌ 没有执行实例、依赖、写集
- ✅ 最后一个子 Feature 完成时自动变为 `[x]`
- ✅ 用于进度统计和可视化

### 依赖管理

**依赖规则**：

```yaml
合法依赖:
  - 依赖: 无
  - 依赖: `USER-REG`
  - 依赖: `USER-REG`, `USER-LOGIN`

非法依赖:
  - 依赖: USER-REG  # 缺少反引号
  - 依赖: `UNKNOWN`  # ID 不存在
  - 依赖: `USER-LOGIN`（在 USER-LOGIN 内）  # 自依赖
  - 依赖: `USER-MGMT`（USER-MGMT 是 Epic）  # 依赖 Epic 等价于依赖其全部子 Feature
```

**依赖是否满足**：只有依赖项处于 `[x]` 才算满足。

| 依赖项状态 | 能否领取 |
|---|---|
| `[x]` 完成 | ✓ 可以 |
| `[~]` 进行中 | ✗ 等它完成 |
| `[ ]` 未开始 | ✗ 先做它 |
| `[!]` 阻塞 | ✗ 先解阻塞 |

**环形依赖**：A 依赖 B、B 依赖 C、C 又依赖 A 这类闭环会被识别并报错，因为闭环里没有任何一项能先开始。

### 并行任务管理

**写集互斥检查**：领取新 Feature 时，把它的写集和所有 `[~]` 任务的写集求交集。交集为空才允许并行。

- 两个 Feature 各改自己的 API 和页面，没有共同文件 → 可以并行
- 两个 Feature 都要改 `src/router/index.ts` → 冲突，只能串行；或者把这个文件从其中一个 Feature 的写集里拿掉

**并行条件**：

- ✅ 不同 Feature
- ✅ 不同执行实例
- ✅ 所有依赖已完成
- ✅ 写集完全互斥（无交集）

### 状态怎么流转

领取、完成、阻塞、释放，以及规划阶段的推进和等待确认，都由 Hook 在后台原子完成，你用自然语言驱动就够了：

| 你说 | 发生什么 |
|---|---|
| "开始实现 USER-LOGIN" | 校验依赖和写集，把它从 `[ ]` 原子领取成 `[~]`，绑定当前会话 |
| "完成 USER-LOGIN" | 走完成门禁；全过才切 `[x]` 并提示提交 |
| "USER-LOGIN 卡住了，等设计稿" | 标 `[!]` 并记下阻塞原因 |
| "继续" / "下一个" | 在 Ready 队列里找下一项并自动领取 |

<Aside type="caution">
状态先落定、再提交：这样 TODO 的更新和代码改动在同一次提交里，不会出现"代码进了远端、状态还留在昨天"。
</Aside>

## 环境变量配置

```bash
# 开发者 ID（仅在 Git 和系统用户名都不可用时）
AGENT_DEVELOPER_NAME=alice-chen

# TODO 目录（仅允许指向当前 Git 根内当前 developer 的规范目录）
AGENT_TODO_DIR=/repo/docs/alice-chen/tasks/todo

# Runtime Instance ID（仅在 Harness 未提供时兜底）
AGENT_RUNTIME_INSTANCE_ID=worker-a

# 仓库根目录映射
AGENT_REPO_ROOTS='{"backend":"/checkout/backend"}'

# 禁用 Runtime Hook（不推荐）
AGENT_RUNTIME_HOOKS_DISABLED=1

# 禁用命令防护（不推荐）
AGENT_COMMAND_GUARD=0

# 禁用自动修复
AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0

# 禁用语音提醒
AGENT_COMPLETION_SOUND=0

# 自定义音频文件
AGENT_CONFIRMATION_SOUND_FILE=/path/to/confirm.wav
AGENT_REPLY_COMPLETION_SOUND_FILE=/path/to/reply.wav
AGENT_TASK_COMPLETION_SOUND_FILE=/path/to/task.wav

# 启用 Skill 发现兜底（旧客户端）
AGENT_SKILL_DISCOVERY_FALLBACK=1
```

## 故障排查

### Hook 未生效

表现是这一轮完全没有自动上下文：没有行为准则、没有项目记忆、没有 TODO 提醒。

```bash
# 1. 检查 Hook 安装状态
node runtime-hooks/scripts/install.mjs --check --json

# 2. 查看客户端配置
cat ~/.claude/settings.json | grep -A 20 hooks

# 3. 重新安装
node runtime-hooks/scripts/install.mjs
```

Codex 用户装完还要在客户端里运行 `/hooks`，审查并信任新的 Hook——这是 Codex 的安全机制，不能跳过。

### TODO 落在了意外的目录

TODO 的位置由 developer-id 决定，先确认它是什么：

```bash
git config user.name
find docs/ -path "*/tasks/todo/*.md"
```

路径和预期不符时，优先把 `git config user.name` 设成你想要的值，而不是去改文件位置。

### 命令被拦截

先确认这条命令是不是真的该跑。属于误拦截时，唯一的处理方式是你在自己的终端里执行；Agent 侧没有绕过路径。要长期关闭防护，必须在**启动 CLI 之前** `export AGENT_COMMAND_GUARD=0`。

### 并行任务冲突

```bash
# 查看当前进行中的任务，逐个比对写集
grep '\[~\]' docs/<developer-id>/tasks/todo/<项目名>.md
```

有交集就只能三选一：等冲突任务完成、把共享文件从其中一个写集里移出去、或者干脆串行做。

<Aside type="tip">
更细的症状-处理对照见 [Hook 故障排查](/skills/hooks/troubleshooting/) 和 [故障排查](/skills/troubleshooting/)。
</Aside>
