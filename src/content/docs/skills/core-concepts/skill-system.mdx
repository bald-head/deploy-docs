Skill 是给 Coding Agent 使用的专业规则与资源包。它明确某类任务何时适用、需要哪些输入、如何推进，以及如何判断结果。框架提供研发 SOP，不是独立的 Agent 编排或项目管理平台。

## 独立目录

```text
<skill-name>/
  SKILL.md
  references/     按需读取的专项资料
  scripts/        确定性操作
  assets/         实际需要的模板与资源
  agents/         适用客户端元数据
```

只有 `SKILL.md` 是必需入口，其余目录按实际消费者添加。每个 Skill 是可单独安装的分发单元，运行时必读资源必须在自身目录内；跨 Skill 按能力名称协作，不把兄弟目录的相对路径当成依赖。

新增的 `resume-claude` 与 `resume-codex` 各自带有 `resume-session/` 规则和 Python reader，因此单独安装时也能读取对应来源的历史。

## 按需读取

| 层次 | 内容 | 使用时机 |
| --- | --- | --- |
| 原生发现信息 | `name`、`description`、可读路径 | 当前 Harness 提供给每次请求与新 subagent |
| `SKILL.md` 正文 | 主流程、输入、约束、失败与完成边界 | 当前任务命中该 Skill 后 |
| 直接引用的资源 | 相关 reference、脚本、模板 | 执行中的具体步骤需要时 |

Runtime Hook 不重复注入完整 Skill 清单、正文或所有 references。`description` 应能独立说明核心用途和关键排除边界，避免只能读完长文才知道不适用。

字段写法见 [Frontmatter 规范](/skills/advanced/frontmatter-spec/)。`triggers`、`gates`、`conflicts` 和 `related_skills` 是语义与协作约定，不是跨客户端固定自动执行协议。

## 怎么调用

| 当前客户端 | 显式调用 | 其他方式 |
| --- | --- | --- |
| Claude Code | `/skill-name` | 自然语言描述任务 |
| Codex | `$skill-name` | 自然语言；`/skills` 浏览，`$` 补全 |

例如，在 Codex 中输入 `$resume-claude <session-id> 只总结未完成事项`，读取的仍是 Claude Code 历史。调用语法由当前客户端决定，历史来源由所选 Skill 决定。

客户端的系统 Skill、项目级 Skill 和同名优选项可能使实际发现数量不同于本站。不要把固定条目数作为接入成功条件，安装与发现检查见[安装与配置](/skills/getting-started/)。

## 职责如何配合

一次纵向功能会用到多个专业能力，但只有一个完整的用户结果和收口过程。

| 工作 | 合适能力 |
| --- | --- |
| 新需求定义与范围澄清 | 产品与规划类 Skill |
| 已批准功能的具体实现 | API、数据库、前端、安全等专业 Skill，适用时由 `dev` 组织 |
| 标准 CRUD 纵向交付 | `crud-development` |
| 调用仓库现有 CRUD 生成器 | `crud` |
| 当前完整 diff 的缺陷审查 | `code-review` |
| 无任何对口专业能力的最小任务 | 最低优先级兜底 `universal-development` |

`related_skills.after` 只说明可能的后续协作，不能自动增加任务范围或写测试、Git、部署授权。实现、验证和 Review 仍按当前任务及有效授权执行。

## 分类与维护

当前框架的 `priority` 分为 Critical、High、Medium、Low；它用于职责声明与目录分组，不是能力排名，也不保证 Harness 固定评分。逐项查阅 [Skill 目录](/skills/catalog/)和[参考手册](/skills/skills-reference/)。

创建或实施已确认结构改动使用 `skill-creator`，普通内容修正使用 `skill-optimizer`，注册与同步使用 `add-skill`。目录校验、静态语义 Review 和真实调用评估分别证明不同结果，详见[评估与验证边界](/skills/advanced/performance-metrics/)。
