已经完成[快速上手](/skills/quickstart/)后，可以按下面的顺序了解框架。日常使用不需要先掌握 Hook 内部实现，遇到问题时再查对应章节。

## 1. Skill：专业规则与资源

每个 Skill 是独立目录，由 `SKILL.md` 定义用途、输入、流程和边界，必要时带有脚本与引用资源。客户端先提供发现信息，命中后才读取正文。

本站收录 97 个非系统 Skill，完整分类见 [Skill 目录](/skills/catalog/)；目录结构与调用方式见 [Skill 系统](/skills/core-concepts/skill-system/)。

## 2. 选择：根据任务与当前事实

Harness 原生提供 `name`、`description` 和可读路径，Agent 结合用户请求与仓库事实选择适用能力。`gates`、`conflicts`、`not_for` 等是理解边界的语义规则，不是所有客户端都会执行的固定评分协议。

例如，读取 Claude Code 历史使用 `resume-claude`；继续当前 TODO 使用 `next`；页面加载慢使用 `performance-doctor`，布局整理使用 `frontend-polish`。

源仓库可选的辅助候选匹配与原生发现不同，具体实现和验证边界见[发现与选择机制](/skills/core-concepts/routing/)。

## 3. Runtime Hook：提供上下文与状态检查

在客户端支持并已信任的事件上，Hook 提供共享行为内核、相关项目记忆、开发者归属与任务上下文，并执行适用的命令或状态检查。它不重复注入完整 Skill 路由清单，也不代替 Agent 执行 commit、push 或部署。

先看 [Runtime Hook 的职责](/skills/core-concepts/runtime-hooks/)，需要配置与排错时再查 [Runtime Hooks 手册](/skills/hooks/)。

## 4. 项目记忆：稳定事实

唯一 `PROJECT-MEMORY.md` 保存技术栈、真实入口、复用 Owner 和边界；已有 `docs/PROJECT-MEMORY.md` 时沿用。它帮助后续工作复用已核对事实，不保存任务状态、对话副本或过程流水。

详细结构与维护规则见[项目记忆](/skills/core-concepts/project-memory/)。

## 5. TODO：功能与执行状态

当前开发者唯一 Markdown TODO 保存功能、菜单或入口、依赖、验收、并行写集与状态。每个 Feature 由一个实例领取，完成后先准备状态，再随业务改动同次授权提交与推送；远端核验后才解锁依赖。

规划档位和自主模式调整工作组织方式，不减少必要产品、设计、技术和交付内容。阅读[工作流模式](/skills/core-concepts/workflow-modes/)了解分工，具体操作见 [TODO 管理](/skills/usage/todo-management/)。

## 如何配合

```text
用户请求 + 当前仓库事实
  → Harness 提供可用 Skill
  → Agent 选择适用规则并按需读取
  → 使用当前项目记忆和任务上下文
  → 完成授权范围内的工作与验证
  → 按证据说明结果与剩余事项
```

`related_skills` 说明可能的前置、后续或协作关系，不会自行启动一条固定工作流。新功能先完成必要规划；已批准 TODO、明确 Bug 和普通维护直接按现有边界推进。

维护元数据见 [Frontmatter 规范](/skills/advanced/frontmatter-spec/)，评估真实效果见[评估与验证边界](/skills/advanced/performance-metrics/)。
