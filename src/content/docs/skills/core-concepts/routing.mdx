## 路由由谁负责

客户端 Harness 负责发现可用 Skill，并在命中后按需读取对应的 `SKILL.md`。Runtime Hook 不会把完整 Skill 清单复制进每轮上下文；它只注入行为内核、项目记忆、当前 TODO，以及可选的本地路由提示。

仓库里的 `skill-router.yaml` 和 `runtime-hooks/scripts/skill-router.cjs` 是辅助能力。它们按场景触发词匹配本地配置，返回候选场景和 Skill 名称，供 Agent 判断下一步。这个提示不等于 Harness 的最终调用，也不会替代对 `SKILL.md` 的读取。

<Aside type="note">
本地路由配置和各 Skill 的 frontmatter 不是同一个数据源。`skill-router.cjs` 读取 YAML 场景表；它不会读取各 `SKILL.md` 的 frontmatter。
</Aside>

## 一次请求会发生什么

以“需求改了，用户表要加手机号字段”为例：

```
用户输入
  ↓
UserPromptSubmit Hook
  - 注入行为内核
  - 定位 Git 仓库并读取项目记忆摘要
  - 读取当前 TODO 状态
  - 可选：运行本地 YAML 路由，输出候选提示
  ↓
Harness 原生 Skill 发现
  - 根据客户端发现结果选择或展示 Skill
  - 按需读取命中的 SKILL.md
  ↓
Agent 按当前任务边界执行
```

本地路由匹配结果可能包含场景分数、候选 Skill，或在多个场景同时命中时建议使用 `grilling` 消歧。这些都是上下文提示，不是自动执行链。

## 本地场景匹配

`skill-router.cjs` 从 `skill-router.yaml` 建立场景和触发词索引：

```yaml
scenes:
  requirement_change:
    triggers:
      zh: [需求改了, 范围变了]
      en: [requirement change, scope change]
    primary_skills: [change-impact-analysis]
    priority: critical
```

匹配行为包括：

- 触发词包含匹配；中文长词支持有限的片段匹配。
- 多个词的触发短语要求各词出现；拉丁短词按词边界匹配。
- 结果按字面命中和累计分排序，最多保留三个场景和五个候选 Skill。
- 没有场景命中时返回 `dev` 与 `universal-development` 作为兜底候选。
- 候选超过阈值时标记需要消歧，提示 Agent 先澄清意图。

这些规则只描述当前辅助路由器的实现，不代表 Harness 的发现算法或准确率承诺。

## Frontmatter 的边界

Skill 的 YAML frontmatter 可以描述名称、职责、触发词、优先级、边界和相关 Skill，具体字段以对应 `SKILL.md` 为准。Runtime Hook 的本地路由器不会自动验证或执行其中的 `gates`、`conflicts`、`related_skills`：当前 `checkGates()` 仅作为保留接口，匹配场景后直接通过。

因此：

- `gates` 和 `conflicts` 是给 Agent 阅读的职责与决策信息，不是已实现的自动门禁。
- `priority` 只参与本地 YAML 场景和候选排序；不能据此推断 Harness 一定选择某个 Skill。
- `related_skills.before/after/complement` 表达协作建议，不会由路由器自动串行调用。
- 真正的阶段门禁、写集检查、TODO 状态切换和远端核验由 TODO 状态机与对应 Hook 负责。

## Runtime Hook 提示

### UserPromptSubmit

每轮请求可注入：

- 行为内核（事实先行、简单优先、最小写集等）。
- 与当前问题相关的项目记忆摘要。
- 当前 Feature、依赖、写集和流程阶段。
- 本地路由器给出的候选场景与 Skill 提示（命中时）。

Skill 正文仍由 Harness 按需加载；需要完整规则时直接打开对应的 `SKILL.md`。

### SubagentStart

启动子 Agent 时注入同一项目上下文，并附上任务边界和交接要求。它不会替主 Agent 领取或完成 Feature。

### PreToolUse 与 Stop

PreToolUse 负责高风险命令、规划阶段生产写入和写集边界检查。Stop 负责检查 AC、Review、写集改动和验证状态，必要时原子切换 TODO 并核验远端；它不会替代主 Agent 执行 `git commit` 或 `git push`。

## 调试与观测

路由提示默认只在命中时注入。若启用遥测，Runtime Hook 可将匹配结果和耗时写入遥测文件；输入关键词还需要显式设置 `AGENT_ROUTER_TELEMETRY_KEYWORDS=1`。实际命令是：

```bash
node runtime-hooks/scripts/routing-telemetry.cjs --help
node runtime-hooks/scripts/analyze-routing.cjs --help
```

实际脚本中没有 `routing-stats.cjs` 或 `routing-benchmark.cjs`。辅助匹配日志不能证明 Harness 的实际调用准确率；发布指标需要同时给出版本、样本和测量命令，详见 [评估与验证边界](/skills/advanced/performance-metrics/)。

## 使用建议

给出具体的操作和对象，例如“审查这段 API 契约”或“优化已有登录页面”，比只说“处理一下”更容易得到明确候选。遇到多个候选时，补充当前阶段、已有实现和期望结果，或让 Agent 使用 `grilling` 消歧。
