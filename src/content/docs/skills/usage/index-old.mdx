## 使用指南概述

### 流程状态机阶段

新功能开发会经过以下阶段：

```
需求录入 → 需求分析 → 需求确认 ⚠️
→ 技术方案 → 方案确认 ⚠️
→ 任务拆分 → 代码生成
→ 业务开发 ✅ → 代码审查
→ 测试生成 → 测试运行
→ 用户验收 → Git 交付 → 完成
```

<Aside type="caution">
业务开发阶段前，不允许修改生产代码，只能进行只读调查和规划文档编写。
</Aside>

## 工作流选择指南

### 场景 1：全新项目

```
你的情况: 从零开始一个项目
推荐流程: 新项目开发
关键 Skill: task-todo-workflow → product-manager → architecture-design
预计时间: 2-4 小时（取决于项目复杂度）
```

### 场景 2：已有项目，新功能开发

```
你的情况: 在现有项目中添加新功能
推荐流程: 功能开发流程
关键 Skill: product-manager → frontend-design → tech-decision → project-manager
预计时间: 1-2 小时（规划） + 实际开发时间
```

### 场景 3：需求变更

```
你的情况: 已批准的需求发生变化
推荐流程: 直接触发 change-impact-analysis
关键 Skill: change-impact-analysis → project-manager
预计时间: 30 分钟 - 1 小时
```

### 场景 4：Bug 修复

```
你的情况: 发现并修复 Bug
推荐流程: 故障排查 → 直接修复 → code-review
关键 Skill: bug-detective → universal-development → code-review
预计时间: 30 分钟 - 2 小时（取决于 Bug 复杂度）
```

### 场景 5：代码优化

```
你的情况: 优化已有代码的性能或质量
推荐流程: 直接触发对应 Skill
关键 Skill: frontend-polish / performance-doctor / simplify
预计时间: 30 分钟 - 2 小时
```

## 开发模式选择

Skills Framework 支持三种开发模式（档位）：

### Lite（轻量模式）

**特点**：
- 只裁剪重复文书
- 不裁剪交付面
- 适合简单功能

**使用场景**：
- 简单的 CRUD 功能
- Bug 修复
- 小型优化

**在 TODO 中标注**：
```markdown
## Feature: USER-LOGIN
档位: Lite
```

### Standard（标准模式）

**特点**：
- 完整规划和证据
- 标准验收流程
- 适合大多数功能

**使用场景**：
- 常规业务功能
- API 开发
- 页面开发

**在 TODO 中标注**：
```markdown
## Feature: USER-MGMT
档位: Standard
```

### High-risk（高风险模式）

**特点**：
- 额外的风险边界分析
- 回滚方案
- 方案复核
- 发布检查

**使用场景**：
- 数据库迁移
- 认证系统变更
- 生产环境部署
- 涉及安全的功能

**在 TODO 中标注**：
```markdown
## Feature: AUTH-MIGRATION
档位: High-risk
```

<Aside type="danger">
**High-risk 模式要求**：
- 必须有回滚方案
- 必须有风险边界分析
- 必须有方案复核
- 完成摘要必须包含发布检查
</Aside>

## 自主模式选择

与档位正交的自主模式决定当前授权内可连续执行到哪里：

### Goal（目标模式）

**特点**：
- 只规划，不实施
- 输出完整 TODO

**使用场景**：
- 需要人工审批
- 需要外部资源
- 不确定技术方案

**在 TODO 中标注**：
```markdown
自主模式: Goal
```

### Plan（计划模式）

**特点**：
- 规划 + 部分实施
- 关键步骤需确认

**使用场景**：
- 需要阶段性确认
- 涉及多个系统
- 需要协调资源

### Build（构建模式）

**特点**：
- 完整实施
- 自动推进

**使用场景**：
- 明确需求
- 技术方案确定
- 可独立完成

**在 TODO 中标注**：
```markdown
自主模式: Build
```

<Aside type="tip">
**推荐组合**：
- Lite + Build：快速迭代
- Standard + Build：常规开发
- High-risk + Plan：关键变更，阶段确认
</Aside>

## 团队协作

### 多人并行开发

```markdown
团队成员 Alice:
  docs/alice-chen/tasks/todo/user-mgmt.md
  [~] USER-LOGIN（写集: src/api/user/login.ts）

团队成员 Bob:
  docs/bob-wang/tasks/todo/user-mgmt.md
  [~] USER-PROFILE（写集: src/api/user/profile.ts）

写集无交集 → 可以并行 ✓
```

### 任务交接

```markdown
Alice 完成 USER-LOGIN:
  [~] USER-LOGIN → [x] USER-LOGIN
  commit + push

Bob 开始 USER-SETTINGS:
  依赖: USER-LOGIN (✓ 已完成)
  领取: [ ] USER-SETTINGS → [~] USER-SETTINGS
```

### 冲突解决

```markdown
Alice 和 Bob 同时修改 src/router/index.ts:
  
检测冲突:
  Alice: [~] USER-LOGIN（写集包含 src/router/index.ts）
  Bob: 尝试领取 USER-REG（写集包含 src/router/index.ts）
  
结果: ✗ 写集冲突，Bob 不能领取

解决方案:
  1. 等待 Alice 完成
  2. 或 Alice 先提交路由部分
  3. 或调整写集边界
```

## 常见问题

### Q1: 如何切换正在进行的任务？

不能直接切换。必须先完成或阻塞当前任务：

```bash
# 完成当前任务
"完成 USER-LOGIN"

# 或标记为阻塞
"USER-LOGIN 卡住了,等设计稿"

# 然后领取新任务
"开始实现 USER-PROFILE"
```

### Q2: 如何查看所有可用的 Skill？

```bash
# 在客户端中
/skills

# 或查看文档
浏览 /skills/catalog/
```

### Q3: 如何知道当前在哪个阶段？

```bash
# 查看 TODO 文件中的流程状态机
cat docs/<your-name>/tasks/todo/<project>.md

# 或询问
"当前在哪个阶段？"
```

### Q4: 如何回到之前的版本？

```bash
# 使用 Git
git log  # 查看提交历史
git checkout <commit-hash>  # 回到指定版本
git revert <commit-hash>  # 撤销指定提交

# 或使用 git-workflow Skill
"回退到上一个版本"
```

### Q5: 如何处理紧急 Bug？

```bash
# Bug 修复不需要经过完整流程状态机
# 直接描述问题
"用户登录失败，报错 401"

# 系统自动触发
bug-detective → 排查 → universal-development → 修复 → code-review → git-commit
```
