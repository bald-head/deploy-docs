## 先选场景

这组指南按一次真实任务的决策顺序排列。先判断任务类型，再进入对应流程；不要因为历史对话或旧摘要跳过当前仓库和 TODO 的核对。

| 现在要做什么 | 入口 |
| --- | --- |
| 从零启动项目 | [新项目开始](/skills/usage/new-project/) |
| 交付 TODO 中已批准的新功能 | [功能开发流程](/skills/usage/feature-development/) |
| 已批准范围、契约或数据边界发生变化 | [需求变更处理](/skills/usage/requirement-change/) |
| 排查并修复 Bug | [Bug 修复流程](/skills/usage/bug-fix/) |
| 读取另一段 Claude/Codex 历史会话 | [会话接续](/skills/usage/session-resume/) |
| 审查已收敛的改动 | [代码审查流程](/skills/usage/code-review/) |
| 管理分支、合并或冲突 | [Git 操作指南](/skills/usage/git-workflow/) |
| 记录每次变更和合并 | [变更日志](/skills/usage/changelog/) |
| 查看、领取或完成 TODO | [TODO 管理](/skills/usage/todo-management/) |

<Aside type="note">
“继续当前已批准的 TODO”和“读取另一段历史会话”是两件事。前者由 `next` 根据当前 TODO 选择，后者才使用 `resume-claude` 或 `resume-codex`。
</Aside>

## 推荐顺序

### 新项目

1. [新项目开始](/skills/usage/new-project/) 建立项目事实、需求和唯一 TODO。
2. [功能开发流程](/skills/usage/feature-development/) 领取一个已批准 Feature 并完成纵向交付。
3. [代码审查流程](/skills/usage/code-review/) 审查完整 diff，关闭 findings。
4. [Git 操作指南](/skills/usage/git-workflow/) 在授权范围内提交、推送并核验远端。

### 已有项目

1. 先读当前 `PROJECT-MEMORY.md`、唯一 TODO 和目标源码。
2. 新功能走 `product-manager` / `project-manager`；已批准范围的真实变化走 `change-impact-analysis`。
3. 已批准 Feature 直接进入 [功能开发流程](/skills/usage/feature-development/)。
4. Bug 走 [Bug 修复流程](/skills/usage/bug-fix/)，不把 Bug 当成新需求重新规划。

### 从历史会话接续

1. 明确历史来源是 Claude Code 还是 Codex，再进入[会话接续](/skills/usage/session-resume/)。
2. 读取结果只作为核对线索；当前仓库、分支、改动、项目记忆和 TODO 才是实施依据。
3. 只读总结到此结束；只有用户明确要求继续，才在当前授权范围内进入实现流程。

## 完成一项 Feature 的最短闭环

```text
当前 TODO 的 [~] Feature
  ↓
来源复核 + 项目记忆
  ↓
核对已批准的技术结论（缺失时才走技术选型）
  ↓
数据 / API / 后端 / 页面 / 权限 / 异常恢复
  ↓
一个最有判别力的现有检查 + 真实入口验证
  ↓
一次完整 code-review，关闭 findings
  ↓
回写 TODO；获得授权后由 git-commit 提交和推送
```

默认不新增测试源码。只有用户在本轮明确要求设计测试策略、方案或用例时，才进入 `test-strategy`；只有明确要求写或改测试源码时，才进入 `test-development`。已有测试、CI 门禁或 Review finding 本身都不构成授权。每条验收都要记录真实证据，证据不足就保持未完成并说明缺口。

## 常用触发

| 目标 | 示例请求 | 主要入口 |
| --- | --- | --- |
| 开始新项目 | `我要做一个订单系统` | `product-manager` / `project-manager` |
| 实现已批准功能 | `开始实现 ORDER-EXPORT` | `next` → `dev` 或专业实现 Skill |
| 需求发生变化 | `需求改了，订单需要支持手机号` | `change-impact-analysis` |
| 修复故障 | `登录接口返回 401，请定位根因并修复` | `bug-detective` |
| 读取 Claude 历史 | `读取 Claude Code 会话 <session-id>` | `resume-claude` |
| 读取 Codex 历史 | `继续 Codex 中关于订单分页的会话` | `resume-codex` |
| 只看当前进度 | `读取我的 TODO，报告完成、进行中和阻塞项` | `progress` |
| 审查改动 | `审查 ORDER-EXPORT 这次完整 diff` | `code-review` |

## 常用检查

```bash
# 当前仓库根目录
git rev-parse --show-toplevel

# 当前开发者的唯一 TODO
cat docs/<developer-id>/tasks/todo/<文件名>.md

# 稳定项目事实
cat PROJECT-MEMORY.md

```

Codex 可在客户端内输入 `/skills` 浏览可用 Skill，或输入 `$` 查看补全；Claude Code 使用当前会话提供的 Skill 列表，并以 `/skill-name` 显式调用。这些都不是终端命令。

不要把示例中的技术栈、路径或命令当成目标仓库事实。先检查项目已有的依赖、脚本、配置和相邻实现，再选择适用 Skill。
