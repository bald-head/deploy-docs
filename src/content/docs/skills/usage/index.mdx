## 常用自然语言触发

不需要记住 Skill 名称，直接用自然语言描述你要做什么：

| 你想做什么 | 说什么 | 触发的 Skill |
|-----------|--------|-------------|
| 开始新项目 | "我要做一个XX系统" | task-todo-workflow → product-manager |
| 需求变更 | "需求改了，XX要改成YY" | change-impact-analysis |
| 开发功能 | "开始实现用户注册" | crud-development / universal-development |
| 设计页面 | "设计用户登录页面" | frontend-design |
| 优化页面 | "优化这个页面的性能" | frontend-polish |
| 审查代码 | "审查代码" | code-review |
| 排查问题 | "报错了，登录失败" | bug-detective |
| 提交代码 | "提交并推送代码" | git-commit |
| 查看进度 | "查看当前进度" | progress |

<Aside type="tip">
系统会根据触发词、前置条件（gates）和冲突规则（conflicts）自动选择最合适的 Skill，准确率 96%+。
</Aside>

## 开发模式选择

不同场景选择不同的档位和自主模式：

| 场景 | 档位 | 自主模式 | 预计时间 |
|------|------|---------|---------|
| 快速原型验证 | Lite | Build | 30 分钟 - 1 小时 |

| 数据库迁移 | High-risk | Plan | 2-4 小时 |
| Bug 修复 | Lite | Build | 30 分钟 - 2 小时 |

## 常见问题

### Q1: 如何切换正在进行的任务？

不能直接切换。必须先完成或阻塞当前任务：

```bash
# 完成当前任务
"完成 USER-LOGIN"

# 或标记为阻塞
"USER-LOGIN 卡住了,等设计稿"

# 然后领取新任务
"开始实现 USER-PROFILE"
```

### Q2: 如何查看所有可用的 Skill？

```bash
# 在客户端中
/skills

# 或查看文档
浏览 /skills/catalog/
```

### Q3: 如何知道当前在哪个阶段？

```bash
# 查看 TODO 文件中的流程状态机
cat docs/<your-name>/tasks/todo/<project>.md

# 或询问
"当前在哪个阶段？"
```

### Q4: 如何处理紧急 Bug？

```bash
# Bug 修复不需要经过完整流程状态机
# 直接描述问题
"用户登录失败，报错 401"

# 系统自动触发
bug-detective → 排查 → universal-development → 修复 
→ code-review → git-commit
```

### Q5: 多人如何避免冲突？

每个任务都有写集（要修改的文件列表），系统自动检查：
- ✅ 写集不冲突的任务可以并行
- ❌ 写集冲突的任务必须串行

详见：[团队协作指南](/skills/usage/team-collaboration/)
