## 概述

本指南将手把手教你如何使用 Skills Framework 从零开始一个新项目，涵盖项目初始化、需求分析、架构设计、技术选型到生成第一个可执行的 TODO。

**预计时间**：2-4 小时（取决于项目复杂度）

**前置条件**：
- ✅ 已安装 Skills Framework
- ✅ Runtime Hook 正常工作
- ✅ 项目目录已创建（可以是空目录）

## 完整流程

### 第 1 步：初始化 Git 仓库

在项目目录中初始化 Git：

```bash
cd /path/to/your-project
git init
git config user.name "alice-chen"
git config user.email "alice@example.com"
```

✅ **检查点**：运行 `git config user.name` 应该输出你的用户名。

<Aside type="tip">
developer-id 会从 `git config user.name` 自动获取，用于 TODO 路径 `docs/alice-chen/tasks/todo/`。
</Aside>

### 第 2 步：启动客户端

```bash
# 启动 Claude Code
cd /path/to/your-project
claude

# 或启动 Codex
codex
```

### 第 3 步：描述项目需求

用自然语言描述你要做什么：

```
我要做一个用户管理系统，包括以下功能：
1. 用户注册（邮箱 + 密码）
2. 用户登录（JWT 认证）
3. 个人信息管理（查看、编辑昵称、头像）
4. 密码修改
```

**预期行为**：

系统自动识别这是新项目，触发一系列 Skill：

```
1. task-todo-workflow - 建立流程状态机
   ↓
2. product-manager - 产品定义
   ↓
3. frontend-design - UI/UX 设计（如有页面）
   ↓
4. architecture-design - 系统架构
   ↓
5. tech-decision - 技术选型
   ↓
6. project-manager - 生成 TODO
```

### 第 4 步：流程状态机建立

**task-todo-workflow Skill 会自动**：

1. 检查是否存在 TODO 文件
2. 不存在则创建 `docs/alice-chen/tasks/todo/user-management.md`
3. 建立流程状态机

**生成的 TODO 内容**：

```markdown
# 用户管理系统 - 任务清单

## 流程状态机

- 当前阶段: intake
- 已完成阶段: 无
- 下一阶段: requirements-analysis
- 阶段 Owner: alice-chen

### intake（需求录入）✓
- 需求来源: 用户输入
- 录入时间: 2024-09-03
- 录入人: alice-chen

## 功能列表（待拆分）

临时记录：
- 用户注册（邮箱 + 密码）
- 用户登录（JWT 认证）
- 个人信息管理
- 密码修改
```

✅ **检查点**：查看 TODO 文件，应该看到流程状态机和临时功能列表。

```bash
cat docs/alice-chen/tasks/todo/user-management.md
```

### 第 5 步：需求分析

**product-manager Skill 会自动**：

1. 研究类似功能（如果项目记忆中有参考）
2. 提出澄清问题（通过 grilling Skill）
3. 完成产品定义

**可能的澄清问题**：

```
系统会问：

1. 用户注册是否需要邮箱验证？
   你的回答: 暂时不需要，v1.0 直接注册

2. 密码强度有什么要求？
   你的回答: 至少 8 位，包含字母和数字

3. 头像上传有大小限制吗？
   你的回答: 最大 2MB，支持 JPG/PNG

4. 是否需要管理员角色？
   你的回答: 暂时不需要，所有用户平等
```

<Aside type="tip">
grilling Skill 会一次一个问题追问，直到约 95% 清晰。可查事实会自行取证。
</Aside>

**产品定义输出**：

```markdown
## requirements-analysis（需求分析）✓

### 功能范围

#### F1: 用户注册
- 用户通过邮箱 + 密码注册
- 密码强度要求: 至少 8 位，包含字母和数字
- 注册成功后自动登录
- 无需邮箱验证（v1.0）

#### F2: 用户登录
- 用户通过邮箱 + 密码登录
- 使用 JWT 进行身份验证
- Token 有效期 7 天
- 支持"记住我"功能

#### F3: 个人信息管理
- 查看个人信息（昵称、邮箱、头像）
- 编辑昵称
- 上传头像（最大 2MB，JPG/PNG）

#### F4: 密码修改
- 需要输入旧密码验证
- 新密码符合强度要求
- 修改成功后强制重新登录

### 验收条件

#### AC-REG-001
用户可以通过注册表单完成注册，密码符合强度要求

#### AC-LOGIN-001
用户可以通过邮箱密码登录，获得 JWT token

#### AC-PROFILE-001
用户可以查看和编辑个人信息

#### AC-PASSWORD-001
用户可以修改密码，旧密码验证通过后生效

### 非功能需求

- 性能: 登录响应时间 < 500ms
- 安全: 密码加密存储（bcrypt）
- 可用性: 表单验证实时反馈
```

✅ **检查点**：TODO 文件更新，包含详细的需求分析。

**推进到下一阶段**：

系统自动推进：

```
当前阶段: requirements-analysis
  ↓
下一阶段: requirements-confirmation（需要确认）
```

**你需要确认**：

```
"确认需求"
```

或者明确说：

```
"需求没问题，继续"
```

系统会推进到下一阶段。

### 第 6 步：UI/UX 设计（如有前端）

**frontend-design Skill 会自动**：

1. 根据产品定义设计页面结构
2. 定义交互流程
3. 输出 DesignContract

**设计输出示例**：

```markdown
## 页面结构

### 1. 注册页面 (/register)
- 表单: 邮箱输入、密码输入、确认密码
- 实时验证: 邮箱格式、密码强度
- 按钮: 注册、已有账号登录

### 2. 登录页面 (/login)
- 表单: 邮箱、密码
- 记住我复选框
- 按钮: 登录、注册新账号、忘记密码

### 3. 个人信息页面 (/profile)
- 显示: 头像、昵称、邮箱
- 编辑: 昵称编辑框、头像上传
- 按钮: 保存、修改密码

### 4. 密码修改页面 (/change-password)
- 表单: 旧密码、新密码、确认新密码
- 实时验证: 密码强度
- 按钮: 确认修改、取消

## 交互流程

注册流程:
  输入邮箱密码 → 实时验证 → 提交 → 成功自动跳转登录页

登录流程:
  输入凭证 → 提交 → 成功跳转首页 → 失败显示错误

信息编辑流程:
  编辑昵称/上传头像 → 保存 → 成功提示 → 刷新显示
```

### 第 7 步：技术方案设计

**architecture-design Skill 会自动**：

1. 设计系统架构
2. 定义模块边界
3. 确定部署方案

**架构输出示例**：

````markdown
## technical-plan（技术方案）

### 系统架构

```
┌─────────────┐
│  Vue 3 前端  │
└──────┬──────┘
       │ HTTP/REST
┌──────▼──────┐
│ Spring Boot │
│   后端 API   │
└──────┬──────┘
       │ JDBC
┌──────▼──────┐
│ PostgreSQL  │
│   数据库     │
└─────────────┘
```

### 模块划分

#### 前端模块
- `src/pages/` - 页面组件
- `src/components/` - 通用组件
- `src/api/` - API 调用
- `src/store/` - 状态管理（Pinia）
- `src/router/` - 路由配置

#### 后端模块
- `controller/` - REST 接口
- `service/` - 业务逻辑
- `repository/` - 数据访问
- `entity/` - 数据模型
- `dto/` - 数据传输对象
- `security/` - 安全配置

### 数据模型

#### User 表
```sql
CREATE TABLE users (
  id BIGSERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  nickname VARCHAR(100),
  avatar_url VARCHAR(500),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### API 设计

- POST /api/v1/auth/register - 用户注册
- POST /api/v1/auth/login - 用户登录
- GET /api/v1/users/profile - 获取个人信息
- PUT /api/v1/users/profile - 更新个人信息
- POST /api/v1/users/change-password - 修改密码
- POST /api/v1/users/upload-avatar - 上传头像
````

**你需要确认**：

```

```

### 第 8 步：技术选型（每个 Feature 独立）

**tech-decision Skill 会自动**：

1. 比较可行技术
2. 选出最优方案
3. 记录决策理由

**技术选型输出示例**：

```markdown
## 技术栈确认

### 前端
- 框架: Vue 3.4（团队熟悉）
- 状态管理: Pinia（Vue 3 官方推荐）
- 路由: Vue Router 4
- UI 组件: Element Plus（快速开发）
- 构建: Vite 5.2（快速热更新）

### 后端
- 框架: Spring Boot 3.1（成熟稳定）
- 数据库: PostgreSQL 15（支持 JSONB，未来扩展性好）
- ORM: Spring Data JPA
- 认证: Spring Security + JWT
- 密码加密: BCrypt

### 工具
- API 文档: Swagger/OpenAPI
- 代码检查: ESLint + Prettier（前端）, Checkstyle（后端）
- 测试: Vitest（前端）, JUnit 5（后端）

## 决策记录

### 为什么选择 Vue 3 而非 React?
- 团队成员更熟悉 Vue
- 学习曲线更平缓
- Composition API 符合函数式编程习惯

### 为什么选择 PostgreSQL 而非 MySQL?
- 支持 JSONB，未来可能存储非结构化数据
- 更好的并发性能
- 更强的数据一致性保证

### 为什么选择 JWT 而非 Session?
- 无状态，易扩展
- 支持移动端
- 适合前后端分离架构
```

```

  ↓

  ↓
product-manager（需求分析 + 确认）
  ↓
frontend-design（UI/UX 设计，如有前端）
  ↓
architecture-design（架构设计 + 确认）
  ↓
tech-decision（技术选型）
  ↓

  ↓

  ↓
database-design / universal-development（实施）
  ↓
code-review（审查）
  ↓
git-commit（在授权后提交和推送）
  ↓
回到当前 TODO；只有明确要求继续时才领取下一项
```

## 常见问题

### Q1: 需求分析阶段被问了很多问题，能跳过吗？

不能跳过，但可以提前准备答案：

```
我要做一个用户管理系统：
- 注册: 邮箱密码，无需验证，密码至少8位
- 登录: JWT认证，7天有效期
- 信息: 昵称编辑，头像上传（2MB限制）
- 改密: 旧密码验证，符合强度要求
```

### Q2: 技术方案不满意，如何修改？

在确认前明确说明：

```
"技术方案需要调整：
1. 数据库改用 MySQL（已有MySQL集群）
2. UI 组件改用 Ant Design Vue（设计规范要求）"
```

系统会重新生成方案。

### Q3: TODO 生成后发现功能遗漏，如何补充？

使用 `add-todo` Skill：

```
"补充功能：用户可以注销账号"
```

系统会：
1. 分析新功能
2. 生成新的 Feature
3. 追加到 TODO（保持依赖关系）

### Q4: 能否跳过某些阶段直接开始开发？

不能跳过流程状态机的强制阶段。但如果项目简单，可以：

1. 需求分析快速确认
2. 技术方案选择现有技术（reuse-existing）
3. 使用 Lite 档位减少文书

### Q5: 多人协作时如何分工？

在 TODO 生成后，手动调整 Owner：

```markdown
- [ ] `INFRA-DB` 数据库初始化
  - Owner: alice-chen  # Alice 负责

- [ ] `USER-REG-API` 注册 API
  - Owner: bob-wang  # Bob 负责
```

或者每人一份 TODO，通过写集互斥并行开发。
