## 这个功能帮你做什么

通知脚本根据客户端事件和回复标记选择中文提示音，区分需要人工接续、普通回复结束与任务完成。

提示音由 Agent 自己按回复性质选择，你不需要做任何标注或手工触发。

## 三类提示音

| 提示音 | 什么时候响 | 你该做什么 |
|--------|-----------|-----------|
| 需要您确认 | 需要你做决定、补充信息、给出授权，或需要你手工操作（重启服务、跑数据库脚本、切换设备） | 看回复内容，给出决定或完成那一步 |
| 回复完成 | 普通回复结束：状态更新、信息汇报、可选建议、部分完成 | 看一眼，决定下一步 |
| 任务完成 | 一件事真正收尾：代码写完、验证通过、Review 通过、已提交并推送，且没有剩余必做事项 | 可以开始下一个任务 |

<Aside type="note">
提示音只是通知分类，不是交付证明。任务完成标记只应在验证、Review 和必要的 Git 交付完成且没有剩余必做事项时使用，仍需以真实证据判断。
</Aside>

### 举例

响"需要您确认"的回复长这样：

```markdown
数据库迁移脚本已生成，请手工执行：

1. 连接到数据库
2. 执行 ALTER TABLE users ADD COLUMN phone VARCHAR(20);
3. 确认执行成功后告诉我
```

响"回复完成"的回复长这样：

```markdown
已完成用户登录 API 实现（参数验证、密码校验、JWT 生成）。
下一步：实现登录页面。
```

响"任务完成"的回复长这样：

```markdown
用户登录功能已完成：

✓ 代码实现（前后端 + 路由）
✓ 开发者验证（手工测试通过）
✓ Code Review（无问题）
✓ Git 交付（已推送到 origin/main）
```

## 两端的接入方式不同

| 客户端 | 提示音接入位置 |
|--------|--------------|
| Claude Code | `PermissionRequest` 确认事件，配置在 `~/.claude/settings.json`；当前 Stop 交给 TODO 脚本 |
| Codex | 用户级 `notify` 配置，在 `~/.codex/config.toml` |

两端都由安装器写入，正常安装后不需要手工改这两个文件。

## 关掉提示音

```bash
# 当前 shell 生效
export AGENT_COMPLETION_SOUND=0

# 永久生效
echo 'export AGENT_COMPLETION_SOUND=0' >> ~/.zshrc
source ~/.zshrc
```

想重新打开：

```bash
unset AGENT_COMPLETION_SOUND
```

## 换成自己的声音

三个环境变量分别指定三类提示音的文件，设了就用你的，没设就用自带的：

```bash
export AGENT_CONFIRMATION_SOUND_FILE=/path/to/custom-confirmation.wav
export AGENT_REPLY_COMPLETION_SOUND_FILE=/path/to/custom-reply.wav
export AGENT_TASK_COMPLETION_SOUND_FILE=/path/to/custom-task.wav
```

音频文件要求：WAV 格式，单声道或立体声，建议 1 到 3 秒。

macOS 下可以直接用系统的 `say` 生成：

```bash
say -v Ting-Ting "需要您确认" -o confirmation.aiff
ffmpeg -i confirmation.aiff confirmation.wav
```

Linux 下可以用 `espeak`：

```bash
sudo apt-get install espeak
espeak -v zh "需要您确认" -w confirmation.wav
```

## 听不到声音怎么排查

按顺序过一遍：

```bash
# 1. 是不是被关掉了
echo $AGENT_COMPLETION_SOUND

# 2. 自带音频文件在不在
ls "<skills-root>/runtime-hooks/audio/"

# 3. 手动播一下，确认系统能出声
afplay "<skills-root>/runtime-hooks/audio/confirmation.wav"

# 4. 确认系统音量没静音
```

对应的处理：

| 排查结果 | 处理 |
|---------|------|
| 第 1 步输出 `0` | `unset AGENT_COMPLETION_SOUND` |
| 第 2 步目录为空 | 先核对并补齐仓库音频资产；安装器不会生成缺失音频 |
| 第 3 步能听到、Agent 回复时听不到 | 核对客户端通知通道和 Hook 安装状态；Claude Code 默认只接确认音频，Codex 走 `notify` |
| 第 3 步也听不到 | 系统音频问题，与本功能无关 |

提示音在 macOS 上开箱即用。其他平台如果始终听不到，把它当可选功能关掉即可，不影响任何开发流程。

### 音频文件损坏

播放报错或完全无声时先确认文件本身：

```bash
file "<skills-root>/runtime-hooks/audio/confirmation.wav"
```

正常应识别为 `RIFF (little-endian) data, WAVE audio`。格式错误时核对仓库资产，或换成有效的自定义音频。
