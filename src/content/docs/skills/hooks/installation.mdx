## 安装前

首次安装整套 Skills，请先看 [安装与配置](/skills/getting-started/)。本页只说明 Hook 配置落点和安装器，不替代原生 Skill 发现目录的注册与目录验证。

确认 Node.js 与目标客户端已可运行、客户端已完成登录。以下 `<skills-root>` 代表当前 Skills 仓库根目录，执行前替换为你机器上的实际路径。

```bash
node --version
claude --version
# 或
codex --version
```

上面的命令只检查运行环境和客户端。Runtime Hooks 有自己的版本，唯一来源是 Skills 仓库的 `runtime-hooks/VERSION`，与 Claude Code、Codex 和共享 Skills 包版本分别维护。

## 查看 Hooks 版本

```bash
# 当前源码中的 Hooks 版本
node "<skills-root>/runtime-hooks/scripts/hook-version-manager.cjs" source

# 各客户端的 Hooks 源版本与已安装版本
node "<skills-root>/runtime-hooks/scripts/hook-version-manager.cjs" status --client codex
node "<skills-root>/runtime-hooks/scripts/hook-version-manager.cjs" status --client claude
```

Runtime Hooks 的独立版本从 `1.0.0` 开始。旧安装的 `0.0.0` 表示过去缺少版本源时写入的占位值，显示为未知，重新运行安装器后会迁移到真实版本。`status` 只读版本记录；完整安装状态仍以安装器检查为准。

## 安装并检查

安装器将 Hook 合并到现有配置，去重托管条目并在改写前备份。它保留第三方 Hook，内容没有变化时不会重复写入。

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs"
node "<skills-root>/runtime-hooks/scripts/install.mjs" --check --json
```

检查结果以 `installed: true` 且 `needsInstall: false` 为通过，表示托管配置和版本记录均一致。`sourceVersion` 是 Hooks 源版本，`versions` 列出各客户端的已安装 Hooks 版本；`changed` 列出待更新配置或版本记录，`installCommand` 保留本次客户端和隔离目录选择。单独运行 `--check` 不写文件。

| 配置落点 | 内容 |
|---|---|
| `~/.claude/settings.json` | Claude Code Hook 事件 |
| `~/.codex/hooks.json` | Codex Hook 事件 |
| `~/.codex/config.toml` | Codex 用户级 `notify` 通道 |
| 两个客户端配置目录下的 `.runtime-hook-version` | Hooks 版本、安装时间和源码路径 |

Claude Code 配置目录可由 `CLAUDE_CONFIG_DIR` 指定，Codex 配置目录可由 `CODEX_HOME` 指定。Node 解释器会写入绝对路径；切换 Node 版本后重新运行安装器以刷新路径。

### 只处理一个客户端

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs" --claude-only
node "<skills-root>/runtime-hooks/scripts/install.mjs" --codex-only
```

### 先查看差异

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs" --dry-run --json
```

需要验证安装器输出结构时，可通过 `--home` 指定隔离目录。它忽略客户端配置目录环境变量，并在该目录下使用 `.claude` 和 `.codex`，不会改当前用户配置：

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs" --home "<isolated-home>" --dry-run --json
```

## 让客户端加载

Claude Code 安装后完全退出并重新启动会话。Codex 中运行 `/hooks`，检查并信任新 Hook；Hook 定义的路径或参数变化后，需要重新检查信任状态。

```text
/hooks
/hooks trust all
```

<Aside type="note">
安装检查通过表示本地配置与当前脚本一致，不等于客户端已重新加载，也不表示远端 Penpot MCP 已连通。SessionStart 只读取 Penpot 本地注册状态，不会注册或探测远端。
</Aside>

## 检查实际生效

在已有 Git 仓库中启动会话，发出“查看项目记忆”这样的只读请求，核对当前仓库、开发者与 TODO 路径是否符合预期。Skill 名单以客户端原生发现结果为准。

要查看托管事件名，可以只读取配置中的键：

```bash
jq '.hooks | keys' "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json"
jq '.hooks | keys' "${CODEX_HOME:-$HOME/.codex}/hooks.json"
```

上下文脚本的检查模式会创建或检查项目记忆，不应当被描述为对任意当前目录绝对只读。其检查命令和观测边界见 [评估与验证边界](/skills/advanced/performance-metrics/)。

验证命令防护时，读取源码中的判定函数或使用其不执行目标命令的输入检查方式，见 [PreToolUse Hook](/skills/hooks/pre-tool-use/)。不要在实际工作区执行破坏性命令来确认 Hook 是否安装成功，也不要为安装验证额外创建活动 TODO。

## 更新

先按仓库既有方式更新 Skills 源码，再运行同一个安装器。安装器负责托管配置与版本记录的差异合并、备份和失败回滚；重复运行不会重写未变化的安装时间。切换源码目录或回退源码版本后也需要重新同步。

```bash
node "<skills-root>/runtime-hooks/scripts/install.mjs"
node "<skills-root>/runtime-hooks/scripts/install.mjs" --check --json
```

多个客户端建议共享一份 Skills 源仓库，并通过各自的原生发现目录注册 Skill。不要把整个仓库复制成客户端的 `skills` 目录，避免嵌套目录、重复发现和 Hook 指向过期副本。

## 开关与配置

| 配置 | 实际作用 |
|---|---|
| `AGENT_RUNTIME_HOOKS_DISABLED=1` | 停用 SessionStart、PreToolUse 和提示音；不关闭上下文注入与 TODO 状态逻辑 |
| `AGENT_COMMAND_GUARD=0` | 停用 PreToolUse，连同该脚本的流程写入门禁一起跳过 |
| `AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0` | SessionStart 仍检查差异，但不自动修改配置 |
| `AGENT_COMPLETION_SOUND=0` | 关闭提示音 |
| `AGENT_DEVELOPER_NAME` | 仅在 Git identity 与系统登录用户名都不可用时兜底 |

这些环境变量必须由客户端启动时继承。给被执行命令添加行内前缀不会改变已经运行的 Hook 进程环境。

## 移除或恢复

先检查安装器生成的配置差异与备份，只删除指向当前 `runtime-hooks/scripts/` 的托管条目，保留第三方 Hook 和通知。不要直接删除整个 `hooks` 对象；Codex 的 `notify` 还可能包含安装器保留的原通知链。

恢复 `.backup-*` 文件前，比较备份与当前配置，确认不会覆盖安装之后新增的配置。恢复后重启客户端并重新检查事件列表。

## 常见问题

| 现象 | 处理 |
|---|---|
| 安装器报运行时资产不完整 | 只读检查仓库是否缺脚本、行为内核或音频文件，先补齐源码资产 |
| Node 路径失效 | 确认当前 Node 可用，再运行安装器刷新绝对路径 |
| 每次启动都提示更新 | 检查实际配置目录、版本记录和安装器输出；必要时临时设置 `AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0` 排查 |
| Hooks 版本为未知或旧记录为 `0.0.0` | 更新 Skills 源码，确认 `runtime-hooks/VERSION` 存在，再重新运行安装器；不要用客户端版本代填 |
| 权限不足 | 查看报错对应文件与父目录的权限、属主；只修正已确认异常的具体路径 |
| 检查通过但没有上下文 | 确认客户端已重新加载、Codex 已信任 Hook，且请求工作目录处于目标 Git 仓库 |
