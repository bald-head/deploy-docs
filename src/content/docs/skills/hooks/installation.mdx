## 概述

Runtime Hooks 需要注册到 Claude Code 或 Codex 的配置文件里才会生效。安装器会合并现有配置、去重并先备份，重复运行不会堆积重复条目，也不会删掉你自己写的第三方 Hook。

## 路径约定

这套 Skill 与 Hook 同时服务 Claude Code 和 Codex，也同时跑在 macOS、Linux 和 Windows 上，所以文档里**不出现任何真实机器的绝对路径**。下面三个占位符贯穿全部文档，你在自己机器上看到的输出会是它们展开后的绝对路径：

| 占位符 | 含义 | 各系统的实际值 | 覆盖方式 |
|---|---|---|---|
| `<HOME>` | 当前用户主目录 | macOS 与 Linux 上是 `$HOME`，Windows 上是 `%USERPROFILE%` | 安装器 `--home <dir>` |
| `<skills-root>` | Skills 仓库所在目录 | 默认 `<HOME>/.agent-workflow/skills`，克隆到哪里就是哪里 | 克隆位置自行决定 |
| `<node>` | Node 可执行文件 | `which node` / `where node` 的结果 | 由 PATH 决定 |

两个客户端的配置目录各自独立，都可以用环境变量改掉：

| 客户端 | 默认配置目录 | 环境变量 |
|---|---|---|
| Claude Code | `<HOME>/.claude` | `CLAUDE_CONFIG_DIR` |
| Codex | `<HOME>/.codex` | `CODEX_HOME` |

<Aside type="note">
安装器的 `--home <dir>` 与这两个环境变量互斥：传了 `--home` 就忽略 `CLAUDE_CONFIG_DIR` 和 `CODEX_HOME`，直接在 `<dir>/.claude` 和 `<dir>/.codex` 下落点。用它可以把安装结果隔离到临时目录里试跑。
</Aside>

## 前置条件

### 系统要求

- **Node.js**：>= 18.0.0
- **操作系统**：macOS、Linux 或 Windows
- **客户端**：Claude Code 或 Codex（已安装并完成登录）

### 检查 Node 版本

```bash
node --version
# 应该输出 v18.x.x 或更高版本
```

如果版本过低，先升级：

```bash
# macOS (Homebrew)
brew install node@18

# Linux (nvm)
nvm install 18
nvm use 18
```

### 检查客户端

```bash
claude --version
# 或
codex --version
```

<Aside type="caution">
首次使用需要先运行一次 `claude` 或 `codex` 完成登录，再安装 Hook。
</Aside>

## 安装步骤

### 1. 定位 Skills 仓库

```bash
# 如果尚未克隆
git clone <skills-repo-url> ~/.agent-workflow/skills

cd ~/.agent-workflow/skills
```

<Aside type="note">
安装路径可以自定义，后续命令都以 Skills 仓库根目录为工作目录。
</Aside>

### 2. 运行安装器

```bash
node runtime-hooks/scripts/install.mjs
```

**预期输出**（首次安装，三个配置落点一次写入）：

```
运行时 Hook 安装完成：
- Claude Code settings.json：已更新
- Codex hooks.json：已更新
- Codex config.toml notify：已更新
- 已备份：<HOME>/.claude/settings.json.backup-20260904-103045
- Claude Code：用户级 Hook 已写入；重新启动会话后生效。
- Codex：仅 Bash 使用轻量命令防护；Stop/SubagentStop 运行 TODO 续作检查。
```

安装器不区分"当前客户端"，两端配置一起对齐；已经是目标内容的文件显示 `无需变更`，不会重复备份。只想处理一端时：

```bash
node runtime-hooks/scripts/install.mjs --claude-only
node runtime-hooks/scripts/install.mjs --codex-only

# 先看会改什么再决定
node runtime-hooks/scripts/install.mjs --dry-run

# 不生成备份
node runtime-hooks/scripts/install.mjs --no-backup
```

### 3. 验证安装

```bash
node runtime-hooks/scripts/install.mjs --check --json
```

**预期输出**（已安装且无需更新时）：

```json
{
  "backups": [],
  "changed": [],
  "check": true,
  "confirmationRequired": false,
  "dryRun": true,
  "files": [
    { "changed": false, "label": "Claude Code settings.json", "path": "<HOME>/.claude/settings.json" },
    { "changed": false, "label": "Codex hooks.json", "path": "<HOME>/.codex/hooks.json" },
    { "changed": false, "label": "Codex config.toml notify", "path": "<HOME>/.codex/config.toml" }
  ],
  "installCommand": "'<node>' '<skills-root>/runtime-hooks/scripts/install.mjs'",
  "installed": true,
  "needsInstall": false,
  "unchanged": [
    "Claude Code settings.json",
    "Codex hooks.json",
    "Codex config.toml notify"
  ]
}
```

判定标准是 `installed: true` 且 `needsInstall: false`。需要安装时 `changed` 会列出待更新的文件标签，`installCommand` 就是可以直接执行的安装命令。

<Aside type="note">
不带 `--json` 时，`--check` 在"已安装且无差异"的情况下**完全没有输出**（退出码 0）。没有输出不是失败，而是检查通过。
</Aside>

### 4. 让它生效

两端各有一步"装完不等于生效"：

| 客户端 | 还需要做什么 |
|--------|--------------|
| Claude Code | 完全退出并重新启动会话，用户级 Hook 才会加载 |
| Codex | Hook 是非托管的，必须在会话里 `/hooks` 审查并信任一次 |

## Codex 专属步骤

### 1. 进入 Codex 查看 Hook 列表

```bash
codex
```

```
/hooks
```

**输出示例**：

```
Non-managed hooks (require trust):
1. SessionStart
2. PreToolUse
3. UserPromptSubmit
4. SubagentStart
5. SubagentStop
6. Stop

Status: Not trusted
```

### 2. 信任前先审查

Hook 脚本都在 `<skills-root>/runtime-hooks/scripts/` 下，信任之前建议自己打开看一遍——这是非托管 Hook 的意义所在，安装器不会替你绕过客户端的信任机制。

### 3. 信任所有 Hook

```
/hooks trust all
```

**确认提示**：

```
This will trust all non-managed hooks. Continue? (y/n)
```

输入 `y` 确认，输出：

```
✓ All hooks trusted
```

### 4. 验证信任状态

再运行一次 `/hooks`，每一项前面应该都是 `✓ Trusted`。

<Aside type="tip">
只更新脚本内容、不改动 Hook 定义（路径与参数）时哈希不变，**不需要**重新信任。只有 Hook 定义变化时才要重新信任。
</Aside>

## Claude Code 验证

Claude Code 使用托管 Hook，安装后重启会话即生效，无需手动信任。想确认配置确实写进去了：

```bash
# Claude Code
jq '.hooks | keys' "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json"

# Codex
jq '.hooks | keys' "${CODEX_HOME:-$HOME/.codex}/hooks.json"
grep -A 3 '^notify' "${CODEX_HOME:-$HOME/.codex}/config.toml"
```

Hook 都写在这两个文件的 `hooks` 段里（Codex 的通知另外写在 `config.toml` 的顶层 `notify`）。安装器写进去的结构大致是这样——每个事件是一个数组，数组里每项带一个 `hooks` 列表，命令是一整条字符串：

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "…匹配的会话事件…",
        "hooks": [
          { "type": "command", "command": "…安装器生成的绝对路径命令…" }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "…匹配的工具名…",
        "hooks": [
          { "type": "command", "command": "…安装器生成的绝对路径命令…" }
        ]
      }
    ]
  }
}
```

这份配置由安装器生成和维护，不需要手写。对着它确认事件都在、命令指向你的 Skills 仓库就够了。

<Aside type="note">
配置里 Node 解释器被写成绝对路径而不是 `node`，这是有意的：Hook 由客户端在自己的进程环境里拉起，那里不一定继承你 shell 的 `nvm` / `fnm` PATH。**换过 Node 版本后重新跑一次安装器**即可刷新这个路径。
</Aside>

## 检查上下文注入

安装完可以直接确认注入链路是通的：

```bash
node runtime-hooks/scripts/skill-catalog-context.cjs --check
```

输出 `ok: true` 表示自检通过，同时会列出当前注入的实际占用与生效上限。这条命令同时是一道门禁，失败时会打印具体原因并以非 0 退出码结束——常见原因是仓库资产缺失或行为内核被改成了不合规格式。

## 配置环境变量

### 开发者 ID

通常从 Git 配置自动获取：

```bash
git config user.name
# 输出: alice-chen
```

Git identity 不可用时才需要手动设置：

```bash
export AGENT_DEVELOPER_NAME=alice-chen

# 永久生效
echo 'export AGENT_DEVELOPER_NAME=alice-chen' >> ~/.zshrc
source ~/.zshrc
```

<Aside type="note">
`AGENT_DEVELOPER_NAME` 是**最后的兜底**，不是覆盖开关。只要 `git config user.name` 有值，设置它不会生效。
</Aside>

### 停用选项

```bash
# 停用命令防护、启动检查和提示音（关不掉上下文注入与 TODO 续作）
export AGENT_RUNTIME_HOOKS_DISABLED=1

# 只停用命令防护
export AGENT_COMMAND_GUARD=0

# 配置版本不一致时不自动重装，只打印手动安装命令
export AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0

# 关闭全部提示音
export AGENT_COMPLETION_SOUND=0
```

<Aside type="caution">
`AGENT_RUNTIME_HOOKS_DISABLED` 不是总开关。要彻底停掉某个 Hook，删掉客户端配置里对应的条目，或恢复安装器留下的 `.backup-*` 文件。
</Aside>

### 自定义提示音

```bash
export AGENT_CONFIRMATION_SOUND_FILE=/path/to/custom-confirmation.wav
export AGENT_REPLY_COMPLETION_SOUND_FILE=/path/to/custom-reply.wav
export AGENT_TASK_COMPLETION_SOUND_FILE=/path/to/custom-task.wav

# 三类共用一个文件
export AGENT_COMPLETION_SOUND_FILE=/path/to/one-sound.wav
```

## 测试安装

### 1. 启动客户端

```bash
claude
# 或
codex
```

### 2. 检查会话启动

会话启动时如果配置有差异，会看到版本检查与对齐提示；配置已是最新时通常没有任何输出。

### 3. 测试上下文注入

随便问一句，例如：

```
查看项目记忆
```

**预期行为**：

- 自动确保目标仓库存在 `PROJECT-MEMORY.md`
- 文件刚创建或主要章节还是模板占位内容时，提示先走 `init-docs` 采集事实
- 回答里带上与这句问题相关的记忆摘要

### 4. 测试命令防护

```
rm -rf .
```

**预期行为**：工具调用被直接拒绝，输出带 `危险操作已阻止：` 前缀的原因文本。

### 5. 测试 TODO 续作

```bash
mkdir -p docs/$(git config user.name)/tasks/todo
cat > docs/$(git config user.name)/tasks/todo/test.md << 'EOF'
# Test TODO

- [ ] `FEAT-001` 测试功能
  - 依赖: 无
  - 写集: test.txt
  - AC-001: 文件创建 -> ?
EOF
```

在客户端里说"开始实现 FEAT-001"。

**预期行为**：

- 自动领取 FEAT-001，状态变为 `[~]`
- 实现并自验
- 完成条件满足后状态更新为 `[x]`

<Aside type="caution">
TODO 状态只能由状态机原子写回。手工编辑 TODO 文件会被 PreToolUse 直接拒绝，这是设计行为。
</Aside>

## 更新 Hooks

```bash
cd ~/.agent-workflow/skills
git pull origin main
node runtime-hooks/scripts/install.mjs
```

安装器会检测差异、备份旧配置、合并更新，重复运行是幂等的。

Hook 定义（路径或参数）变化时，Codex 需要重新信任：

```bash
codex
/hooks trust all
```

<Aside type="note">
只是脚本内容更新（定义未变）时不需要重新信任。
</Aside>

## 卸载 Hooks

### 手动卸载

编辑配置文件，删掉 `hooks` 段或其中特定条目：

```bash
# Claude Code
vim ~/.claude/settings.json

# Codex：Hook 在 hooks.json，通知在 config.toml
vim ~/.codex/hooks.json
vim ~/.codex/config.toml
```

Codex 的 `config.toml` 只需删掉 `notify` 一项。

### 恢复备份

备份文件名是原路径加上 `.backup-YYYYMMDD-HHMMSS`（同一秒内重复备份会再追加 `-1`、`-2`）：

```bash
# 先列出实际存在的备份
ls -t ~/.claude/settings.json.backup-* ~/.codex/hooks.json.backup-* ~/.codex/config.toml.backup-* 2>/dev/null

cp ~/.claude/settings.json.backup-20260904-103045 ~/.claude/settings.json
cp ~/.codex/hooks.json.backup-20260904-103045 ~/.codex/hooks.json
cp ~/.codex/config.toml.backup-20260904-103045 ~/.codex/config.toml
```

## 安装类故障排查

### Hook 未生效

**症状**：看不到上下文注入，危险命令也没被拦。

```bash
# 1. 检查安装状态
node runtime-hooks/scripts/install.mjs --check --json

# 2. 确认配置落点里有 hooks 段
jq '.hooks | keys' ~/.claude/settings.json

# 3. 确认 Node 可用
which node
```

**处理**：

```bash
node runtime-hooks/scripts/install.mjs
```

然后 Claude Code 重启会话、Codex 重新 `/hooks trust all`。更多现象见 [故障排查](/skills/hooks/troubleshooting/)。

### 安装器报"运行时资产不完整"

说明 Skills 仓库里缺文件（脚本、行为内核或提示音音频）。这种情况安装器不会写配置。重新拉取仓库或检查工作区是否有误删：

```bash
cd ~/.agent-workflow/skills
git status --short
git pull origin main
```

### 每次会话都要重装

配置版本检测认为落点与仓库不一致。先跑一次完整安装；仍然反复时可以临时关掉自动对齐：

```bash
node runtime-hooks/scripts/install.mjs
export AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0
```

### 权限问题

**症状**：`Error: EACCES: permission denied`

```bash
chmod -R u+rw ~/.agent-workflow/skills/
sudo chown -R $USER ~/.agent-workflow/skills/
```

### Node 版本不兼容

```bash
brew install node@18  # macOS
nvm install 18        # Linux
```

升级后重新运行一次安装器，刷新配置里固定的解释器路径。

## 多客户端同时使用

### 方案 1：共享一份仓库（推荐）

两个客户端指向同一个 Skills 仓库，安装一次即可：

```bash
cd ~/.agent-workflow/skills
node runtime-hooks/scripts/install.mjs

codex
/hooks trust all
```

### 方案 2：独立镜像

分别维护副本，各自安装：

```bash
# Claude Code
cp -r ~/.agent-workflow/skills ~/.claude/skills
cd ~/.claude/skills && node runtime-hooks/scripts/install.mjs

# Codex
cp -r ~/.agent-workflow/skills ~/.agents/skills
cd ~/.agents/skills && node runtime-hooks/scripts/install.mjs
codex
/hooks trust all
```

<Aside type="tip">
推荐方案 1，避免维护两份代码。
</Aside>

## 持续集成

```yaml
# .github/workflows/test.yml
name: Test with Runtime Hooks

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: 18

      - name: Install Runtime Hooks
        run: node runtime-hooks/scripts/install.mjs

      - name: Verify Installation
        run: node runtime-hooks/scripts/install.mjs --check --json

      - name: Check Context Injection
        run: node runtime-hooks/scripts/skill-catalog-context.cjs --check
```
