## 这个 Hook 帮你做什么

每次启动客户端时，SessionStart Hook 会确认你机器上的 Hook 配置还是有效的。配置正确时它完全静默；配置过时或缺失时它自动修复，并提示你重启客户端。

它解决的实际问题是：Skills 仓库换过位置、换过 Node 版本、或者升级后多了新的 Hook 事件——这些情况下旧配置会静默失效，而你不会立刻发现。

**触发时机**：首次启动客户端、重启客户端、新建会话窗口。

## 你会看到什么

**配置正常**（绝大多数情况）：

```
$ claude
(无输出，直接进入会话)
```

**检测到配置过时并已修复**：

```
运行时 Hook 已自动更新：Claude Code settings.json。
请完全退出并重新启动 Claude Code，使新的 Hook 与通知配置生效。
```

<Aside type="caution">
看到这条提示要真的**完全退出**再启动。当前这个会话仍在用旧配置运行。
</Aside>

**检测到过时但你关掉了自动修复**：

```
检测到运行时 Hook 需要更新：Claude Code settings.json。
自动更新已禁用，请手动运行安装器。
安装命令：…
```

提示里给出的安装命令是在你这台机器上现算的，直接复制执行即可。

## 它检查和改动哪些文件

| 客户端 | 配置文件 | 改配置目录用的环境变量 |
|--------|---------|---------------------|
| Claude Code | `~/.claude/settings.json` | `CLAUDE_CONFIG_DIR` |
| Codex | `~/.codex/hooks.json`（Hook）、`~/.codex/config.toml`（完成通知） | `CODEX_HOME` |

会被判定为"需要修复"的情况：

- 配置里缺了某个 Hook 事件
- Hook 指向的路径已经失效（仓库搬过位置、换过 Node 版本）
- 残留了旧版本的启动命令

## 修复时会不会弄坏我的配置

不会覆盖你自己的设置。修复走的是合并 + 去重 + 备份：

1. `settings.json` 里与 Hook 无关的字段（主题、模型等）原样保留；
2. 同一个 Hook 事件的重复定义会被去重，只留有效的那份；
3. 旧版本残留的启动命令会被清掉；
4. 内容真的发生变化时才写文件，写之前先备份。

**备份命名**：原文件名后加 `.backup-YYYYMMDD-HHMMSS`，同一秒内重名会继续追加序号，不会互相覆盖。

```
~/.claude/settings.json.backup-20260904-103045
~/.codex/hooks.json.backup-20260904-103045
~/.codex/config.toml.backup-20260904-103045
```

备份不会自动清理，可以自己删旧的。因为只有内容变化时才生成，正常使用下备份不会无限增长。

## Penpot MCP 检查

启动时会顺带确认 Penpot MCP 在客户端配置里注册过，**只读检查，不联网**。

| 会做 | 不会做 |
|------|-------|
| 看客户端 MCP 配置里有没有 penpot server | 不测网络连通性 |
| 看配置里的 URL 和 token 字段是否存在 | 不验证 token 有效性 |
| | 不调用任何 MCP 工具 |

真正的连接只在你使用 penpot 相关 Skill 时才发生。

未注册时只是一条警告，不阻止会话启动：

```
⚠️  Penpot MCP 未注册，部分 Skill 可能不可用
```

不需要 Penpot 就忽略；需要的话运行注册脚本（`<skills-root>` 是你的 Skills 仓库根目录）：

```bash
cd <skills-root>
node project-manager/scripts/penpot-mcp-setup.mjs

# 只看当前状态
node project-manager/scripts/penpot-mcp-setup.mjs --check --json
```

## 配置

| 环境变量 | 设成什么 | 效果 |
|---------|---------|------|
| `AGENT_RUNTIME_HOOKS_AUTO_UPDATE` | `0` | 仍然检测差异并提示，但不自动改配置 |
| `AGENT_RUNTIME_HOOKS_DISABLED` | `1` | 关闭全部 Hook，包括本页的启动自检 |
| `CLAUDE_CONFIG_DIR` | 目录路径 | 换掉 Claude Code 配置目录 |
| `CODEX_HOME` | 目录路径 | 换掉 Codex 配置目录 |

```bash
# 关掉自动修复
export AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0

# 长期生效
echo 'export AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0' >> ~/.zshrc
source ~/.zshrc
```

<Aside type="note">
`CLAUDE_CONFIG_DIR` / `CODEX_HOME` 必须在启动客户端**之前**导出，Hook 进程才继承得到。启动后再 export 不生效。
</Aside>

## 手动运行安装器

不想等自动修复，或者要排查问题时：

```bash
cd <skills-root>

# 修复一次
node runtime-hooks/scripts/install.mjs

# 只看状态，不改文件
node runtime-hooks/scripts/install.mjs --check --json
```

安装器和自动修复走的是同一套合并逻辑，重复运行是安全的。

## 故障排查

### 每次启动都提示"已自动更新"

说明每次都被判定成需要修复。两个常见原因：

- **配置目录被环境变量改过**，但版本记录留在了另一个目录里；
- **换过 Node 版本**，配置里记录的解释器路径已经失效。

诊断：

```bash
cd <skills-root>

# 1. 仓库里的版本
cat runtime-hooks/VERSION

# 2. 已安装的版本记录（跟着实际配置目录走）
cat "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.runtime-hook-version"
cat "${CODEX_HOME:-$HOME/.codex}/.runtime-hook-version"

# 3. 安装器自己怎么判定
node runtime-hooks/scripts/install.mjs --check --json
```

两个版本号一致、`--check --json` 返回 `installed: true` 且 `needsInstall: false`，就不应该再反复提示。

处理：

```bash
cd <skills-root>

# 手动修复一次（换过 Node 版本后必须重跑，用来刷新解释器路径）
node runtime-hooks/scripts/install.mjs

# 确认环境变量在启动客户端之前就导出了
echo "CLAUDE_CONFIG_DIR=$CLAUDE_CONFIG_DIR"
echo "CODEX_HOME=$CODEX_HOME"

# 先停掉自动修复，留出排查时间
export AGENT_RUNTIME_HOOKS_AUTO_UPDATE=0
```

<Aside type="caution">
不要用"删掉配置重装"来绕过：`settings.json` 里通常还有你自己的其他设置。重跑安装器是幂等的，比手工挪文件安全。
</Aside>

### 备份文件太多

```bash
CFG="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"

# 看一眼
ls -t "$CFG"/settings.json.backup-* 2>/dev/null

# 只留最近 5 个
ls -t "$CFG"/settings.json.backup-* 2>/dev/null | tail -n +6 | xargs rm

# Codex 两个落点同理
ls -t "${CODEX_HOME:-$HOME/.codex}"/hooks.json.backup-* 2>/dev/null
ls -t "${CODEX_HOME:-$HOME/.codex}"/config.toml.backup-* 2>/dev/null
```

<Aside type="caution">
删之前先确认当前配置能正常工作。
</Aside>

### 权限报错

现象：

```
Error: EACCES: permission denied, open '~/.claude/settings.json'
```

处理：

```bash
CFG="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"

chmod 600 "$CFG/settings.json"
chmod 700 "$CFG"
sudo chown -R $USER "$CFG"
```

### Penpot MCP 检查失败

先手动跑一次看具体状态：

```bash
cd <skills-root>
node project-manager/scripts/penpot-mcp-setup.mjs --check --json
```

未注册就运行不带 `--check` 的同一命令注册；不用 Penpot 直接忽略警告。

## 和手动安装的分工

| 场景 | 怎么做 |
|------|-------|
| 日常使用 | 交给 SessionStart 自动修复 |
| 首次安装 | 手动运行安装器 |
| 排查问题 | 手动运行安装器，看它的输出 |
| 关掉了自动修复 | 看到提示后手动运行安装器 |

差别只在触发方式和输出详细程度：自动修复静默完成，手动运行会打印每一步进度。
