Skills Framework 为 Claude Code、Codex 等 Coding Agent 提供研发 SOP 和专业 Skill。客户端按需发现和读取 Skill，Runtime Hook 补充共享行为约束、项目记忆与任务上下文。

| --- | --- |
| 第一次接入客户端 | [安装与配置](/skills/getting-started/) → [快速上手](/skills/quickstart/) |
| 想开发一个完整功能 | [第一个功能开发](/skills/first-feature/) |
| 已经在项目里工作 | [使用指南](/skills/usage/)：新项目、开发、修复、变更、Review 和 Git |

新用户先完成安装和一次实际使用即可。原理、Hook 配置和维护者资料放在后面的章节，遇到对应问题再查。

## 新增与更新

- [`resume-claude`](/skills/skills-reference/medium/resume-claude/)：读取、总结或接续 Claude Code 历史会话。
- [`resume-codex`](/skills/skills-reference/medium/resume-codex/)：读取、总结或接续 Codex CLI、VS Code 历史会话。
- 安装与维护：明确 `add-skill` 的注册职责、`skill-creator` 的内容创建职责，以及 Claude Code 和 Codex 各自的调用方式。
- 任务选择：补充 `grilling`、`performance-doctor`、`store-pc`、`utils-toolkit` 等能力边界；编写测试与运行已有检查分开说明。
- 图表：`archify` 的参考页覆盖架构、时序、生命周期和 Mermaid 转换的输入、验证与导出。

完整分类和数量以 [Skill 目录](/skills/catalog/)为准。客户端的系统 Skill 和项目级 Skill 不计入本站框架目录。

## 日常工作方式

在业务仓库中描述要达成的结果、已知问题和约束。Agent 先查仓库事实，只有仍缺少会改变结果的决定时才澄清；新功能完成必要规划后进入实现，已批准任务直接续作。

开发覆盖实际涉及的数据、API、后端、页面或调用方、权限和异常恢复，并执行适用验证与一次 Review。需要写测试源码、Git 提交、推送或部署时，按对应授权边界执行。

任务和状态保存在当前开发者唯一 Markdown TODO；稳定事实保存在唯一 `PROJECT-MEMORY.md`。恢复历史会话时，历史提供目标和停点线索，当前仓库仍是实现依据。

## 按需了解原理

- [核心概念](/skills/core-concepts/)：Skill 发现、选择、项目记忆与工作流。
- [Runtime Hooks](/skills/hooks/)：各事件职责、安装状态和故障定位。
- [Frontmatter 规范](/skills/advanced/frontmatter-spec/)：维护 Skill 的元数据和职责边界。
- [评估与验证边界](/skills/advanced/performance-metrics/)：区分目录检查、静态场景和实际行为证据。

框架提供可复用的规则和工具，不是独立的工作流引擎或 Agent 编排平台。目录检查通过也不代表固定的调用准确率或无人介入完成保证。
