## 1. 准备环境

- 已安装 Git、Node.js 和要使用的 Claude Code 或 Codex，版本满足对应客户端要求。
- Git 已配置 `user.name` 和 `user.email`；TODO 的开发者目录优先由目标仓库的 Git `user.name` 生成。
- 使用 `resume-claude` 或 `resume-codex` 读取历史时需要 Python 3；读取压缩的 Codex `.jsonl.zst` 文件还需要 `zstd`。

以下终端命令按 macOS/Linux shell 编写。先确认命令可用：

```bash
git --version
node --version
git config --get user.name
git config --get user.email
```

## 2. 获取 Skill 源仓库

```bash
git clone https://git.qiucou.cn/dengtx/skills.git
cd skills
```

已有仓库时进入已有的 Skill 源目录，不需要重新克隆。下文的 `add-skill/`、`runtime-hooks/` 等脚本路径都相对于 **Skill 源仓库根目录**，不能在本页面所在的文档仓库执行。

源目录可以位于团队已有位置。客户端发现目录由注册脚本探测，不要求把源码直接克隆进 `~/.claude/skills` 或 `~/.agents/skills`。

## 3. 注册到要使用的客户端

按目标客户端选择一条命令；两种客户端都要使用时分别注册。

### Claude Code

```bash
AGENT_WORKFLOW_CLIENT=claude-code node add-skill/scripts/validate-skill-catalog.mjs --install-discovery --require-discovery=claude-code
```

### Codex

```bash
AGENT_WORKFLOW_CLIENT=codex node add-skill/scripts/validate-skill-catalog.mjs --install-discovery --require-discovery=codex
```

该命令会先检查并按需安装 Runtime Hook、注册当前客户端的远端 Penpot MCP，再建立 Skill 发现入口。已有发现目录需要替换时，脚本先创建带时间戳的备份。

<Aside type="note">
目录 validator 包含安装和修复动作，不是只读检查。首次注册 Penpot 需要既有客户端配置或 `PENPOT_MCP_URL` 等真实来源；缺失时按错误补齐配置，不猜地址，也不能把未完成注册记为成功。
</Aside>

成功结果应包括：

```text
退出码：0
errors: []
runtimeHooks.installed: true
penpotMcp.configured: true
```

<Aside type="caution">
Codex 安装器若提示新的非托管 Hook 尚未信任，按当前客户端的 `/hooks` 提示审查并信任。Hook 支持和信任状态以当前客户端版本为准；不能仅凭文件已写入判断 Hook 已生效。
</Aside>

## 4. 在客户端确认发现与调用

| 客户端 | 显式调用示例 | 如何确认 |
| --- | --- | --- |
| Claude Code | `/project-navigator 定位当前项目的启动入口` | 查看当前会话可用 Skill，并核对响应是否引用真实路径 |
| Codex | `$project-navigator 定位当前项目的启动入口` | 用 `/skills` 浏览，或输入 `$` 查看补全 |

两种客户端都支持用自然语言描述任务，由 Agent 根据可用 Skill 的用途选择。Codex 的 `/skills` 是浏览入口，`/skill-name` 不是其 Skill 调用语法。

本站收录的框架 Skill 数量见 [Skill 目录](/skills/catalog/)。客户端可能另外加载系统 Skill、项目级 Skill 或同名优选项，因此不要把固定条目数作为安装成功条件。

找不到新增条目时，先确认当前客户端的发现路径可读；仍未刷新再重新打开会话。文件可发现、Hook 安装成功和 Skill 实际调用成功是不同的检查结果。

## 同步新增 Skill

更新已有 Skill 源仓库后，在该源目录重新运行上面的对应客户端注册命令，确认新增目录已进入原生发现范围。共享目录通过软链接接入时，内容修改作用于同一真实来源，不需要按客户端重复复制。

本次新增的会话恢复入口是 [`resume-claude`](/skills/skills-reference/medium/resume-claude/) 和 [`resume-codex`](/skills/skills-reference/medium/resume-codex/)。使用方法见[历史会话接续](/skills/usage/session-resume/)。

普通业务请求不重复运行注册命令。只诊断 Hook 本地安装状态时，在 Skill 源目录执行：

```bash
node runtime-hooks/scripts/install.mjs --check --json
```

`skill-catalog-context.cjs --check` 检查目录上下文与预算，不能替代 Hook 安装或客户端调用验证。更多问题见[故障排查](/skills/troubleshooting/)和 [Hook 安装与配置](/skills/hooks/installation/)。
